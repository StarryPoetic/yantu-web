# 研途 · 考研专业与院校选择工作台

基于 [产品设计文档 V1.0](docs/产品设计文档.md)、[技术设计文档清单](docs/技术设计/00-文档清单与需求映射.md) 与现有 demo 实现的全栈应用。默认页面使用账号登录、服务端会话和数据库，旧离线 demo 仅供开发回归。具体工程决策、实现范围与发布门槛见[实施说明](docs/实施说明.md)。

## 启动

需要 Node.js **24.14+**。完整验证还需要 Python 3 与 Chromium。

```powershell
npm ci
npm run dev
```

打开 http://127.0.0.1:4173 。前端和后端一起启动，数据库自动创建在 `var/yantu.sqlite`，重启后资料保留。首次进入注册学生账号。开发模式提供全国学科目录与明确标识的示例招生项目和题库；示例项目默认收起。不需要模型密钥即可建档、测评和查看专业探索结论。

```powershell
npx playwright install chromium
npm run check
```

单独运行：`npm run build`、`npm run test:unit`、`npm run test:docs`、`npm test`。浏览器验证覆盖默认应用和 `/?demo=1`，数据库/API 与模型/联网失败路径另有测试。测试不进行真实收费调用。

## 已实现的流程

- 注册、登录、退出与跨设备保存：学生和管理员在同一入口登录，由服务端角色进入独立工作台；游客资料注册时显式迁移。
- 全国专业探索：14个学科门类、117个一级学科、67个专业学位类别，按官方目录搜索与统计；不默认计算机或本科同专业。
- 顺序流程：个人情况标准字段下拉选择，保存后进入测评并记录已保存；公共课后直接查看个性化探索结论与补问。
- 逐题教学：每题提示/提交后解析、专业数学排版、行列式图示与连续追问；答前不泄露标准答案。
- 兴趣选择：下拉与输入框等宽，按拼音首字母分组，只显示有结果的字母；支持搜索、键盘和自填兴趣。
- 测评回顾：题干内直接排版行列式，解释性图示提交后展示；绿/红/黄方格表示答对/答错/未答，点击定位题目与解析，左右切换。
- 联网研究报告：现行新报告为 `profile-research-v7`，兼容旧版 `profile-research-v6` 及v3–v5。从全国184目录按画像建立调查范围，意向城市清单与官网编码项目独立于模型发现候选；按固定需求规则分层。`history-first-v1` 在目标为2027年时优先调查2026、2025、2024年政策，以最近可核验历史专业为比较基准，保留最多三年科目对照，2027年辅助核对已知变化。城市／校区和费用参考保留实际年份，历史不替代目标年度资格。同校学硕、专硕保留对照，测评快照用于知识点诊断与准备任务；示例小测不判定考试能力。以5–10所不同学校为覆盖目标，候选核验记录说明遗漏与缺口；阶段、来源和报告可恢复及下载。具体规则见[推荐方法与证据链](docs/recommendation-method.md)。

- 个人画像与七项偏好：城市中文、拼音、首字母搜索，多选、自定义与不确定；保存、刷新恢复、版本冲突提示及删除范围预览。
- 专业与院校联合探索：年度、学校、城市、专业、学位筛选，项目详情和来源，收藏、屏蔽学校/方向/项目及恢复，最多三个完整项目对比。
- 服务端推荐：固定画像、选择、目录和规则版本，资格优先、稳定排序、缺失依据说明。未知资格单列，不补齐前十，不生成虚假匹配百分比。
- 服务端测评：公共科目自由选择，每科五题，专业确认后可选专业课；固定题集、分层组卷、草稿保存、自动切题、末题主动提交、确定性诊断和解析。
- 目标与规划：选择学校/专业立即保存为规划目标，刷新后恢复；按项目实际科目设置目标，校验单科与总分，未知资料保持待核验；更换目标使旧计划与推荐需复核。
- 报告与反馈：固定版本的 Markdown 报告、下载与历史记录、纠错提交和处理状态。
- 资料后台：不同身份的录入、独立复核、发布、撤回、审计；题库逐项审校、风险和规则两人复核。
- 悬浮咨询：页面边角圆球，支持自由问题、多轮连续回答、收起恢复及清空；服务端DeepSeek、按需博查搜索和官网来源。模型未配置会明确提示，固定解析和专业结论仍可用。

## 配置模型、搜索和后台

参考 [.env.example](.env.example) 和 [本地模型与联网测试](docs/本地模型与联网测试.md)。`npm run dev`、`npm start` 与 `npm run preview` 自动读取根目录 `.env`，也支持系统环境变量（系统值优先）。本地测试不需要先部署公网：

```powershell
npm run dev
```

- 模型：设置 `YANTU_MODEL_ENABLED=true` 与 `DEEPSEEK_API_KEY`。默认关闭；未配置时明确提示，固定题解与专业结论仍可使用。不自动探测真实凭据。
- 搜索：国内接入默认使用博查，设置 `YANTU_SEARCH_PROVIDER=bocha`、`YANTU_SEARCH_ENABLED=true` 与 `BOCHA_API_KEY`。保留 `brave` 配合 `BRAVE_SEARCH_API_KEY` 的显式兼容选项，两家凭据隔离，不自动切换产生额外调用。用户可允许联网或提供最多两个官方网页地址；无搜索配置时明确降级。
- 深度报告：规划使用Pro非思考4096token/30秒，最终默认Pro/high、16384token、45秒空闲超时/默认300秒总上限；目标5–10所不同学校，每校一个主专业，综合完整画像分优先推荐、适合备选与探索选择，费用只是因素，不能机械决定层级。优先整理目标年度前3年政策，历史官网可支持条件性建议，最近历史条目作基准，目标年度已知停招、资格及其他变化独立覆盖历史假设；未知条件逐项待核验，硬报考限制不放宽。项目和学习方式明确的历史年费可作带年份的年度预算参考，不能称为目标年度价格，全程／学期／学分费用不擅自年化。最多24次搜索、80项搜索候选、60项官网读取，另可登记受控附件及费用来源，成功公开资料15分钟复用，失败不缓存。模型每阶段最多一次结构修复，全报告共享一次确认临时HTTP重试，证据充分但少于5校时再最多补充分析一次；全部共用额度与取消检查。超时/网络/认证/余额不足不自动重试。应用默认模型每账号300000token/日、全站900000token/日、搜索每账号60次/日及全站300次/日；配置和准确边界见[模型模块](server/explanation/README.md)。
- 官方网页：默认精确白名单包含研招网等；部署方用 `YANTU_OFFICIAL_HOSTS` 维护实际允许的主机。普通咨询与用户自填网址仍只用 HTTPS、不跟随跳转；研究流程显式设置 `maxRedirects:3`、`allowHttp:true`，只对 `.edu.cn` 放行明文HTTP。同校跳转限同一学校注册域名最多3次，每跳重新做全部DNS公网校验并固定连接IP，HTTPS保留TLS主机校验；跨校跳转拒绝，私网、IP直连、凭据、显式端口、大小与时间上限继续拦截。读取支持GBK/GB18030编码识别和gzip/deflate/br受限解压，细分HTTP、TLS、连接及跳转失败码。HTTP来源显示明文传输提示，保持verified:false。研究可显式读取受控PDF及XLS/XLSX纯文本，普通问答默认拒绝；解析有独立进程、时间、页数／单元格与字符上限，不做OCR或执行宏、公式。
- 后台账号：设置 `YANTU_BOOTSTRAP_ADMINS`，JSON每项包含 `username`、独立强密码 `password` 和 `roles`（`editor`、`reviewer`、`publisher`、`auditor`）。仅首次创建，已有账号不会被改密码或自动提升权限。管理员从正常登录页面进入，学生不能注册成管理员。初始化完成后移除明文初始化环境值；数据库只保存密码哈希。规则和风险仍须两名独立复核者，录入者不能自审。
- 兼容接口：`YANTU_ADMIN_CREDENTIALS` 仅为已有后台机器调用保留，页面不提供凭据输入框。
- 受控代理：`YANTU_TRUSTED_PROXY_IPS` 默认空，忽略来访者提供的转发IP。单层本机Caddy可显式设为 `127.0.0.1`，由代理覆盖 `X-Forwarded-For`，应用只接受一个合法IP；认证与API统一按真实客户限流。
- 登录频控：`YANTU_AUTH_REGISTRATION_IP_LIMIT` 默认每15分钟10次，`YANTU_AUTH_LOGIN_IP_LIMIT` 默认40次，可按部署调整1–1000整数；账户维度限制独立生效。反向代理应按受控来源配置网络入口，不能盲信客户端转发IP。

不要将密钥放入 `VITE_` 变量、前端代码、知识库或 Git。`.env`、数据库及日志均已忽略。自动化模型与检索测试使用模拟响应；真实服务连通性需单独验证，当前交付的验证范围见[实施说明](docs/实施说明.md)。

## 构建与单实例部署

```powershell
npm run build
$env:NODE_ENV='production'
$env:YANTU_ORIGIN='https://your-domain.example'
$env:YANTU_DATABASE_PATH='D:\yantu-data\production.sqlite'
npm start
```

API 与构建页面由同一服务提供，默认监听 `127.0.0.1:8787`，由 HTTPS 反向代理接入；可配置 `HOST`、`PORT`。生产必须显式指定独立数据库的绝对路径与 HTTPS 来源，并自动禁用示例数据；若数据库包含活动示例发布，启动会拒绝。实际部署时使用自己的域名与受保护配置。

长期单实例部署的systemd、Caddy模板、健康检查和恢复步骤见[部署手册](docs/长期部署.md)。健康接口会实际查询数据库，故障返回503。手动在线备份使用 `node scripts/backup-database.mjs --source <数据库> --destination <新备份文件>`，不覆盖已有文件；目前未配置自动备份或公网服务器。

数据库使用 SQLite WAL，当前面向单实例。固定推荐报告、发布和删除为短事务；联网研究为异步任务，阶段与结果持久保存，重启后未完成任务标记失败，用户可手动重试。没有预装 PostgreSQL、队列集群或自动备份；跨进程部署前需升级存储、共享额度/限流和作业策略。模型额度为单进程日额度，重启会重置，不应据此宣称长期账单硬上限。

研究检索按 `history-first-v1` 优先调查目标年度前3年的真实硕士项目，并单独检查目标年度变化；每个参考年度均有检索机会，明确目标年度停招或调整优先读取。初期最多18次搜索、40次普通读取，按学校与年份轮询、每校累计最多8次；意向城市恢复最多借用8次读取槽位。实际编码专业和同年度校区政策仍缺城市时可追加最多2次官方地理补读、每候选校最多1次。历史培养城市可标年份作参考，但目录与政策不得跨年拼接，目标年度相反证据不能被旧校区安排覆盖。随后费用补查最多6次搜索，读取使用剩余槽位；全流程共用24次搜索、60次官网读取与每校8次上限。80条搜索候选、最多24个同校目录／PDF／工作簿新链接共用读取预算，最多3层链接发现。原文保留换行以校验项目行；未填写学费时从已读取正文恢复唯一可核对的同校项目费用，并补入引用。具体领域、多种学习形式或冲突金额不强行选价，学习方式明确且按学年计费的历史金额可作带年份预算参考，全程／学期／学分价格不擅自换算。招生年度从正文明确政策语境识别，不以搜索标题、发布日期或版权年份补造。固定需求规则使模型层级措辞不能改变排序，城市证据未知不当作符合；达到5校而意向城市覆盖为0仍显示partial及缺口。旧报告需重新生成才能使用新规则。完整候选、分层、科目与测评边界见[推荐方法与证据链](docs/recommendation-method.md)。

## 数据与使用边界

全国基础学科目录来自官方版本；它不等于全国各校每年二级、自设、交叉招生专业的完整项目库。开发目录中的八个项目和二十道题仅用于流程验证。真实招生数据、题库学科审校、排序规则与分数依据仍须人工审核。生产无获批规则时返回未就绪，资料不足时不生成正式排名；历史门槛、备考目标和当前能力分别保存，五题测评不能换算考研成绩或录取概率。

账号会话Cookie有效期30天，登录成功旋转会话并支持同账号跨设备保存；退出撤销当前会话。尚未提供邮件验证、忘记密码找回或账号注销界面。删除个人资料会清除画像、测评、推荐结论、报告、收藏、屏蔽、确认专业、目标、任务、纠错、聊天与个人缓存；保留登录账号、当前会话和无内容的删除状态，可重新开始。此实例不自动备份；不能删除用户已下载文件。正式留存、备份恢复、监控和容量目标须在实际上线环境验收。

原 demo 缓存不自动迁入服务端，`/?demo=1` 只在开发服务器可访问。生产构建不包含旧 demo 与其题目答案。城市目录仍是[有来源说明的离线快照](docs/city-data.md)，不宣称实时或全国招生项目全覆盖。

## 公共院校资料预抓取（阶段4）

公共院校资料库已实现 ProgramFact，始终 `verified:false`。事实按项目身份、字段、年度和来源保存，复用时保留原获取时间，仍以当前画像核验推荐；不自动发布到正式目录。

```powershell
node scripts/prefetch-schools.mjs --city 杭州 --school 杭州电子科技大学 --school 浙江工业大学 --discipline 0802 --max-pages-per-school 3 --db var/prefetch-smoke.sqlite --dns-mode public-doh
node scripts/prefetch-schools.mjs --province 浙江 --dry-run
```

`--school` 可以重复，`--discipline` 限定事实汇总范围，公共目录原文仍按学校保存；默认每校20页、深度≤3，支持 `--refresh` 强制复核。未指定 `--db` 时沿用服务端数据库路径策略；`--dns-mode system|public-doh` 未指定时沿用服务端 YANTU_DNS_MODE 解析，不输出环境变量值。`--dry-run` 只列汇总，不建库、不联网。

脚本不调用付费搜索或模型；遵守 robots.txt、每主机串行、间隔≥1秒、全局主机并发≤4。robots.txt 不允许时不抓取；4xx 视为无限制（429 除外）；429/5xx/网络失败时跳过该主机。robots 允许同校注册域名内最多3次安全跳转；2xx 逐行解析，忽略无效行，HTML 无有效规则即无限制。超长内容仅解析前100000字节；页面跳转每一跳也受 robots 限制。汇总区分 robotsDisallowed 与 robotsUnavailable，并保留获取失败原因码。HTTP `.edu.cn` 原文保留明文传输标注，HTTP/HTTPS 同页按最终地址去重。杭州两校免费冒烟及研招网安全降级结论见 [实施说明第13节](docs/实施说明.md)。

## 阶段5预算与本地额度

研究预算集中在 `server/explanation/research-budget.ts`：60次正文读取、每校8次、24次搜索、初期40次读取、城市追加≤8次，全局并发≤4且同主机串行；80条候选、40项模型来源、40000字符思考输入，非思考仍16000字符。默认 `YANTU_MODEL_USER_DAILY_TOKENS=300000`、`YANTU_MODEL_DAILY_TOKENS=900000`，与直接创建运行时一致。规划和最终各一次修复及一次全报告临时重试预留209344 token，含可选覆盖补充为265728；仅本地账本，不是供应商账户余额或充值。修改现有部署额度需运维人员自行更新环境变量；本阶段未读取或修改真实 `.env`。

## 阶段6报告资料展示

报告顶部区分资料库累计收录与本次调查，显示复用、新读和失败次数；旧报告没有统计时显示未记录。推荐卡片展示初试科目、学费、培养校区/城市、资料年度的已绑定、待确认、未找到状态，保留历史参考和真实适用范围。

待确认原文每字段默认最多2条，其他可展开；已绑定字段默认收起待确认原文。已读但未结构化的学校页面默认折叠，前600字可展开至6000字。明文传输、研招网平台及复用原获取时间都有文字说明，375px与键盘交互通过模拟测试。继续补查沿用幂等与失败保留旧报告。详见[页面契约](docs/技术设计/04-接口与前端交互.md)与[实施说明](docs/实施说明.md)。
