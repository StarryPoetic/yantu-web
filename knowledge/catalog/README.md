# 招生知识库扩建

招生资料放在本目录，领域规则放在 `server/catalog`、`server/recommendation` 和 `server/planning`。HTTP、数据库、鉴权和模型供应商由各自 Module 负责；这里的 Interface 只读取 JSON 快照并返回新快照，没有网络请求、时钟、数据库或模型依赖。

## 当前资料的可信范围

`example.json` 只把原交互 Demo 的八个项目组合迁移为结构化示例。学校名称之外的组合、学院、专业和科目均未核验。所有项目保留 `isExample: true` 和 `availability: unverified`，分数、名额、假匹配百分比与假风险分组均未迁入。界面审核通过仅说明可以展示这份示例，不把示例变成真实招生事实。

正式覆盖院校、年份、资料源、规则权重和分数目标仍需文档 D-01、D-02、D-04、D-06、D-07 的人工决策。开发中的测试夹具写有明确测试标识，不能导入为真实资料。

## 新增资料

1. 复制 `import-template.json`，替换全部示例身份、内容和出处；保留 `schemaVersion: 1`。来源应记录发布机构、标题、官方 URL 或受控原件引用、采集时间、核验时间、原件 SHA-256 和使用限制。示例 URL 为空，不提供虚构官方链接。
2. 为年度项目生成稳定 `programId`，为内容修订生成新的 `programRevisionId`。唯一身份包括学校、学院、专业代码及体系、方向（未单列方向也要明确）、学位、学习方式、年度，以及官方区分的校区、招生单元、考试组。不同年份不能复用项目 ID。
3. 逐条填写 `claims`，保留原文定位、来源 ID、单位、年份、人群范围、录入及复核人。冲突保留为 `conflicting`，缺失使用 `null` / `missing`；不能补默认分数、费用、学制或资格。
4. 使用 `validateCatalogImport` 检查文件，再通过管理端导入。导入只接受 `draft` + `unpublished`；未知结构版本、重复身份、错误满分、缺少来源、未核验来源冒充 verified、重复风险证据都会拒绝。
5. 提交审核并记录理由，经过人工复核后批准；审批不会改变 `availability`。发布时提供完整修订清单、唯一目录版本和变更摘要，原子切换由存储层完成。
6. 新修订沿用年度项目 ID 并通过 `supersedesRevisionId` 引用旧修订。禁止覆写已发布版本。发现错误先撤回，再导入并发布更正版；旧报告保留固定快照，读取旧目录时同时附加撤回清单，新推荐不得使用被撤回资料。

前端字段、HTTP 契约与导入校验共用 `server/catalog/types.ts`。扩建专业或院校只增加数据，不复制推荐流程。大批量资料建议分批，每批最多 5000 个项目、20000 个来源；导入未通过时整批不写入。

## 三组状态各自独立

| 字段 | 允许值 | 用途 |
| --- | --- | --- |
| reviewStatus | draft / pending_review / approved / rejected | 人工审核进度 |
| publicationStatus | unpublished / published / withdrawn | 是否可供新业务读取 |
| availability | verified_current / verified_historical / missing / unverified / conflicting / expired / not_applicable | 事实可用范围 |

资格 `eligible/ineligible/unknown` 是规则对资料和个人条件的计算结果。任意已核验条件明确不符优先于未知；必要条件未全核实时不得进入正式前十。`isExample` 的项目始终是未知资格。

## 推荐规则与证据

`RecommendationRule` 要求独立的规则版本、两名不同复核人、兼容结构版本、六个评分维度的 0–100 权重、最低证据范围、缺失策略和风险规则。第七项“风险接受程度”只调整已审核中度风险的有限降权，不能加分。严重、仍适用且得到两名复核人与两簇独立证据支持的风险移出前十；匿名反馈、转载、已整改或失效材料不降权。

维度的规范值为 0–1，必须引用同一已审核 `ruleVersion` 和已核验来源。当前 Interface 支持人工评审后的证据取值和用户偏好权重，不自动从学校名气、城市名称、缺失就业数据或模型文字推导分值。缺少任一被赋权或规则要求的维度，候选保留为“符合已核验资格但无法排序”，不重分配剩余权重。权重全零同样不排序。并列按稳定项目 ID 排序，最多十项，不凑数。

规则未发布时保留 `facts_only` 和待核验列表；`exampleRule` 明确是草稿，不能进入生产排序。HTTP 层可以在生产环境将缺失有效规则返回服务未就绪。运行保存完整画像、选择、筛选及所有依赖版本；重新计算产生新运行。

## 科目、历史分数与规划

科目按实际项目填写，不能由学硕/专硕推导。官方允许的替代科目使用同一 `optionGroupId`，计划必须明确选一项。满分、单科门槛、总分门槛和复试条件分别核验，缺失保持 `null`。历史记录保留完整人群、录取类别、考试组、阶段、统计指标、满分、样本数、来源和可比性复核结果；缺年不插值，也不把历史录取最低分作为当年硬门槛。

计划可保存用户目标草稿。超过实际满分、低于已核验单科或总分门槛、科目合计不一致时，`valid` 必须为 false。资料不足为 `pending_verification`。只有科目与分数口径一致、有来源日期且经过复核的可靠测量才能计算当前表现；五题初测和自报成绩不换算考试分数。当前实现不自动生成分数建议或个性化分数差距。

任务模板只来自资料核验和实际科目。完成进度由存储层独立保存，计划修改不应重置旧任务；目标或科目变更会列出旧任务需要重新确认的 ID。报告固定推荐、计划和目录快照，保存 Markdown；后续资料更新只提示刷新，不重写原报告。

## 验证

运行 `node --experimental-strip-types --test tests/backend/catalog.test.ts tests/backend/rules.test.ts`。新增来源类型、资格算子、证据维度或科目选择逻辑时，先扩充对应正常、缺失、冲突、撤回和历史回放测试。技术测试只证明结构和计算，不证明资料事实真实；正式资料与排序规则仍必须人工复核。
