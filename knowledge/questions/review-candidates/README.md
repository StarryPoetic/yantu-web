# 5a 题库审校准备包

这里是现存56题的完整离线审校模板，不是新正式题库，不由应用自动加载。5a只交付边界说明、逐题材料、覆盖和缺项清单、校准待决表；真实学科审校和样本校准等人。本目录无发布命令，不将自动检查记为人工审核。

- `question-review-pack.json`：每题固定版本/哈希、完整原题快照、六项必需审核和五项补充检查；审核人、时间、通过与否、理由和更正全部null。
- `coverage.md`：由当前56题生成模块、范围、初分难度、知识点和逐题索引，并列出提示、错误假设、专业映射等缺项；不是正式大纲覆盖率。

## 离线检查

```text
node scripts/question-review-pack.ts --check
node --test tests/backend/question-review-pack.test.ts tests/backend/question-publication.test.ts
```

原题在 `knowledge/questions/example-v1.json`。生成器按真实题目计算，输出不会调用模型、搜索、网络、数据库或读取环境配置。更新原题后可用 `--write` 重建空模板；一旦模板中出现人工填写的审核或校准结果，生成器会拒绝覆盖。知识目录含答案，不应复制到公开静态资源或前端打包。

## 人工接手流程

1. 指定真实学科审校人与资料/版权负责人，保存本包版本及哈希。复核人与作者应独立。复制模板到单独的审校记录；不要直接改生成文件后再重建覆盖。
2. 逐题核验答案唯一、条件完整、选项差异、解析一致、范围和使用权。再复核提示不泄露答案、公式/图示及无障碍文本、干扰项假设与难度。判断“不适用”也需写原因，不能把空白当通过。
3. 发现错误时新建题目修订，保留原题和审校记录，重新核对适用测评及已保存作答的影响；没有完整审核的题继续draft/unpublished。
4. 专业映射、官方大纲范围、真实翻译/写作等主观任务覆盖需另行确认。现有每科五题仅观察本次知识点，不换算考研分、不校准能力等级、不预测录取概率。
5. 校准前由学科/试测负责人确定目标人群、采样与同意程序、样本量依据、难度与区分度、信度效度、偏差和分数映射验证、验收阈值。`calibrationDecisions` 全部null表示未决定；56题或某固定样本数均不能自动证明校准。
6. 获得真实审核后，通过既有独立审核/发布门禁处理新修订；本包不提供导入捷径、不代填检查项、不批准发布。审校与校准是不同状态，学科审校通过不自动把 `manual_initial` 改成 `calibrated`。

## 仍需确认

| 决定                           | 所需输入/负责角色                                            | 当前值 |
| ------------------------------ | ------------------------------------------------------------ | ------ |
| 首批正式科目、学科及题型覆盖   | 产品与学科负责人；明确机械等具体目标，不从通用专业题推断覆盖 | null   |
| 正式知识点/考试范围映射        | 当年适用大纲与具名学科复核                                   | null   |
| 来源和使用权                   | 原创依据、引用/授权范围及资料负责人                          | null   |
| 240公共题+40专业题建议是否采纳 | 先确认覆盖、题型、质量及人力；原建议不是完成标准             | null   |
| 审核人员和交付时间             | 独立学科审校人与版权负责人                                   | null   |
| 校准方案、样本与验收方法       | 学科/测量/试测负责人及合规样本                               | null   |

以上准备可由代码完成；具名审核、实际样本、事实校准及发布决定不能由自动化替代。5b可靠成绩录入与规划差距属于独立工作，不由五题示例结果代填。
