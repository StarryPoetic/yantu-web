## 复现命令与新增回归

```powershell
node scripts/diagnose-pdf-text.mjs
```

脚本固定执行 3 次顺序测试和 2 轮四并发测试，隔离继承环境，不启动应用服务。它保存每个进程的 TAP、退出状态、首项测试耗时和汇总 JSON；出现失败时退出非零。测试运行器的 60000ms 是整份测试文件的保护上限，生产 PDF 的 5000ms 没有修改。该诊断需要主动运行，不加入日常 `npm run check` 的重复负载。

新增回归同时发起英文/中文解析、页数超限与 1ms 超时，检查两个成功结果不会串文、一个请求超限或超时不影响其他请求，并验证随后仍能解析。现有 JavaScript 不执行、网络链接不打开、本地字体、字节/页数/字符上限、超时结束解析、环境隔离等测试全部保留。

## 结论与后续验证

本次有限重复未复现原超时，没有改动生产解析器、扩大时间限制、增加自动重试或引入常驻解析进程。仅凭当前证据不足以判断共享解析进程能够解决问题；该变化还会引入跨文档状态和终止隔离问题，不在本轮贸然实施。

本轮验证仅涵盖 PDF 专项，不能代替整个后端套件的混合负载。最终全量 `npm run check` 由主任务统一串行运行。若全量再次出现同一超时，保留对应日志和同时运行的测试；随后在该负载下增加受控的子进程启动/模块就绪/解析结束阶段测量，再决定最小修复。原偶发失败仍列为待观察风险。
