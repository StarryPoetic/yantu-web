# PDF 解析偶发超时验证记录

## 2026-11-11：补充阶段观测，根因仍待观察

本次给每个独立解析请求增加阶段时序：父进程请求/启动、worker 启动、模块加载前后、收到输入、解析前后、销毁前后、结果接收、截止时间与进程终止。解析器仍每次创建独立子进程，生产限制仍为 **5000ms**，没有自动重试、共享解析进程或延长超时。

`pdfText` 的可选内部 `onDiagnostic` 回调只收到随机请求 ID、固定阶段名称、毫秒时间、配置的截止时间和白名单错误码；不包含 PDF 正文、原件路径、URL、环境变量或凭据。观察者抛错或 Promise 拒绝会被隔离。默认不打印日志，错误对象上的阶段快照为不可枚举属性，不进入普通 API 错误 JSON。进程退出事件可以晚于解析 Promise 返回；不会为了等待诊断而延长解析任务。

父进程 `elapsedMs` 包含进程调度与 IPC；worker 的 `workerElapsedMs` 从其脚本开始计时，可用于计算模块加载、解析和销毁区间，两个时钟不能混合相减。缺失的阶段保持缺失，不能估计未完成阶段的耗时。销毁开始但未结束与模块尚未就绪可以据此区分，但仍须结合失败负载复现，不能仅据一次时序断言根因。

`node scripts/diagnose-pdf-text.mjs` 仍执行三次串行文件和两轮四并发文件。它显式开启测试阶段输出，按文件保存 TAP 和 `.phases.json`，汇总各阶段最大耗时、超时前最后观测阶段和 `productionDeadlineTimeouts`。测试中主动设定的 **1ms 超时负例**单独可识别，不算历史 5000ms 偶发故障复现。普通全量测试若出现默认截止时间超时，也会输出该请求的安全阶段轨迹。

新增回归覆盖成功阶段顺序、超时阶段与不可枚举错误快照、同步/异步观察者异常、并发请求 ID 与失败隔离；原有 JavaScript 不执行、禁用网络、本地 CMap、字节/页数/字符上限、环境隔离回归保留。

## 复现命令与新增回归

```powershell
node scripts/diagnose-pdf-text.mjs
```

脚本固定执行 3 次顺序测试和 2 轮四并发测试，隔离继承环境，不启动应用服务。它保存每个进程的 TAP、退出状态、首项测试耗时和汇总 JSON；出现失败时退出非零。测试运行器的 60000ms 是整份测试文件的保护上限，生产 PDF 的 5000ms 没有修改。该诊断需要主动运行，不加入日常 `npm run check` 的重复负载。

新增回归同时发起英文/中文解析、页数超限与 1ms 超时，检查两个成功结果不会串文、一个请求超限或超时不影响其他请求，并验证随后仍能解析。现有 JavaScript 不执行、网络链接不打开、本地字体、字节/页数/字符上限、超时结束解析、环境隔离等测试全部保留。

本次有限重复未复现原超时，没有改动生产解析器、扩大时间限制、增加自动重试或引入常驻解析进程。仅凭当前证据不足以判断共享解析进程能够解决问题；该变化还会引入跨文档状态和终止隔离问题，不在本轮贸然实施。
