# 备份保留与隔离恢复

本工具只处理部署方显式指定的数据库路径，不加载 `.env`，不读取应用配置或调用网络、模型、搜索。仓库中的配置与定时器只是模板，默认不启用备份，也不安装或启动服务。本次验证仅使用临时测试数据库，没有备份、清理或恢复真实用户数据库。

## 1. 配置与执行

复制 `deploy/backup.example.json` 到部署方管理的独立 JSON 文件，明确设置源库绝对路径、备份目录、至少保留数量及最短保留小时数。`enabled:false` 时即使传 `--apply` 也不操作；配置字段缺失、非法或多余均拒绝。备份目录不能包含源数据库。

```powershell
node scripts/managed-backup.mjs --config D:/yantu-ops/backup.json
node scripts/managed-backup.mjs --config D:/yantu-ops/backup.json --apply
```

第一个命令仅检查配置并汇总已有归属备份，不创建目录或备份，不清理文件。第二个命令在 `enabled:true` 时执行一次在线备份和保留规则。需要周期执行时，由部署方审核 `deploy/yantu-backup.service`、`deploy/yantu-backup.timer` 后安装并启用；模板为每天一次，仍需修改实际 Node 路径、目录权限、配置位置和执行频率。没有服务器时可手工执行一次命令做本地演练。

策略必须先确认：备份频率、可接受的数据丢失时间、恢复时间目标、`retainCount`、`minimumAgeHours`、备份目录、访问权限、异地加密和告警接收方式。模板数值仅为示例，不能当作用户已同意的正式留存政策。文件快照含账号和个人资料，须限制访问；Windows 还需检查目录 ACL。本工具不实现异地上传或加密，不声称副本已满足异地灾备。

每次先复用 `backup-database.mjs` 创建独立快照，通过完整性和外键检查，再转换为无 WAL 附件的独立数据库文件；最后写入归属清单，包含源库路径、生成时间、随机文件名和快照 SHA-256。控制台只显示状态、路径及计数，不显示数据库内容、账号或密钥。

只有本工具命名、清单归属同一源库、哈希相符的普通文件参加保留计算；没有清单、损坏、外来文件、符号链接均不作为清理对象。至少保留最新 `retainCount` 份，仅清理超过 `minimumAgeHours` 的其余归属快照。新快照或清单创建失败时不执行清理。清理只删除核验过的具体快照及配对清单，不递归删除备份目录。无效清单和孤立文件需由运维另行核查，工具不会猜测归属后删除。

## 2. 生成隔离恢复候选

```powershell
node scripts/restore-isolated.mjs --snapshot D:/yantu-backups/known.sqlite --current D:/yantu-data/current.sqlite --directory D:/yantu-rehearsal/new-candidate
```

三个路径必须是显式绝对路径，快照和当前库必须不同，输出目录必须尚不存在。父目录须已存在。输入库只读打开；输出只写新隔离目录，绝不覆盖在线库、不修改服务配置、不启动服务。

`--current` 必须由操作者确认为可信的当前状态库：它提供最新删除代次、账号状态、密码、资源存在性、撤回与消费账本。本工具不能自动判断哪个外部文件是真实当前库。当前可信状态不可读、所需结构缺失、出现未支持的数据表/触发器/视图或完整性失败时直接拒绝；只有旧备份不足以证明不会恢复已删除的数据。

恢复规则：

- 账号、密码、主体删除代次、注册登录限流和审计使用可信当前状态，已注销账号不会复活，密码不会回退。
- 个人资源仅保留快照与当前库内容相同、主体代次相同的记录；缺失、已修改、所属账号已注销的记录均保守丢弃。这个规则也避免恢复已从聊天中删除的消息。它不把当前更新内容自动写回旧快照，丢弃数量在报告中列明。
- 最新个人删除状态保留，所有旧会话、一次性恢复码和幂等写入回放清空，恢复后需重新登录并重新生成恢复码。
- 专业目录合并已撤回修订集合，题库撤回标记保留。当前推荐规则和当前题库使用可信当前库的完整状态；当前记录缺失则移除旧快照的活动记录，不能凭旧批准恢复为可用。带撤回标记的活动题库内题目仍标为撤回，新建测评入口也独立检查标记；旧发布不会消除新撤回。
- 日预算账本取快照和当前库的保守并集，同一预占采用较高计数，不因恢复返还消费或未知用量。
- 不支持的未来表结构直接拒绝；新增私人数据表时必须同步恢复规则与测试，不能原样遗漏地带入恢复副本。

输出为 `candidate.sqlite` 和 `RESTORE_REVIEW_REQUIRED.json`，状态固定为 `isolated-review-required`、`approvedForServing:false`。报告只给出计数、保护措施和可信状态采集时间，不输出个人正文、密码哈希或会话信息。若采集截点后发生新的删除、改密、退出或资料撤回，须使用更新的可信状态重新生成候选；本工具不提供对外切换命令。

正式恢复仍需运维关闭公网入口，验证目标版本与数据结构兼容、业务引用、账号隔离、删除及撤回保护、实际访问权限并登记审核结果，然后单独执行部署切换。不得因为 SQLite 完整性检查通过就自动开放旧数据。生成过程中可能遗留私有 `.yantu-restore-*` 临时目录；失败时工具清理自身临时目录，进程被强制终止后的遗留目录只能在确认无运行任务后人工检查清理。

## 3. 本地验证

```powershell
node --test tests/backend/backup.test.ts tests/backend/recovery-tools.test.ts tests/backend/usage-ledger.test.ts
```

测试只在系统临时目录生成合成账号和数据，覆盖在线 WAL 备份、现有目标保护、失败不清理、默认关闭与 dry-run、归属清单及最短保留、删除/注销/改密/聊天删改/退出/恢复码/撤回保护、未知表拒绝、原始输入库不变，以及恢复时预算不退款。真实服务器定时器、磁盘故障、外部加密存储、告警投递与恢复时间目标仍需在部署环境验收。
