# 研途 V0.3 实施说明

实施日期：2026-09-27。需求依据为[产品设计文档 V0.6](产品设计文档.md)与[技术设计文档清单](技术设计/00-文档清单与需求映射.md)。本次按用户反馈补齐全国专业范围、表单下拉、保存后下一步、测评后结论、逐题图文讲解、悬浮自由咨询和注册登录/管理员分流。本文记录实际实现与部署条件。

## 1. 当前交付范围

默认入口是同源 API 驱动的应用，覆盖注册登录、账号身份、画像、城市偏好、专业/院校双向检索、收藏与三级屏蔽、三项目对比、固定题集测评、有限诊断、推荐快照、目标与分科计划、任务、报告、纠错与审核后台，以及全国学科目录、个人专业探索结论、逐题公式与图解、悬浮多轮联网咨询。正式记录保存到数据库；旧浏览器 Demo 缓存不会自动上传。

提供可运行代码不等于真实招生资料已建设完成。全国基础目录包含14门类、117一级学科、67专业学位类别；不等于全国每校每年全部二级/自设招生项目。开发模式预置八个示例项目与二十道示例题，示例项目默认收起；这些项目的资格、分数、就业、政策及风险证据均不能冒充已核验事实。正式模式默认没有示例资料；未发布规则返回 503，未发布题库可跳过，资料不全不会补齐推荐前十。

## 2. 实施选择

| 范围 | 已实现的选择 | 适用限制 |
| --- | --- | --- |
| 运行与数据库 | Node.js 24.14+、React 19、TypeScript、SQLite WAL；单应用进程 | 使用 Node 自带 SQLite，无需额外数据库安装；PostgreSQL 属后续部署适配，不声称已支持。 |
| 持久化 | 一个 Store 负责参数化查询、事务、版本和请求回放；领域模块只处理快照 | SQLite 单机数据文件放 var，生产用独立路径；多进程服务须先迁移模型额度与限流共享状态。 |
| 身份 | 用户名密码注册/登录；scrypt独立盐哈希；稳定账号主体；30天HttpOnly/SameSite/生产Secure Cookie；会话旋转、频控、CSRF与来源校验 | 支持跨设备同账号数据，尚无邮件验证、密码找回及账号注销界面。游客注册迁移必须明确选择；登录已有账号不合并游客数据。 |
| 删除 | 清除个人画像、作答、结论/推荐、报告、收藏、目标、任务、纠错、聊天和缓存，阻断旧请求回填 | 保留登录账号、当前会话与无内容删除状态以重新开始；不自动备份，不删除下载文件。 |
| 管理权限 | 受保护环境首次初始化独立管理员账号，统一登录后按server角色分流；录入/复核/发布/审计分开 | 普通用户无法自选管理角色；初始化不修改已有密码或提升学生；规则和风险至少两名独立复核。旧Bearer只兼容机器接口。 |
| 作业 | 报告、发布、删除作为有持久状态的单事务短作业完成，返回 202 与已完成状态 | 当前无需独立队列；不宣称支持长时间后台执行、租约恢复或分布式队列。 |
| 规则 | 已核验资格先筛选，再按获批规则排序；缺失证据不重分配权重 | 附带规则样例未获业务批准，仅供开发事实浏览；正式发布需要真实复核。 |
| 规划 | 按实际项目科目与已核验门槛校验用户目标，当前能力不足为 null | 不从五题诊断推测考研分数；自动建议目标仍需经复核规则与数据。 |
| 题库 | 服务端组卷、草稿、主动提交、确定性判分、题库版本和适用性 | 不批量虚构未审题；新增范围覆盖不足返回具体原因。 |
| 模型 | 专业结论选择已验证依据；逐题固定解析+辅助讲解；自由咨询支持自然语言多轮；统一DeepSeek Adapter、额度、超时及降级 | 默认关闭，不在本次验证中调用收费服务；单进程额度在重启后重置，正式长期额度需持久计费账本。 |
| 联网 | Brave 搜索 Adapter 与官网 HTTPS 读取；提取文本、来源与检索时间 | 搜索需服务端配置；网站精确白名单，DNS 公网检查并固定连接 IP；外部资料只供参考。 |

上述工程选择满足本地开发和单实例验证。原设计 D-01、D-02、D-04、D-06、D-07、D-09、D-12 中的真实资料、规则数值、学科审校和正式城市口径仍属于内容发布门槛，不能由代码测试替代。

## 3. 模块与扩展位置

| 变化 | 唯一主要位置 | 调用关系 |
| --- | --- | --- |
| 全国学科目录、专业探索规则 | knowledge/disciplines、server/disciplines、shared/discipline-matching | 独立全门类目录和可解释关联，不从院校样例决定专业范围。 |
| 注册、登录与账号保存 | server/auth、server/store | 密码、迁移、身份和频控在单一模块；个人记录主体稳定。 |
| 新学校、专业、年度、政策/就业/评价依据 | knowledge/catalog 的规范批次与 server/catalog | 后台草稿 → 独立复核 → 原子发布 → 推荐读取固定版本。 |
| 新题目、考试范围、难度层和专业课 | knowledge/questions 与 server/assessment | 源文件仅在服务端加载；发布前逐题审校；前端只获得允许展示的字段。 |
| 资格、偏好、排序与风险策略 | server/recommendation | 接收画像/选择/目录与明确引用的诊断，不反向修改资料。 |
| 分科约束、能力证据与任务生成 | server/planning | 计划保存由应用层事务同步选择记录；任务进度独立保存。 |
| 模型供应商请求与费用控制 | server/explanation/deepseek.ts、index.ts | 业务不拼接供应商请求；密钥只读服务端环境。 |
| 网页搜索与读取 | server/explanation/web.ts | 仅公开资料进入受控问答；禁止任意工具执行与自动发布知识库。 |
| 报告格式 | server/reports | 读取不可变运行与计划；当前 Markdown 安全转义。 |
| HTTP、权限、并发与持久化 | server/routes、server/app.ts、server/store.ts | 所有写入经过会话/角色、版本、幂等及归属检查。 |
| UI 与数据请求 | src/workspace | 页面拆为目录、画像、测评、规划、助手和后台；api.ts 统一请求契约。 |

不用为每个专业复制推荐页面或算法，不建动态插件注册或任意多模型编排。新业务差异先扩展明确类型和发布校验，再增加测试；修改题目内容使用新修订 ID。详见[目录扩建](../knowledge/catalog/README.md)、[题库扩建](../knowledge/questions/README.md)和[模型与联网配置](../server/explanation/README.md)。

## 4. API 与前端约定

保留设计中的 `/api/v1`、JSON、ETag/If-Match、Idempotency-Key、错误状态及本人资源隔离。`PUT /me/selections` 整体保存选择，`GET /recommendations` 找回本人历史运行。新增 `/auth/session`、`/auth/register`、`/auth/login`、`/auth/logout` 管理身份；`/disciplines` 提供全国目录；`/guidance`、`/guidance/latest`、`/guidance/:id/explanation` 保存与解释专业结论。`/assistant/conversation` 读取、继续和清空多轮咨询，`/assessment-attempts/:id/tutor` 提供逐题讲解；原 `POST /assistant/questions` 保留兼容。请求字段通过允许清单验证，用户不能传 subjectId、标准答案或模型密钥。

当前管理端 `program/risk/claim` 草稿的 content 为完整 CatalogImport 批次，`question` 为完整 QuestionBank，`rule` 为 RecommendationRule。批次写入减少一条事实拆多次事务导致的混版本。每个草稿有独立复核记录和 ETag；题目复核须明确完成逐项检查。来源记录可单独登记，也必须包含在导入批次里。

业务 POST 与 DELETE 需幂等键；身份接口单独处理，不缓存密码请求或认证响应；即使重试命中记录，仍先验证身份、CSRF 和当前删除代次。删除作业重试仅返回删除状态，不回放旧资料。测评提交可重试，提交后的作答不能修改；重测产生新尝试。公开目录支持绑定版本/筛选的游标；当前个人历史列表一次返回，规模扩大前需补齐分页和留存归档。

模型咨询不读取未提交题库。普通咨询可自由问答和连续追问；专业结论解释只选择固定快照依据；提交后逐题讲解可围绕本题解释推导。外部网页和用户文本均为数据，不得改规则、自动发布招生事实或给无依据的录取概率。搜索摘要与官网正文分别标注，未核验内容保持辅助建议性质；无模型/搜索时显示真实状态。

## 5. 验证与发布门槛

`npm run check` 执行生产构建、后端单元/真实 HTTP 测试、文档检查与浏览器回归。测试使用临时或内存数据库、独立浏览器上下文、模拟模型与搜索响应，不使用真实学生资料、不产生模型费用。CI 执行相同流程。

- T-01/T-02：年度项目身份、资料状态/来源、审核与撤回、资格未知/不符、屏蔽、确定性排序及缺失证据。
- T-03/T-04：固定题集、五题基线、草稿版本/答案保护、主动提交/重试、专业变更适用性、实际科目/满分/单科/总分、有限诊断。
- T-05/T-06：身份隔离、CSRF、版本冲突、幂等、独立复核、资料删除、缓存清理、服务端秘密、网页 SSRF 防护。
- T-07/T-08：默认应用完整用户流程、城市与学位说明、刷新恢复、报告下载、375px 与键盘交互；旧 Demo 另作回归。
- T-09/T-10：数据库重启恢复、无资料/无规则降级、题库不可变修订、模型引用/截断/超时/预算/删除竞态、网页来源核验。
- T-11～T-16：全国专业完整性与无默认专业、画像下拉与保存流转、专业结论依据与失效、逐题公式图解、悬浮多轮咨询、注册登录及管理员角色分流。

实际学校资格、题库学科正确性、生产性能、长期备份/恢复、账号找回与身份治理、监控报警、正式模型质量和费用仍需要部署环境与人工内容验收。技术设计中的完整运营矩阵不是本地测试通过后自动完成的上线认证。

## 6. 数据迁移与回滚

首次启动自动创建表与索引；本轮以增量建表加入账号与登录频控，原个人资源不改归属。已有保存画像补齐完成标记，不伪造历史保存时间。旧 Demo 保留浏览器原键，默认应用不读取它；生产构建不包含 Demo 的题库答案。开发者需要 Demo 时使用开发服务器的 `/?demo=1`。

数据库、环境文件及日志均被 Git 忽略。代码回滚使用对应 Git 提交；数据回滚必须另行核验 schema、被撤回资料与删除标记，不能直接把旧数据文件覆盖线上库。当前没有自动备份或一键恢复命令，避免误将已删除信息重新开放。正式备份策略应在上线前补齐并演练。
