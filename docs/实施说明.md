# 研途实施说明（技术设计基线 V0.7）

实施日期：2026-09-27。需求依据为[产品设计文档 V1.0](产品设计文档.md)与[技术设计文档清单](技术设计/00-文档清单与需求映射.md)。本轮将联网研究改为完整画像驱动的方向规划与具体校专业分析，优先展示结构化匹配理由，将条件性适合建议与目标年度报考资格核验分开。本文记录实际实现与部署条件。

## 1. 当前交付范围

默认入口是同源 API 驱动的应用，覆盖注册登录、账号身份、画像、城市偏好、专业/院校双向检索、收藏与三级屏蔽、三项目对比、固定题集测评、有限诊断、推荐快照、目标与分科计划、任务、报告、纠错与审核后台，以及全国学科目录、个人专业探索结论、逐题公式与图解、悬浮多轮联网咨询。正式记录保存到数据库；旧浏览器 Demo 缓存不会自动上传。

提供可运行代码不等于真实招生资料已建设完成。全国基础目录包含14门类、117一级学科、67专业学位类别；不等于全国每校每年全部二级/自设招生项目。开发模式预置八个示例项目与二十道示例题，示例项目默认收起；这些项目的资格、分数、就业、政策及风险证据均不能冒充已核验事实。正式模式默认没有示例资料；未发布规则返回 503，未发布题库可跳过，资料不全不会补齐推荐前十。

## 2. 实施选择

| 范围 | 已实现的选择 | 适用限制 |

| 运行与数据库 | Node.js 24.14+、React 19、TypeScript、SQLite WAL；单应用进程 | 使用 Node 自带 SQLite，无需额外数据库安装；PostgreSQL 属后续部署适配，不声称已支持。 |

| 模型 | 普通咨询Flash；研究两个阶段按完整画像规划方向及分析官网具体校专业，至少两个真实画像维度理由 | 规划同模型非思考4096/30秒；最终默认Pro/high16384/120秒（最高16384），每阶段最多一次校验修复，共享额度；仅确认临时HTTP故障可经同账本再试一次，网络/超时/认证/余额/预算/取消不自动重试。自动化使用模拟响应，历史v3/v4/v5真实记录不代表v6已真实验收。 |
| 联网 | 默认博查，保留Brave显式兼容；每报告最多24次搜索、24次官网读取、40项搜索候选（另有受控附件/费用来源） | 历史官网可支持条件性校专业建议；年度资格、学费及名额仍待核验。示例/停招/无校专业证据拒绝，仅摘要partial。密钥隔离、HTTPS/公网DNS/IP固定继续生效。 |

上述工程选择满足本地开发和单实例验证。原设计 D-01、D-02、D-04、D-06、D-07、D-09、D-12 中的真实资料、规则数值、学科审校和正式城市口径仍属于内容发布门槛，不能由代码测试替代。

## 4. API 与前端约定

保留设计中的 `/api/v1`、JSON、ETag/If-Match、Idempotency-Key、错误状态及本人资源隔离。`PUT /me/selections` 整体保存选择，`GET /recommendations` 找回本人历史运行。新增 `/auth/session`、`/auth/register`、`/auth/login`、`/auth/logout` 管理身份；`/disciplines` 提供全国目录；`/guidance`、`/guidance/latest`、`/guidance/:id/explanation` 保存与解释专业结论。`/assistant/conversation` 读取、继续和清空多轮咨询，`/assessment-attempts/:id/tutor` 提供逐题讲解；原 `POST /assistant/questions` 保留兼容。请求字段通过允许清单验证，用户不能传 subjectId、标准答案或模型密钥。

当前管理端 `program/risk/claim` 草稿的 content 为完整 CatalogImport 批次，`question` 为完整 QuestionBank，`rule` 为 RecommendationRule。批次写入减少一条事实拆多次事务导致的混版本。每个草稿有独立复核记录和 ETag；题目复核须明确完成逐项检查。来源记录可单独登记，也必须包含在导入批次里。

业务 POST 与 DELETE 需幂等键；身份接口单独处理，不缓存密码请求或认证响应；即使重试命中记录，仍先验证身份、CSRF 和当前删除代次。删除作业重试仅返回删除状态，不回放旧资料。测评提交可重试，提交后的作答不能修改；重测产生新尝试。公开目录支持绑定版本/筛选的游标；当前个人历史列表一次返回，规模扩大前需补齐分页和留存归档。

模型咨询不读取未提交题库。普通咨询可自由问答和连续追问；专业结论解释只选择固定快照依据；提交后逐题讲解可围绕本题解释推导。外部网页和用户文本均为数据，不得改规则、自动发布招生事实或给无依据的录取概率。搜索摘要与官网正文分别标注，未核验内容保持辅助建议性质；无模型/搜索时显示真实状态。

`PUT /me/target` 用选择记录的 If-Match 原子保存年度项目与修订，衔接确认专业和规划；变更目标会使旧计划/推荐需复核。`GET /research/status` 仅检查配置。`POST /guidance/:id/research` 创建异步报告，`GET /guidance/:id/research/latest` 与 `GET /research-jobs/:id` 恢复/轮询任务。准备阶段执行全国目录与完整画像方向规划，之后实际检索、分析、整理；不以计时器伪造进度。新报告保持schemaVersion1并以 `reportVersion:profile-research-v7` 标识，兼容旧版 `profile-research-v6` 及历史v3/v4/v5，并可用failureStage标明真实失败阶段；researchDirections、followUpQuestions及建议的programName、degreeType、fitReasons、tradeoffs、admissionStatus可选，旧报告缺字段不补造事实。current_evidence表示找到目标年相关资料，不能显示为已满足资格。画像、诊断依据、目标或目录撤回造成的过期会显示并阻止沿旧结论生成。

题干行列式以内联结构呈现；解释性图示只在提交后序列化。答对、答错、未答使用绿色、红色、黄色方格，并附文字与辅助技术标签。单题回顾包含题干、自己的答案、标准答案、解析/图示和连续追问，左右切换不会混用题目上下文。

## 5. 验证与发布门槛

`npm run check` 执行生产构建、后端单元/真实 HTTP 测试、文档检查与浏览器回归。测试使用临时或内存数据库、独立浏览器上下文、模拟模型与搜索响应，不使用真实学生资料、不产生模型费用。CI 执行相同流程。

浏览器回归直接启动开发脚本，不加载本地 `.env`。并行测试共用本机IP，使用仅在 `NODE_ENV=test` 生效的 `YANTU_TEST_API_RATE_LIMIT=10000`；正式和开发环境仍为每分钟600次，覆盖配置不能绕过生产限制，测试环境也保留实际频控。限额边界及环境隔离由真实HTTP测试验证。

- T-01/T-02：年度项目身份、资料状态/来源、审核与撤回、资格未知/不符、屏蔽、确定性排序及缺失证据。
- T-03/T-04：固定题集、五题基线、草稿版本/答案保护、主动提交/重试、专业变更适用性、实际科目/满分/单科/总分、有限诊断。
- T-05/T-06：身份隔离、CSRF、版本冲突、幂等、独立复核、资料删除、缓存清理、服务端秘密、网页 SSRF 防护。
- T-07/T-08：默认应用完整用户流程、城市与学位说明、刷新恢复、报告下载、375px 与键盘交互；旧 Demo 另作回归。
- T-09/T-10：数据库重启恢复、无资料/无规则降级、题库不可变修订、模型引用/截断/超时/预算/删除竞态、网页来源核验。

## 6. 数据迁移与回滚

首次启动自动创建表与索引；研究任务复用带归属的资源存储，原个人资源不改归属。本轮示例题使用新版本与修订ID，已保存作答不修改答案或判分；旧题目展示经兼容层拆分题干与解析。已有保存画像补齐完成标记，不伪造历史保存时间。旧 Demo 保留浏览器原键，默认应用不读取它；生产构建不包含 Demo 的题库答案。开发者需要 Demo 时使用开发服务器的 `/?demo=1`。

数据库、环境文件及日志均被 Git 忽略。代码回滚使用对应 Git 提交；数据回滚必须另行核验 schema、被撤回资料与删除标记，不能直接把旧数据文件覆盖线上库。当前没有自动备份或一键恢复命令，避免误将已删除信息重新开放。正式备份策略应在上线前补齐并演练。

最终检查通过：格式检查、前后端TypeScript、生产构建及打包验证，594项后端测试、38项文档测试、79项浏览器测试，共711项。回归覆盖资料库重启复用、目录后半段的第8个专业、不同学校补查配额、同代码跨院与方式限制、真实费用附件关系、空页与超限拒存、补查失败保留、双击防重复及页面刷新；测试均使用模拟供应商。浏览器最初发现普通重新生成时残留旧报告遮住进度，修复后全量79项以单并发通过；不能把测试通过等同于全国资料已经补齐或真实供应商推荐质量已全面验收。
