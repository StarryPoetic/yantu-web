# 研途 V0.2 实施说明

实施日期：2026-09-27。需求依据为[产品设计文档 V0.5](产品设计文档.md)与[技术设计文档清单](技术设计/00-文档清单与需求映射.md)。用户本次明确授权实现项目，并补充「模型需要时可读取网页或搜索回答问题」。原 V0.2 技术设计保留为设计基线，本文记录已落地的实现选择与启用条件。

## 1. 当前交付范围

默认入口是同源 API 驱动的应用，覆盖游客会话、画像、城市偏好、专业/院校双向检索、收藏与三级屏蔽、三项目对比、固定题集测评、有限诊断、推荐快照、目标与分科计划、任务、报告、纠错与审核后台，以及有来源的联网咨询。正式记录保存到数据库；旧浏览器 Demo 缓存不会自动上传。

提供可运行代码不等于真实招生资料已建设完成。开发模式预置八个示例项目与二十道示例题；这些项目的资格、分数、就业、政策及风险证据均不能冒充已核验事实。正式模式默认没有示例资料；未发布规则返回 503，未发布题库可跳过，资料不全不会补齐推荐前十。

## 2. 实施选择

| 范围 | 已实现的选择 | 适用限制 |
| --- | --- | --- |
| 运行与数据库 | Node.js 24.14+、React 19、TypeScript、SQLite WAL；单应用进程 | 使用 Node 自带 SQLite，无需额外数据库安装；PostgreSQL 属后续部署适配，不声称已支持。 |
| 持久化 | 一个 Store 负责参数化查询、事务、版本和请求回放；领域模块只处理快照 | SQLite 单机数据文件放 var，生产用独立路径；多进程服务须先迁移模型额度与限流共享状态。 |
| 身份 | 30 天匿名 Cookie、HttpOnly、SameSite、生产 Secure，CSRF 与来源校验 | 无账号绑定、跨设备登录或身份找回；清除 Cookie 会失去原匿名记录的访问凭据。 |
| 删除 | 清除全部个人资料、作答、快照、报告、收藏、目标、任务、纠错和缓存 | 保留会话与不含内容的删除状态；本实例不自动备份；无法删除用户下载文件或外部平台记录。 |
| 管理权限 | 环境配置不同操作者的角色凭据；录入、独立复核、发布、审计分开 | 普通资料至少一名独立复核，规则和风险至少两人；后台凭据仅内存输入，需部署方管理。 |
| 作业 | 报告、发布、删除作为有持久状态的单事务短作业完成，返回 202 与已完成状态 | 当前无需独立队列；不宣称支持长时间后台执行、租约恢复或分布式队列。 |
| 规则 | 已核验资格先筛选，再按获批规则排序；缺失证据不重分配权重 | 附带规则样例未获业务批准，仅供开发事实浏览；正式发布需要真实复核。 |
| 规划 | 按实际项目科目与已核验门槛校验用户目标，当前能力不足为 null | 不从五题诊断推测考研分数；自动建议目标仍需经复核规则与数据。 |
| 题库 | 服务端组卷、草稿、主动提交、确定性判分、题库版本和适用性 | 不批量虚构未审题；新增范围覆盖不足返回具体原因。 |
| 模型 | 固定解析 + DeepSeek Adapter，受控 JSON、引用验证、额度、超时及降级 | 默认关闭，不在本次验证中调用收费服务；单进程额度在重启后重置，正式长期额度需持久计费账本。 |
| 联网 | Brave 搜索 Adapter 与官网 HTTPS 读取；提取文本、来源与检索时间 | 搜索需服务端配置；网站精确白名单，DNS 公网检查并固定连接 IP；外部资料只供参考。 |

上述工程选择满足本地开发和单实例验证。原设计 D-01、D-02、D-04、D-06、D-07、D-09、D-12 中的真实资料、规则数值、学科审校和正式城市口径仍属于内容发布门槛，不能由代码测试替代。

## 3. 模块与扩展位置

| 变化 | 唯一主要位置 | 调用关系 |
| --- | --- | --- |
| 新学校、专业、年度、政策/就业/评价依据 | knowledge/catalog 的规范批次与 server/catalog | 后台草稿 → 独立复核 → 原子发布 → 推荐读取固定版本。 |
| 新题目、考试范围、难度层和专业课 | knowledge/questions 与 server/assessment | 源文件仅在服务端加载；发布前逐题审校；前端只获得允许展示的字段。 |
| 资格、偏好、排序与风险策略 | server/recommendation | 接收画像/选择/目录与明确引用的诊断，不反向修改资料。 |
| 分科约束、能力证据与任务生成 | server/planning | 计划保存由应用层事务同步选择记录；任务进度独立保存。 |
| 模型供应商请求与费用控制 | server/explanation/deepseek.ts、index.ts | 业务不拼接供应商请求；密钥只读服务端环境。 |
| 网页搜索与读取 | server/explanation/web.ts | 仅公开资料进入受控问答；禁止任意工具执行与自动发布知识库。 |
| 报告格式 | server/reports | 读取不可变运行与计划；当前 Markdown 安全转义。 |
| HTTP、权限、并发与持久化 | server/routes、server/app.ts、server/store.ts | 所有写入经过会话/角色、版本、幂等及归属检查。 |
| UI 与数据请求 | src/workspace | 页面拆为目录、画像、测评、规划、助手和后台；api.ts 统一请求契约。 |

不用为每个专业复制推荐页面或算法，不建动态插件注册或任意多模型编排。新业务差异先扩展明确类型和发布校验，再增加测试；修改题目内容使用新修订 ID。详见[目录扩建](../knowledge/catalog/README.md)、[题库扩建](../knowledge/questions/README.md)和[模型与联网配置](../server/explanation/README.md)。

## 4. API 与前端约定

保留设计中的 `/api/v1`、JSON、ETag/If-Match、Idempotency-Key、错误状态及本人资源隔离。便于前端整体保存，增加 `PUT /me/selections`；提供 `GET /recommendations` 找回本人历史运行；新增 `POST /assistant/questions`。请求字段通过允许清单验证，用户不能传 subjectId、标准答案或模型密钥。

当前管理端 `program/risk/claim` 草稿的 content 为完整 CatalogImport 批次，`question` 为完整 QuestionBank，`rule` 为 RecommendationRule。批次写入减少一条事实拆多次事务导致的混版本。每个草稿有独立复核记录和 ETag；题目复核须明确完成逐项检查。来源记录可单独登记，也必须包含在导入批次里。

所有 POST（游客会话除外）与 DELETE 需幂等键；即使重试命中记录，仍先验证身份、CSRF 和当前删除代次。删除作业重试仅返回删除状态，不回放旧资料。测评提交可重试，提交后的作答不能修改；重测产生新尝试。公开目录支持绑定版本/筛选的游标；当前个人历史列表一次返回，规模扩大前需补齐分页和留存归档。

模型咨询不读取未提交题库。用户输入的问题和网址是任务数据；模型输出只允许选择来源中的可校验引文，不得改规则、发布招生事实、给出无依据的录取概率。搜索结果摘要与已读取官网正文分别标注，网络失败或无配置会返回明确的降级状态。

## 5. 验证与发布门槛

`npm run check` 执行生产构建、后端单元/真实 HTTP 测试、文档检查与浏览器回归。测试使用临时或内存数据库、独立浏览器上下文、模拟模型与搜索响应，不使用真实学生资料、不产生模型费用。CI 执行相同流程。

- T-01/T-02：年度项目身份、资料状态/来源、审核与撤回、资格未知/不符、屏蔽、确定性排序及缺失证据。
- T-03/T-04：固定题集、五题基线、草稿版本/答案保护、主动提交/重试、专业变更适用性、实际科目/满分/单科/总分、有限诊断。
- T-05/T-06：身份隔离、CSRF、版本冲突、幂等、独立复核、资料删除、缓存清理、服务端秘密、网页 SSRF 防护。
- T-07/T-08：默认应用完整用户流程、城市与学位说明、刷新恢复、报告下载、375px 与键盘交互；旧 Demo 另作回归。
- T-09/T-10：数据库重启恢复、无资料/无规则降级、题库不可变修订、模型引用/截断/超时/预算/删除竞态、网页来源核验。

实际学校资格、题库学科正确性、生产性能、长期备份/恢复、账号服务、监控报警、正式模型质量和费用仍需要部署环境与人工内容验收。技术设计中的完整运营矩阵不是本地测试通过后自动完成的上线认证。

## 6. 数据迁移与回滚

首次启动自动创建 schema version 1 的表与索引。旧 Demo 保留浏览器原键，默认应用不读取它；生产构建不包含 Demo 的题库答案。开发者需要 Demo 时使用开发服务器的 `/?demo=1`。

数据库、环境文件及日志均被 Git 忽略。代码回滚使用对应 Git 提交；数据回滚必须另行核验 schema、被撤回资料与删除标记，不能直接把旧数据文件覆盖线上库。当前没有自动备份或一键恢复命令，避免误将已删除信息重新开放。正式备份策略应在上线前补齐并演练。
