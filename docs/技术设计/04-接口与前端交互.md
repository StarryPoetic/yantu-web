本版新增院校资料三层架构与收集可靠性方案（2026-10-11）。阶段0只修订文档与测试；新增模块、读取策略和覆盖契约须在后续阶段实现并验收，现行预算保持不变。

## 1. 通用契约

当前本地服务采用同源 `/api/v1`、UTF-8 JSON；下表记录实现契约与扩展约束，不代表已经公网部署。字段含义以 [02](02-数据模型与可信数据.md)为准，身份与数据权限以 [05](05-安全运维与验证.md)为准。时间用带时区的 ISO 8601，分数/金额附单位与口径；未知值为 `null` 并带原因，不用零替代。

- 成功响应包含 `schemaVersion`、`requestId`、`generatedAt` 和该资源实际涉及的业务版本；不再增加含义重叠的通用数据版本。列表游标绑定筛选、排序和快照，提供 `nextCursor`，翻页不能混入新目录。
- 本人资源归属由会话解析 `subjectId`；客户端不提交主体归属、审核结论、标准答案、模型参数或密钥。返回字段使用允许清单，答案仅在本人已提交结果中可见。
- 可变资源返回不透明 `ETag`，`If-Match` 必须匹配资源当前版本；缺少必需条件为 428，版本不符为 412。业务状态不允许为 409。首次创建画像由 GET 返回已定义空画像及版本，不靠猜测初始值写入。
- 创建、提交、生成、解释、删除作业等 POST 和异步 DELETE 使用 `Idempotency-Key`；作用域为已认证主体（管理端为操作身份）＋操作＋删除代次＋键，另存输入摘要。相同键及输入返回同一资源/作业，输入不同为 409。鉴权及删除屏障必须先于任何幂等响应回放；旧代次响应不得返回被删内容，重建画像的 ETag 不复用旧值。删除自身的重试只复用受保护的删除作业状态，不回放资料。并发以唯一约束和事务消重；键保留期见 D-10，测评一次提交约束持续到对应个人记录删除。
- 游客会话创建是上述业务幂等的例外：已有有效会话时复用；未有会话时创建空主体，不接收个人资料。响应丢失后的新空会话不能冒领旧主体，未使用空主体按 D-03 期限清理。
- PUT 表示资源的完整目标状态，重复写相同内容不产生额外副作用；PATCH 只修改列明字段。草稿及任务写入用版本检查防覆盖。客户端取消请求不保证服务端取消，应通过资源 ID 查询结果。
- 统一错误体为 `{code, message, requestId, details}`，`details` 仅含可公开字段/原因，禁止原始上游错误、SQL 或凭据。400 结构错误；401 会话失效；403 操作权限不足；404 不存在或隐藏他人私有资源；409 状态/幂等冲突；412 版本冲突；422 业务约束不满足；428 缺条件头；429 限流；503 服务不可用或发布配置未就绪。

## 3. 核心请求与响应约定

**推荐请求**：`{profileVersion, selectionVersion, targetAdmissionYear, filters, assessmentRefs[]}`。画像未填也使用有效空版本。服务端固定当前兼容的目录与规则，逐项校验引用；题目范围不适用的诊断返回 `ignoredAssessmentRefs[]` 及理由，越权引用直接拒绝。撤回诊断不得使用。服务端不自动采用未明确引用的最近测评。

**推荐响应**：`{recommendationRunId, profileVersion, selectionVersion, catalogVersion, ruleVersion, assessmentRefs[], ignoredAssessmentRefs[], coverage, items[], pendingVerification[], exclusionReasons[]}`，附通用响应元信息。每项含 `programId`、`programRevisionId`、专业方向列表、资格依据、名次、事实/规则/偏好分类的理由、风险、实际科目、来源和缺失项。空结果是合法成功；规则包未就绪为 503，不生成伪推荐。

**测评提交**：客户端先等待所有草稿保存成功，再用最后取得的 ETag 主动提交。若有未答题必须明确确认；412 时读取新草稿并让用户核对，不能自动覆盖或提交。服务端按 attempt ID 唯一提交；相同幂等键重试优先返回已保存结果，不因旧 ETag 再次评分。新键对已提交尝试只返回既有提交，不修改答案。

**目标选择**：只接受 `programId/programRevisionId` 字段，取消时不接受修订字段。已撤回或修订变化返回 409；不存在的项目返回 404。全国类别由有效 `majorCode` 前四位及 `degreeType` 共同确定，无全国对应时仅兼容明确历史方向；歧义不自动决定。相同目标重复 PUT 无新版本、副作用；实际变化保存新选择版本，并为已有计划新增需复核版本。前端等待保存成功再导航，失败保留详情及原目标。规划页以选择记录为准，不用 GET 计划中的旧 programId 覆盖它。

**报告请求**：`{recommendationRunId, planId?, planVersion?, format}`，首版格式 `markdown`。计划 ID/版本成对出现；校验主体与目标年度相同、计划显式引用的来源运行就是该运行、目标在其中且项目修订/目录/规则一致。保存目标引起的选择版本递增不要求与原运行相等；needs_review 计划不可作为当前有效方案生成报告。依赖不符返回 409 提示重算或选对版本，不能混合旧分数与新科目。排队时固定输入，执行前再核验删除代次与撤回状态；依据被撤回则失败并要求刷新。

**联网研究请求与恢复**：先读取 readiness 及当前结论的 latest，再由用户显式 POST 生成；读取或轮询本身不启动付费请求。任务固定本人基础结论及 `selections.targetProgramId` 对应的项目修订和目录，拒绝客户端传入模型、归属、报告或进度。返回阶段 `preparing/researching/analyzing/writing` 分别表示整理依据、检索/读取网页、模型分析、引用核对与报告整理；10/30/60/90 的刻度只随真实阶段进入变化，终态 completed/partial 才到 100，不用计时器伪造进度。配置缺失为 blocked，只有摘要或证据不足为 partial，失败/取消显示原因。离开再返回读取持久任务；服务重启把未完成任务标为 failed，用户重新发起才能重试，不自动付费重试。旧幂等键读取最新任务状态，不启动第二次生成。

研究期间及结果写入前复核会话、删除代次、结论版本和目标资料；失效则停止后续写入并显示原因。历史报告读取附需刷新标记，不能把历史内容冒充当前结论。联网报告不使用固定 Markdown 报告的 recommendationRunId/planVersion 契约替代自身依赖。

新报告通过 `reportVersion:'profile-research-v7'` 区分，字段主定义见 [02](02-数据模型与可信数据.md)。页面首先展示具体学校、`programName`、目录派生学位类型、`fitReasons`、`tradeoffs` 与逐项 `admissionStatus`，然后展示准备动作和补问。`current_evidence` 显示“已取得目标年度相关资料”，不能显示为“已符合报考资格”；`needs_verification` 显示“目标年度待核验”，同时保留有官网关联依据的适合建议。旧基础探索默认折叠并标记规则参考，不以“当前结论”标题与模型研究混淆；研究范围、完整来源与模型技术信息放在可展开区域，年度待核验状态留在卡片上。`failureStage` 可选值为 `preparing/researching/analyzing/writing`，表示失败发生的真实阶段；阶段失败、模型输出校验失败和用户信息不足分别解释。已保存画像充分但模型格式错误时，不提示用户必须先选学校或重新填写画像；只有实际画像不足或有效规划中的明确追问才请求补充。保存画像（包括清空notes）成功后，新基础结论与报告固定新的profileVersion；旧结论仅供回顾并标记过期，新请求不能用旧值填补已清空内容。报告中的profileValue由服务端当前快照绑定，浏览器不自行拼接或沿用旧理由。旧报告缺字段时兼容显示原专业类别和原理由，不拼造具体专业或匹配依据。

准备阶段实际执行完整画像与全国目录的方向规划，再进入搜索、官网读取和最终分析。已确认专业或已选目标可以作为用户约束，但本科专业及旧结论高亮项不能自动缩小完整候选目录。查看历史、展开来源、刷新或轮询不启动新的模型规划或收费请求。

### 3.1 逐专业资料覆盖与继续补查

当前 v7 在每个候选学校的 `candidateAudit[].coverage.programs` 中分别记录专业、目录代码、学院、学习形式与资料年度。同校同名专业的不同学院或学习形式保留独立身份，不借另一专业的费用、考试科目或培养地点。六个资料字段为 `program/exams/location/tuition/eligibility/curriculum`；状态为 `supported_current/supported_reference/missing/ambiguous/not_applicable/excluded`。每项附 `reason/sourceIds/references`，引用保留该来源实际原文与年度；历史资料显示为参考，不能改称目标年度已核验。已有目录但学费、城市或考试未知时，只记录对应字段缺项，不把整校说成缺目录；资料覆盖状态也不等于符合报考资格。

`evidenceCoverage` 使用 `strategy:program-evidence-v1`，返回本次学校数、专业数、已有专业依据数与仍有实质缺项的专业数，以及 `gaps/reusedSourceCount/supplementedSourceCount/lookupKeys/attempts`。每个缺项有稳定 ID、适用专业与年度、优先级、原因、下一动作、原文引用及实际读取记录；失败记录包含 URL、失败原因和尝试时间。历史参考已有依据但目标年度待核对的事项单独保留，不能与完全未读到目录混合计数。覆盖数量仅统计本次实际调查，不代表全国院校资料已全部覆盖；未调查学校不能据此排除。

“继续补查缺少的资料”调用上述 supplement 端点，请求体必须为 `{}`，不接受客户端指定报告、缺项、学校、模型或进度。请求使用同源 JSON、`X-CSRF-Token` 与 `Idempotency-Key`，服务端先核验本人会话、基础结论和版本，再回放幂等结果。相同键和输入返回同一任务的最新状态；不同键再次提交时，若同一结论已有 queued/running 任务，也返回同一在途任务，生成与补查共用该防重复边界。没有已有报告返回 409；基础结论已过期时须刷新，不能把旧画像的缺项用于新结论。

`ResearchJob.mode` 区分 `generate/supplement`。补查任务创建时携带上次报告作为基础报告（base report），queued 响应及 latest 均返回该基础报告，刷新页面或补查进行中仍可阅读和导出。按钮在请求提交及 queued/running 时禁用，重复点击复用当前任务。补查请求失败或任务失败保留历史报告及来源，展示独立失败原因并允许用户显式重试；不因错误清空报告，不自动发起付费重试。新报告完成后更新逐专业依据与缺项，生成新报告的入口继续保留。

公共资料库只复用合规官方公开正文、真实获取时间与读取诊断，不保存个人画像、模型回答或私人推荐。补查按已有缺项与年度定向读取，优先专业目录等主证，随后处理具体字段；保留查询去重键与失败冷却记录，并共享原研究任务的检索、正文读取和取消边界。每次任务仍受最多 24 次搜索及 60 次正文读取限制，不承诺一次补齐，也不做无界重试。

## 4. 管理接口与发布

管理接口使用独立身份、角色和审核权限。以下 `kind` 仅允许预先定义的 program/question/rule/risk/claim，映射到固定模块和结构；不是允许任意表名或动态工作流的通用入口。

| 方法与路径 | 作用与限制 |
| --- | --- |
| `POST /api/v1/admin/sources` | 登记原件、出处、范围、使用限制和哈希。 |
| `GET /api/v1/admin/drafts/{kind}` | 按状态/范围检索草稿，稳定分页。 |
| `POST /api/v1/admin/drafts/{kind}` | 以该类型固定结构创建草稿及 ETag。 |
| `PUT /api/v1/admin/drafts/{kind}/{draftId}` | If-Match，修改未提交草稿；已批准内容另建修订。 |
| `POST /api/v1/admin/drafts/{kind}/{draftId}/submit-review` | If-Match，校验后进入 pending_review。 |
| `POST /api/v1/admin/drafts/{kind}/{draftId}/withdraw-review` | If-Match，将 pending_review/rejected 返回 draft；关闭旧审核，修改后重新提交审核。 |
| `POST /api/v1/admin/reviews/{reviewId}/decision` | If-Match，批准/拒绝及理由；检查复核人数、角色和自审限制。 |
| `POST /api/v1/admin/publications` | kind 为 catalog/questionBank/rule，固定获批修订及依赖清单；202 作业完成后原子发布。 |
| `POST /api/v1/admin/publications/{publicationId}/withdraw` | 指定受影响修订/范围和理由，执行紧急失效并保留审计。 |
| `GET /api/v1/admin/jobs/{jobId}` | 读取授权管理作业状态与脱敏校验结果。 |
| `GET /api/v1/admin/corrections` | 审核人员查看纠错队列。 |
| `PATCH /api/v1/admin/corrections/{correctionId}` | If-Match，补充处理决定与关联修订；不能跳过发布。 |
| `GET /api/v1/admin/audit-events` | 按权限、对象、人员和时间查询追加审计。 |

单题发布检查答案唯一、解析、适用范围和来源；组卷规则另检查每科五题及覆盖，不能把“题库只有五题”当发布条件。资料状态由 02 定义，后台不得自创第二套审核状态。待审核/被拒草稿可撤回到编辑态，但每次再提交需新审核记录；历史审核不能复用到改过的内容。

## 5. 页面状态与迁移

客户端的筛选、弹窗和当前题号属于页面状态；正式画像、提交结果、收藏、计划和发布记录以服务端为准。新请求开始时记录输入版本，慢响应只有仍匹配当前条件才显示；删除期间及删除后拒绝旧代次响应，避免重新填回个人资料。离线或服务错误保留当前草稿和已加载内容的时间标记，不用演示项目补真实结果。

Demo 的 `yantu-demo-v1`、测评 v2 和后台示例不自动上传。将来若提供迁移，先预览并由用户确认；旧六题记录不迁成新版完成结果。未提交题目不放入包含标准答案的前端包；正式页面展示加载、无覆盖、待核验、失败和需刷新等明确状态。

## 6. 交互细则

首次进入先登录/注册，服务器确定角色后分流；学生不显示管理入口或凭据输入框。退出卸载所有个人页面与聊天，过期会话引导重新登录。管理员页面显示只读身份和权限，服务端对每次操作重复授权校验。

画像的年份、英语经历、数学基础、每日时间、预算、备考进度、主要目标采用下拉控件，允许“不确定”；本科院校/专业/相关课程保留自由输入。旧的自定义字段值要能显示，不因下拉改造静默丢失。保存成功显示持久进度并自动进入测评；失败保留表单，不前进。

兴趣输入由独立 `InterestPicker` 维护展示状态，画像仍保存普通字符串；建议来自全国目录名称。使用同宽、左右对齐的自定义 combobox/listbox，按中文拼音首字母及名称排序，分组仅含当前匹配项，不显示空字母。支持名称与首字母搜索、顿号/逗号分隔多兴趣及自由文本；选择不会丢弃先前兴趣。上下方向键移动、Enter 选择、Esc 收起，组合输入期间不拦截键盘；焦点和选中状态通过 ARIA 暴露。浮层依据可用空间翻转、限定高度并独立滚动，桌面与手机都不超输入框或视口宽度。对应 T-17。

测评提交后保留逐题解析，并出现明确“查看专业推荐结论”按钮，不能自动跳走导致读不到解析。全国目录按门类/关键词/学位筛选，默认无确认；未核验示例招生项目默认收起。悬浮圆球不占固定导航栏，面板有关闭和清空入口、键盘焦点与手机适配；关闭不等于清空。



测评按实际选择计算题号、总数和模块进度；选中反馈后自动下一题，末题停留待主动提交。返回修改不丢作答；改模块或重新答题创建新尝试，显式处理旧草稿。题库不足显示原因并允许跳过测评。答前讲解仅提供安全概念提示，完整推导及解释图只在提交后开放，模型失败仍显示审核解析。题干的受限数学表达直接插入对应文本位置，不另排一份重复公式；手机局部数学容器可滚动，页面不横向溢出。对应 T-18。

已提交结果采用三色方格题号导航，正确、错误、未答同时有文字/可访问名称；支持按题号、上一题/下一题与键盘切换单题回顾。一次仅展开当前题的本人作答、标准答案、固定推导、解释图和追问入口，不把所有解析堆在同一长列表。切换回顾题不修改已提交作答，刷新从本人固定结果恢复；单题未答和模块边界仍保留。对应 T-19；完整状态与适用性见 [06](06-诊断型题库与分层选题.md)。

城市浮层打开、页面滚动、窗口及手机可视高度变化时重新定位，空间不足向上翻转并限制高度；列表独立滚动，字母索引只含实际分组，底部说明及四方向按钮始终可见。输入框内保留光标方向键；进入选项后左右相邻、上下按实际网格行列、Home/End 首末、Enter 选择、Esc 收起。聚焦项滚入列表可视区，不带动整页；鼠标四方向按钮同样可用。

学硕/专硕说明在画像页与推荐页共用内容和组件，桌面双列、手机单列，宽高不超视口；标题与关闭按钮固定，正文独立滚动，Esc 关闭并将焦点返回入口，键盘焦点不落到弹窗背后。正文默认 16px、辅助至少 12px、标签/按钮/次要操作至少 14px；375px 不裁字、不整页横向滚动，宽表格只在自身容器内滚动。


### 6.1. v7 多校报告与分层

页面以资料库加检索的覆盖目标取得5–10所不同学校，每校一个具体主专业；按“第一级·优先推荐（preferred）”“第二级·适合备选（alternative）”“第三级·探索选择（exploratory）”展示，并显示tierReasons解释为什么在这一层。结合目标、兴趣、基础、跨专业准备成本、时间、城市和预算，费用或城市不符不自动决定层级；同费用学校可分不同层。

当前层级由服务端 `demand-match-v1` 固定规则决定，模型只提供解释，不能改变层级；有城市偏好时，城市未知不满足优先比较条件。unknown条件仍需核验，不能把preferred、current_evidence或有来源显示为“已符合报考资格”。

卡片显示至少两项真实画像理由、取舍、budget/cities检查结果，以及有证据时的费用年度、金额、形式、单位和来源；无证据不填价格。历史费用只作参考，年度预算不直接与全程费用比较。

`coverage` 显示实际不同学校数和不足5所的具体缺口，禁止用同校多专业凑数。v5等旧报告缺字段时按历史内容展示并提示重新生成，不将旧结果自动包装成v7；刷新只读已有任务，显式重新生成才发起新请求。来源和原始研究范围继续位于可展开区域。

余额不足、认证失败、无效请求、临时HTTP故障、连接错误与结构校验失败分别显示原因。后台在同一任务内执行已限定的临时重试时显示真实重试阶段，不伪造百分比或要求用户改画像。服务重启仍不自动付费重试。对应T-23、T-24。

### 6.2. 资料库覆盖展示契约（V0.7，阶段6已实现）

新报告为 `profile-research-v7`，兼容旧版 `profile-research-v6` 及v3–v5；旧报告缺字段时显示“该报告生成时未记录资料覆盖统计”，不能默认计数为0或伪造全库覆盖。保存的零计数正常展示；缺少任一统计字段时不拼出完整的统计句。

报告顶部展示“资料库已收录 X 校 Y 专业、本次复用 Z 条、新读 W 条”，字段对应02的 `librarySchoolCount/libraryProgramCount/reusedSourceCount/supplementedSourceCount`。全库收录与本次覆盖分开展示，复用保留原获取时间，新读只计本次成功读取的唯一来源，不计失败或资料库复用。失败尝试单列，原因分布使用 `shared/research-status.ts` 的中文说明；内部代码只放在默认折叠的“技术信息”中。保存的历史尝试继续用于缺口诊断，不计入本次失败次数。

每张推荐卡片直接展示初试科目、学费、培养校区/城市、资料年度四项逐字段状态：“已绑定”“待确认”“未找到”。已绑定显示值、资料年度与来源；历史事实标“历史参考，目标年度待核验”。校区证据只到城市时显示“城市已核验，具体校区待确认”。学费范围分别显示“全校统一标准”“按学位类型的全校标准（学术/专业学位）”或“该专业标准”，按实际学位类型展示括号内容；按学习方式的学校标准继续保留。候选调查中的六项字段清单和独立专业身份仍可展开查看。

待确认原文整合现有 `pendingEvidence`，不另建重复清单。每字段默认最多2条，优先目标年度，再按年份新旧；余下放进“查看更多待确认原文（N 条）”。已有确定绑定的字段，其待确认原文默认收起。连续摘录保留“归属待确认”原因，不用于预算或城市匹配。未找到的字段说明是否有记录的继续补查任务；未记录任务时提示重新调研。

来源为 `transport:'http'` 时在链接旁显示“明文传输”，说明沿用已有传输警告；来源完整列表保留同一警告原文，不增加第二套说明。研招网域名显示“研招网平台”。资料库复用来源显示原获取时间。来源链接新窗口打开并使用 `rel="noopener noreferrer"`，必要核验状态不藏在来源折叠区。

服务端 `unstructuredSources` 保存本次成功读取、明确所属学校且未抽取出任何 bound 字段的页面，pending-only 页面也保留。仅有搜索摘要、未读取、复用页面或归属不明页面不列入；不能套用邻近专业事实。按学校提供默认折叠的“已读但未结构化的原文”，显示页面标题、链接、获取时间与前600字连续原文，可展开至6000字；截断时提示打开来源。该列表随账号私有报告保存，任务和 latest 接口仅向报告所有者返回。
