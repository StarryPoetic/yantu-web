# 接口契约与前端交互设计

状态：设计草案｜依据：[产品设计文档 V0.5](../产品设计文档.md)

## 1. 接口边界

当前 React/Vite 页面继续负责表单、筛选、可视化和无障碍交互；正式服务通过版本化 JSON API 提供已发布项目、测评、推荐、收藏、规划与后台审核。浏览器不得持有模型密钥、管理员凭据或用于评分的正确答案。静态 Demo 数据保留为明确标记的演示模式，不与正式接口结果混用。

首版可采用同源 `/api/v1`，请求和响应均使用 UTF-8 JSON；时间使用 ISO 8601，金额/分数为数值加单位和口径，空值显式为 `null` 并附缺失原因。列表使用游标或稳定排序分页。写请求带请求 ID，需防重复提交的端点使用幂等键。返回数据包含 `schemaVersion`、相关 `dataVersion` 与 `generatedAt`，便于回溯。

## 2. 学生端 API 草案

| 方法与路径 | 用途 | 关键约束 |
| --- | --- | --- |
| `POST /api/v1/guest-sessions` | 创建匿名会话 | 签发仅同源可用的会话凭据；游客模式是当前设计假设，是否需要登录和跨设备同步须在 D-03 确认。 |
| `GET/PUT/DELETE /api/v1/me/profile` | 读取、保存、删除画像 | PUT 带 `If-Match` 或版本号，冲突返回 409；DELETE 清理画像、诊断草稿与结果，并返回删除范围。 |
| `GET /api/v1/cities` | 城市标准库和拼音检索 | 返回来源版本、规范 ID；自定义城市保留原文与匹配状态，“不确定”与城市列表互斥。 |
| `GET /api/v1/major-directions` | 专业方向、学习内容和职业去向 | 带来源、适用年份及缺失标记。 |
| `GET /api/v1/programs`、`GET /api/v1/programs/{id}` | 检索及查看招生项目 | 可按年份、专业、城市、学校筛选；详情包含完整组合键、实际考试科目、资料状态与历史分数口径。 |
| `POST /api/v1/recommendations` | 基于画像和筛选条件联合推荐 | 服务端固定规则/目录快照；返回最多十项、待核验列表、解释及版本；不得接受客户端传入“报考资格已通过”。 |
| `POST /api/v1/assessment-attempts` | 按阶段和模块创建测评 | 首版公共课至少一科；专业课阶段仅作为可选增强的预留契约，启用时要求已确认专业；返回固定题集版本与不含答案的题目。 |
| `PATCH /api/v1/assessment-attempts/{id}`、`POST .../{id}/submit` | 保存草稿、主动提交 | PATCH 保留题号、选项、思路、用时；提交幂等并由服务端判分；未提交不得产生结果。 |
| `GET /api/v1/assessment-attempts/{id}/result` | 读取诊断 | 仅提交后可读；包含所选模块、题库版本、证据限制与解析。 |
| `GET/PUT/DELETE /api/v1/me/saved-programs/{programId}` | 收藏/移除项目 | 收藏按完整招生项目 ID；屏蔽项另存且可恢复。 |
| `GET/POST /api/v1/me/exclusions`、`DELETE /api/v1/me/exclusions/{id}` | 读取、屏蔽和恢复学校/专业方向/完整项目 | 请求明确 `scope` 和对象 ID；服务端展开作用范围并返回受影响组合数量及排除原因，删除记录后重新推荐。 |
| `GET/PUT /api/v1/me/plan` | 确认目标和分科计划 | 服务端检查项目科目、总分与单科目标的一致性；资料不足返回待核验项。 |
| `GET/PUT /api/v1/me/tasks` | 查看与勾选阶段任务 | 返回任务来源、生成版本、目标项目与状态；目标或科目变化时旧任务转历史或待确认，保留已完成记录。 |
| `POST /api/v1/reports`、`GET /api/v1/reports/{id}` | 生成与获取报告 | 报告固化当时输入和数据版本，注明来源、缺失、风险及生成时间。 |
| `POST /api/v1/corrections` | 提交资料纠错 | 只生成待审核记录，不直接影响已发布目录。 |

推荐结果的最小结构应包括 `runId`、`profileVersion`、`catalogVersion`、`ruleVersion`、`assessmentVersion`、`coverage`、`items[]`、`pendingVerification[]`。每个 `items[]` 至少有 `programId`、完整项目名称、`majorDirectionId`、`eligibility`、`rank`、`reasonFactors[]`、`riskFactors[]`、`subjectRequirements[]`、`sourceRefs[]` 与 `missingData[]`。解释因子应标明是事实、规则计算还是用户偏好，前端可据此展示“为何推荐”和“为何变化”。

统一错误体建议为 `{code, message, requestId, details}`。400 表示字段无效，401 表示会话失效，403 表示无权限，404 表示资源不存在，409 表示版本冲突或状态不允许，422 表示计划不满足已知科目/分数约束，429 表示请求过频，503 表示上游或模型暂不可用。对 503，目录查询和确定性推荐仍应可用；模型解释失败时返回规则生成的简明理由。

## 3. 管理后台 API 草案

后台需独立身份认证与角色控制，至少区分录入、复核、发布和审计；高风险评价不得由录入者单独发布。接口按“草稿 → 待复核 → 已批准 → 已发布 → 已撤回”状态流转，服务端限制跳步并记录审核人、时间、差异与理由。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/v1/admin/sources` | 登记官方文件、就业/政策资料或评价证据的原始来源、适用年份与文件校验值。 |
| `POST/PUT /api/v1/admin/program-drafts` | 维护项目、报考条件、科目、分数口径与专业关联的未发布版本。 |
| `POST/PUT /api/v1/admin/question-drafts` | 维护题目、答案、解析、适用范围及题库版本。 |
| `POST /api/v1/admin/reviews/{id}/decision` | 审核招生资料、题目和评价；要求留下决定及证据。 |
| `POST /api/v1/admin/publications` | 原子发布经过审核的数据快照；支持撤回并保留历史版本。 |
| `GET /api/v1/admin/audit-events` | 按对象、人员、时间查询不可随业务记录修改的审计事件。 |

项目发布前应验证组合键唯一、目标年份、资格条件、考试科目、来源链接及适用范围。题目发布前应验证五题模块、正确答案和解析。评价公开前要完成脱敏、去重与证据分级。

## 4. 前端状态与迁移

现有 `src/App.tsx` 持有页面、收藏、目标与筛选，`src/Flows.tsx` 包含画像和管理示例，`src/AssessmentView.tsx` 包含本地测评，`src/CityPicker.tsx` 管理城市输入。正式接入时将数据访问抽成统一客户端与查询缓存，展示组件仍可复用。页面状态（当前筛选、展开弹窗、正在看的题号）留在前端；画像、测评结果、收藏、排除项、目标、报告及审核记录以服务端为准。接口返回前显示加载/空态/资料待核验，不把旧演示数据静默填入正式结果。

首次进入正式环境不自动上传现有 `localStorage` 中的 `yantu-demo-v1`、`yantu-demo-assessment-attempt-v2` 或后台演示记录。若将来提供迁移工具，应先给用户逐项预览和确认；旧六题记录一律不转为新版测评。删除画像成功后清除本地相关缓存和草稿，避免刷新后恢复；收藏与目标的删除策略需与最终产品隐私定义保持一致。

## 5. 交互实现约束

### 专业/院校探索

专业卡片和院校项目卡片消费同一个推荐结果。改变专业、学校、城市、学位类型、排序或偏好时，客户端发起新请求并取消或丢弃旧请求结果，防止慢响应覆盖新条件。收藏与对比按完整项目 ID 操作；屏蔽可作用于学校、专业方向或完整项目，界面显示范围与排除原因并提供恢复。对比最多三项的当前 Demo 限制可继续采用，但首版是否固定为三项需产品确认。学硕/专硕说明不得将学位类型映射成固定考试科目。

### 测评

客户端负责选中反馈和自动切题计时，服务端负责草稿版本与判分。题目总数、当前题号、模块进度和结果都从本次实际所选模块及固定题集计算，不使用默认十五题常量覆盖单模块尝试。末题停留待用户提交，刷新恢复到同一尝试与题号；切换模块必须创建新尝试或显式确认放弃旧草稿。若启用可选专业课测评，切换目标专业时提示旧结果的适用性变化。公共课未测仍可进入推荐，能力解释显示“依据不足”。

### 城市浮层与学位说明弹窗

城市浮层相对输入框定位，打开、页面滚动、窗口变化及手机可视高度变化时测量可视区域，空间不足则向上翻转并限制高度。城市列表独立滚动，字母索引只显示有城市的首字母，底部操作区保持可见。输入框内的方向键保留光标行为，进入选项后再处理 `← →` 相邻移动、`↑ ↓` 按当前网格实际显示行列移动、`Home/End` 首末项、`Enter` 选择和 `Esc` 收起；键盘选中项滚入列表可视范围但不滚动整页，并保留可点击的四方向按钮。

学硕/专硕说明在推荐页与画像页使用同一个弹窗组件。桌面双列、手机单列，宽高随视口收缩且不超出屏幕；标题与右上角关闭按钮固定，正文独立滚动；支持 Esc 关闭和焦点返回触发按钮。主内容正文默认 16px，辅助说明不小于 12px，表单标签、按钮及次要操作不小于 14px；375px 宽度页面不裁字、不产生整页横向滚动，宽表格仅在自身容器内滚动。

## 6. 接口评审前待定

需要产品明确首批专业及项目清单、报告保留/下载格式、游客资料保留期限、是否要跨设备账号、对比项数量与后台审核角色。上述决定不影响本草案的项目组合键、版本化来源、主动提交和无障碍交互约束。
