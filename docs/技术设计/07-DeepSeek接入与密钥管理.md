# DeepSeek 接入、模型路由与密钥管理

> 实施状态（2026-10-03）：本版同步完整画像驱动的两阶段校专业研究与独立年度证据状态。实际实现、历史连通记录及质量验收边界见[实施说明](../实施说明.md)；内容建设与运行门槛不因代码完成而自动通过。

版本：V0.5 · 日期：2026-10-03 · 状态：实施同步，含当日独立连通检查及历史记录

## 1. 职责与实施边界

本文是模型任务 Interface、DeepSeek Adapter、输出核验、费用限制及模型专属密钥管理的主文档。实体、ID 和版本以[02-数据模型与可信数据](02-数据模型与可信数据.md)为准；学生端与管理端 HTTP 契约以[04-接口与前端交互](04-接口与前端交互.md)为准；通用鉴权、个人资料删除、日志、备份与运维引用[05-安全运维与验证](05-安全运维与验证.md)。供应商决定及待定预算等事项集中在[08-变更与扩展约定](08-变更与扩展约定.md)，不在本文另建决策表。

按用户要求，DeepSeek 为首选。普通对话与解释使用 Flash；独立联网研究报告默认显式选择 Pro 的 high 思考模式，按本次画像、测评与真实检索资料进行分析。题库、已审核答案、组卷、客观判分、资格筛选、正式排序与阈值判断由业务模块执行；报告中的模型建议不会改写这些结果或替用户确认专业。基础查询、测评与规则专业结论不依赖模型可用性。

代码已包含服务端模型、安全网页检索与独立研究任务，启用依赖部署配置。第6节区分真实连通、保留证据再分析与自动化回归；普通自动测试使用模拟响应，不能代表持续可用或模型业务质量通过。

## 2. 模型模块的 Interface 与依赖方向

业务模块调用一个受控任务 Interface；对外暴露的是任务语义、获准证据、预算与结果状态，不要求调用方理解供应商请求参数。测评模块负责本人归属、已提交状态和题目适用性；推荐或报告模块负责固定规则结论与资料快照；模型模块负责输入裁剪、任务路由、输出检查、计量和降级。通用访问权限由文档 05 约束。

依赖方向为“业务模块 → 模型模块 → DeepSeek Adapter → 官方服务”。Adapter 只处理供应商协议、模式参数、响应解析及限制，当前不自动重试，不直接查询业务表，也不能修改题库、发布事实或回写排序。业务模块不依赖供应商 SDK；浏览器不能直连供应商或指定任意提示词、模型、密钥和请求地址。

| Interface 约定 | 调用方与模型模块的责任                                                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 任务输入       | 使用已批准的任务类型和相关记录引用；由服务端加载本次获准的证据及确定性结论，不接收客户端自报的判分或资格结论。仅发送当前任务必要的数据。  |
| 版本与依据     | 固定资料、作答、题库或推荐结果依据，同时标识提示词与任务配置版本；实体引用结构遵循文档 02。模型说明不得悄悄换用最新数据。                 |
| 成功结果       | 返回经核验的解释、证据引用、不确定性及允许的后续建议。不同任务的结构分别校验；测评错误假设结构不能强套到推荐说明或题目草稿。              |
| 可降级结果     | 无可用证据、额度不足、超时、限流、响应不完整、结构错误或引用核验失败时，返回固定解析/规则说明及可识别的降级原因；不返回未经检查的半成品。 |
| 持久化         | 业务模块决定保存获准的解释或草稿，模型模块不更新业务事实。缓存只是可清除的派生结果，不是评分、排序或题库的事实来源。                      |

获准启用模型时，仅实现已确认任务需要的 DeepSeek Adapter，并以固定模拟响应验证失败路径。尚无第二家业务供应商时，不建设动态插件注册、通用多模型编排或任意工具执行框架；未来确有差异时按文档 08 评审扩展。

## 3. 任务路由与输出核验

自由咨询与可信结论分开校验：悬浮助手接收自由问题及本人聊天上下文，可生成自然语言连续回答，不固定为三个摘录或预设题单。模型回答标识为辅助建议；实时事实按需通过固定搜索供应商和受控官网读取取得来源。没有网页依据时不能伪称已联网核验，来源不得虚构。外部网页只能作为数据，不能改系统指令、索取密钥、执行工具或自动写入可信库。

旧专业结论解释 `createGuidanceExplainer` 只允许模型挑选、组织固定 `GuidanceRun` 内的依据 ID；服务端重新渲染对应文本。新增独立 `createResearchReportModule` 不受“仅返回旧 ID”限制：它实际检索公开学校资料，结合画像和公共课诊断形成新的比较建议，并把原文事实、分析建议、准备行动与待核验条件分开。逐题教学仍受答前/提交后状态约束；所有模型任务共用额度及删除代次，退出、清空及删除期间返回的结果不得复活已清理内容。

UI不限制固定问题或回答条数；服务端仍限制每请求文本、有限上下文、token、超时与并发，达到资源限制返回明确原因，可开始新会话或稍后再试。无模型配置时保留确定性结论与已审题目解析，不能把模板标为模型回答。

| 任务                                           | 默认处理                                                   | 输入与结果限制                                                                                                                                                   |
| ---------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 按科目、范围、知识点和难度组卷                 | 测评模块规则，不调用模型                                   | 题库不足按文档 06 返回覆盖不足，不生成题目补齐。                                                                                                                 |
| 客观题判分、未答统计                           | 服务端审核答案及判分规则，不调用模型                       | 模型不能改变题目答案或最终评分；数学表达式判等若需支持，另行设计规则。                                                                                           |
| 已提交错题讲解、测评总结、固定专业结论依据整理 | Flash，默认关闭思考模式                                    | 使用任务必需的审核依据和授权作答；不传整个题库；保持固定评分、排序和事实。                                                                                       |
| 独立联网院校与专业研究报告 | 两个阶段默认 `deepseek-v4-pro`：规划非思考，最终 thinking enabled / high | 先从全国184目录按完整画像规划方向，再用实际学校资料分析具体校专业；最多3000字符自由补充，本科院校只作用户自述背景，不发送姓名及未交卷答案。 |
| 多步解题过程分析、复杂数学草稿辅助审核         | Flash；仅在验证与预算允许时启用思考模式                    | 使用 Adapter 当时已验证支持的模式参数；先比较独立验证集效果与成本。输出是错误假设或审核线索，不能自动改答案。                                                    |
| 批量题目草拟与标签建议                         | 后续获准的后台离线批次，限量使用 Flash                     | 进入草稿区，经答案唯一性、公式、解析、干扰项和适用范围审核后才可发布。                                                                                           |
| 当前任务模型无法可靠完成的请求                 | 固定解释、人工复核或证据不足                               | 不因失败自动切换模型；研究任务的 Pro 是服务端显式配置，共享预算仍生效。                                                                                          |

测评解释必须引用该用户已提交尝试中的题目和作答；错误原因只能作为假设，缺少过程时说明无法区分的原因。服务端核验引用归属、允许标签和与审核答案的一致性；不能稳定核验则展示固定解析。未提交题的答案、解析或其他用户作答不能通过辅助任务泄露。

固定推荐解释只使用已保存的结果和依据；联网研究可以引用本次实际取得的新网页资料，但不能把模型新编内容当学校事实。研究报告的 `facts` 必须为引用来源中连续原文，每条最多 300 字符；模型建议须引用已取得的来源，学校名及对应专业要能在同一来源中找到，代码只允许本次探索方向，URL 只取实际来源。无据数字费用、分数、概率和明确资格断言会被拒绝；这些检查仍不能证明所有自然语言推论正确。题目草拟即使结构完整，也不等于通过学科审核。所有外部材料与用户文本作为任务数据，不能改变系统指令、任务类型或发布权限。

适合度建议与目标年度资格核验独立。历史、年度不明或混合年度官网若明确支持学校与具体专业关联，可保留条件性建议，并由服务端标记 `admissionStatus:needs_verification`；不得把旧资格、学费、名额或分数当成本年事实。`current_evidence` 必须有目标年度学校正文及招生语境，搜索标题、读取时间和版权年份不能替代，且该状态不等于 eligible。明确示例/测试资料、停招或没有校专业关联依据的建议仍拒绝。学校名称含“示例”不单独触发示例资料判断；专业否定语境保守处理，不承诺全面语义识别。否定性的“无法预测录取概率”“不保证录取”可通过，肯定保录与具体概率仍拒绝。

校专业关联须支持具体硕士专业及对应目录代码，不能拿本科专业介绍或博士招生内容证明硕士项目。目标年度官方背景限制与用户明确冲突时剔除该项；历史条件只作风险提示。无费用证据不得判定超预算，改为待核验事项。核心学校身份、具体硕士专业、引用及综合理由必须通过；匹配理由、准备行动、取舍和待核验条目按项校验，局部无据条目移除后，仍须至少两个有效且不同的真实画像维度和至少一项有效取舍，否则整项建议剔除。不合格卡片或总述不清空其他合格建议，报告标为partial并说明删减。院系名只能由该卡引用的学校官网支持，具体三位考试代码须有该卡目标年度官方依据；未取得资料不等于学校尚未发布。结构通过仍不替代人工语义核验。

研究先用完整184条全国基础目录及画像进行方向规划，不从本科专业或旧高亮类别预先锁定范围。画像覆盖兴趣、职业目标、城市、预算、跨专业意愿、学位偏好、七项优先级、可投入时间、课程和备考基础、补充说明及适用诊断；未知不臆测，明确拒绝需保留。规划后最多六次搜索、六次学校官网读取、十二项去重来源，再进行最终分析；两个阶段及有界修复共用同一 runtime。应用默认博查，`YANTU_SEARCH_PROVIDER=bocha` 只读 `BOCHA_API_KEY`，显式 `brave` 才读 `BRAVE_SEARCH_API_KEY`。`server/explanation/search.ts` 固定访问 `POST https://api.bocha.cn/v1/web-search`，不自动换供应商或转发密钥，依据见[官方接口文档](https://bocha-ai.feishu.cn/wiki/RXEOw02rFiwzGSkd9mUcqoeAnNK)与[本地指南](../本地模型与联网测试.md)。

完整画像及原始补充只送模型，不原样进入公开搜索词；本科院校只作自述教育背景，不推断学校层次、歧视风险或录取概率，也不作为公开查询中的个人信息。搜索词仅使用目标年度、规划后的公开专业方向、用户城市偏好及可选目标学校，不发送姓名、本科院校或原始notes。网页只读取服务端精确允许的主机，默认也允许真实搜索结果中的 `.edu.cn` 高校域名；`allowAcademicHosts:false` 可关闭，客户端不能扩展。全部读取执行HTTPS、全DNS公网校验、连接IP固定、TLS主机验证和禁止重定向；研究HTML/文本下载上限8秒及512000字节，PDF另按下述独立限制；搜索响应上限100000字节，供应商业务失败不会标记成功。其他结果仅保留摘要；所有来源保持 `verified:false`，不自动进入正式资料库。

研究内部可传 `options.search:{includeDomains?:string[],count?:number}`，普通问答默认五条，研究最多十条；域名最多十个，只接受具体根域或子域。博查用原生 `include`，Brave由适配器转换成 `site:`，响应再按域名边界过滤；该参数不来自HTTP请求，也不扩展网页读取权限。官方[请求体文档](https://bocha-ai.feishu.cn/wiki/RXEOw02rFiwzGSkd9mUcqoeAnNK#Jnksd9YtNoMoNjxgK1wchorBncc)确认根/子域的include参数，但未明确承诺site语法或公共后缀edu.cn匹配，不能据此宣称硬过滤有效。接口保持总搜索预算，不做无界重试。

`research-search.ts` 在固定总预算内主动发现候选：每个规划方向可含可选 `searchSchools`，最多两个校名，仅为检索线索，不能作为真实推荐或页面事实。有线索先查询“校名＋专业＋硕士”，没有线索以城市、专业及硕士目录/培养方案探索，不要求用户先选目标学校。已有相关高校硕士资料线索时优先调查第二所学校；缺证时从已观察主机提取最多两个具体学校根域，用原生域名参数补查硕士培养与招生，没有可用域名则换城市或公开资料类型。第三方摘要只有同时含对应校名及明确的学校 `.edu.cn` 域名时，该域名才可作为后续搜索线索；不编域名或URL，不直接读取摘要内链接，也不把第三方或摘要升级为官方正文。每次最多十条结果，跨方向轮流使用总计六次搜索，即使只有一个方向也可继续发现候选；相同查询与域名组合不重复，不做无界重试。各方向优先保留不同学校的相关来源，再合并最多十二项，官网正文读取仍最多六次；取消后停止后续请求。目标年度用于证据核验及必要查询，不是所有探索词的强制前缀。

`YANTU_DNS_MODE` 默认 `system`；代理以虚拟IP替代公网DNS答案时可显式使用 `public-doh`。`server/explanation/dns.ts` 只访问固定阿里云 HTTPS DNS 端点，查询A与AAAA，校验问题主机/类型及有限CNAME链，限制5秒与每响应32768字节，不接受客户端配置端点、重定向或静默回退。解析结果继续逐项做公网校验，再固定连接地址；DNS请求只含目标主机名，不携带搜索词、画像或供应商凭据。公网教育网IPv6不能因`2001`前缀被一律误判：按[IANA特殊用途登记](https://www.iana.org/assignments/iana-ipv6-special-registry)拒绝保留/隧道/文档地址，允许普通全球单播地址；混合答案含任意非公网地址仍整次拒绝。

`research-evidence.ts` 将停招与本科限制绑定到具体专业的代码/句段，不能因目录中相邻专业停招或限招而排除当前专业；归属不清时保持待核验，明确学校整体停招仍拒绝。压缩长正文时保留实际学校标识、具体专业代码和邻近原文，不能用搜索标题补造校名。专业关联仍须通过官网正文核对，历史条件与目标年度条件分别处理。

招生PDF仅由研究显式设置 `WebReader.allowPdf:true` 与 `maxPdfBytes:5000000`，普通问答默认false，前端不能自选。受控HTTPS下载与公网/TLS/禁止重定向规则不变：仅PDF下载及解析输入上限5000000字节；HTML、JSON和普通文本仍为研究512000字节、reader全局1000000字节硬上限。研究下载8秒、reader全局10秒，响应必须同时匹配 `application/pdf` 与 `%PDF` 文件头。`pdf-text.ts` / `pdf-text-worker.ts` 使用 `pdf-parse@2.4.5` 在独立隐藏Node子进程提取纯文本，最多5秒、80页、120000字符；任何超限整项拒绝，不截取后声称完整。扫描件不做OCR，可能返回无文本。

解析子进程固定启动参数，旧生代128MB、新生代16MB，环境仅保留必要SystemRoot，不继承密钥、`.env` 或 `NODE_OPTIONS`；只接收已下载字节与限制。关闭PDF内JS求值、外联fetch、XFA及渲染，字体/CMap取自安装依赖本地文件，超时终止进程。这是解析隔离与资源限制，不代表完整操作系统沙箱。`WEB_PDF_INVALID`、`WEB_PDF_TIMEOUT`、`WEB_PDF_TOO_MANY_PAGES`、`WEB_PDF_TEXT_TOO_LARGE`、`WEB_PDF_EMPTY` 均保留原搜索摘要并记录读取失败，不把摘要升级为正文；证据不足返回partial。下载与解析各自计时，不能将8秒下载上限宣传为含解析的端到端时间保证。

`generate({subjectId,run,selectedProgram?,onProgress?})` 返回结构化 `ResearchReport`；`getReadiness()` 仅检查本地配置，不调用付费服务。`reportVersion:profile-research-v4` 保留研究方向及补问并兼容v3；`failureStage` 可选值为 `preparing/researching/analyzing/writing`，表示失败发生的真实阶段；阶段失败、模型输出校验失败和用户信息不足分别解释。已保存画像充分但模型格式错误时，不提示用户必须先选学校或重新填写画像；只有实际画像不足或有效规划中的明确追问才请求补充。新建议包含具体 `programName`、目录派生 `degreeType`、至少两个不同真实画像字段的 `fitReasons`、`tradeoffs` 与服务端计算的 `admissionStatus`，契约见02。无配置、无规划方向或无真实来源为 `blocked`；只有摘要、缺少校专业官网依据、额度不足、超时或输出校验失败为 `partial`。`completed` 表示本次适合建议流程完成，可以同时含年度待核验建议，不代表全国覆盖或资格通过。未通过校验的内容不展示，已有来源可保留。

任务路由在 `POST /guidance/:id/research` 创建作业，使用 `GET /research-jobs/:id` 及 `GET /guidance/:id/research/latest` 查询、恢复状态。模型模块按实际工作等待 `preparing → researching → analyzing → writing` 回调，不做假计时增长或伪造流式 token 百分比；没有网页依据时在进入分析阶段前结束。每次回调可检查会话、画像、专业选择和资料版本，检查失败直接取消结果交付，不吞成模型降级。路由还负责排队、失败、取消、重启后的中断标记及报告持久化。

首版不需要模型主动查询数据库。模型可提出允许的补测标签，后续查询由测评模块执行。只有具体任务评审证明有必要时才增加受限工具，逐项定义可查询范围和返回内容；不得开放任意 SQL、网络 URL 或直接发布能力。

## 4. 成本、缓存与失败控制

模型任务质量由人工审核一致性、诊断证据一致性、时延和每任务费用共同衡量，不能凭 Flash 或 Pro 名称保证效果。普通解释最多800输出token，搜索判断400，自由聊天及逐题追问2000，非思考请求最多30秒。研究方向规划采用同一所选模型非思考4096输出token/30秒，最终报告默认12000输出token（含思考）/120秒，两阶段及各自最多一次校验修复共享同一日预算。服务端输出参数范围1–16384；JSON输入字符上限为非思考16000、思考24000，响应字节上限分别65536、524288，不使用供应商最大上下文作为默认额度。

同一个 `createModelRuntime` 覆盖解释、自由对话、搜索判断、逐题讲解和研究报告。默认每账号每日20000、全站每日100000 token，并发分别为1和4；调用前按输入字符及最大输出预留，用供应商实际输入和总输出（含思考）结算。完整研究可能超过默认账号预留额度，部署时需明确设置 `YANTU_MODEL_USER_DAILY_TOKENS` 和 `YANTU_MODEL_DAILY_TOKENS`，不能为报告静默绕过预算。搜索独立计量；研究、兼容接口、自由聊天共享注入的搜索预算，默认每账号每日10次、全站100次，可由 `YANTU_SEARCH_USER_DAILY_REQUESTS` 和 `YANTU_SEARCH_DAILY_REQUESTS` 配置。发送前预留次数，失败也计数，清空对话不退额度；仅当前进程共享，重启计数重置。

研究参数由 `YANTU_RESEARCH_MODEL`、`YANTU_RESEARCH_EFFORT`、`YANTU_RESEARCH_TIMEOUT_MS`、`YANTU_RESEARCH_MAX_OUTPUT_TOKENS` 提供，默认分别为 `deepseek-v4-pro`、`high`、`120000`、`12000`。模型只允许 Flash/Pro，强度只允许 low/high/max；超时最高 120000 毫秒，输出最高 16384 token。这些输出与超时配置只控制最终分析；方向规划固定非思考4096输出token/30秒。普通调用保持 Flash 非思考配置，研究失败不自动降级调用第二个模型。

相同用户、任务、作答或推荐依据、提示词与模型配置下的重复请求，可复用已经核验的结果。缓存必须按用户及完整依据版本隔离；答案、诊断、资料、提示词或模型配置变化后不能继续命中旧结果。供应商别名发生已知变更时重新验证并更新配置版本，不宣称可以固定无法获知的内部模型版本。私人解释缓存的清理属于文档 05 的删除范围。

`research-generation.ts` 通过同一 `ModelRuntime` 执行两个模型阶段：方向规划使用所选研究模型（默认Pro）非思考模式，4096输出token/30秒；最终报告默认Pro/high，12000输出token/120秒（输出配置最高16384）。每阶段仅在结构、引用或画像校验失败且已取得模型正文时最多修复一次，整份报告至多四次模型调用，全部预留和实耗计入共享预算。修复前再次检查取消与数据版本；传输、认证、额度、超时、输出截断及取消不自动重试，不更换模型。修复只携带原始画像、目录、证据与内部字段问题；接近上下文上限时可去掉上一份无效回答，不截断原始依据，仍超限则结束。问题路径不作为学生原始诊断展示。适配器本身不自动重试。超时不等于未计费，取消浏览器请求也不代表取消了供应商计算，计量未知时保留预留额度。额度不足或模型不可用时，旧解释可保留固定解析，研究报告明确 `partial/blocked`，测评提交、判分、资料查询和规则结论继续可用。预算、预留及最长 24 小时缓存目前属于单进程内存，重启不会保留日计数，多进程上线前需共享事务存储；个人数据删除会清私有缓存并使在途结果失效。

## 5. 模型专属密钥与配置

- 正式密钥由服务端从部署平台密钥管理或受保护环境读取，配置名建议为 `DEEPSEEK_API_KEY`。账户 ID 不作为模型 ID，也不写入任务正文。
- 真实密钥和账户信息不写进文档、代码、夹具、版本记录或报告；禁止通过 `VITE_` 变量、浏览器存储、URL、客户端请求体或模型提示词传递密钥。
- 本地配置只放受保护、被 Git 忽略的 `.env` 或部署密钥管理，`.env.*` 同样忽略，示例文件仅含占位符。开发、测试、正式环境使用独立凭据；忽略规则不能清除已提交的秘密。
- Adapter 仅连接已允许的官方 HTTPS 主机；不接受前端给定地址，不把认证头转发给重定向目标。不在错误页、测试输出或日志中输出密钥片段、认证头、环境变量清单或原始上游错误。
- 先前密钥曾出现在聊天中，建议由用户在控制台轮换。仓库扫描无法证明聊天或平台保留记录已经消失；本轮不自动撤销凭据或操作账号。新密钥应通过受保护配置提供。

会话鉴权、资源归属、日志脱敏、保存期限及删除流程不在本文重复定义，统一遵循文档 05。模型专属检查只验证上述限制及 Adapter 不向错误主机发送认证内容。
