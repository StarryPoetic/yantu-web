# DeepSeek 接入、模型路由与密钥管理

版本：V0.2 · 日期：2026-09-27 · 状态：草案待评审，含历史连通性记录

## 1. 职责与实施边界

本文是模型任务 Interface、DeepSeek Adapter、输出核验、费用限制及模型专属密钥管理的主文档。实体、ID 和版本以[02-数据模型与可信数据](02-数据模型与可信数据.md)为准；学生端与管理端 HTTP 契约以[04-接口与前端交互](04-接口与前端交互.md)为准；通用鉴权、个人资料删除、日志、备份与运维引用[05-安全运维与验证](05-安全运维与验证.md)。供应商决定及待定预算等事项集中在[08-变更与扩展约定](08-变更与扩展约定.md)，不在本文另建决策表。

按用户要求，DeepSeek 为首选，优先评估质量满足任务要求且成本较低的 Flash。题库、已审核答案、组卷、客观判分、资格筛选、排序与阈值判断由业务模块执行；模型只承担获准的补问、解释、题目草拟和报告整理。基础查询、测评与联合推荐不依赖模型可用性。

本轮仅整理文档，不变更配置、不接入网页、不扩充题库，也不重新调用外部接口。第 6 节保留已有的 2026-09-27 核验记录；它不代表本次重测、持续可用或业务质量通过。当前网页仍未连接 DeepSeek。

## 2. 模型模块的 Interface 与依赖方向

业务模块调用一个受控任务 Interface；对外暴露的是任务语义、获准证据、预算与结果状态，不要求调用方理解供应商请求参数。测评模块负责本人归属、已提交状态和题目适用性；推荐或报告模块负责固定规则结论与资料快照；模型模块负责输入裁剪、任务路由、输出检查、计量和降级。通用访问权限由文档 05 约束。

依赖方向为“业务模块 → 模型模块 → DeepSeek Adapter → 官方服务”。Adapter 只处理供应商协议、模式参数、响应解析及受控重试，不直接查询业务表，也不能修改题库、发布事实或回写排序。业务模块不依赖供应商 SDK；浏览器不能直连供应商或指定任意提示词、模型、密钥和请求地址。

| Interface 约定 | 调用方与模型模块的责任 |
| --- | --- |
| 任务输入 | 使用已批准的任务类型和相关记录引用；由服务端加载本次获准的证据及确定性结论，不接收客户端自报的判分或资格结论。仅发送当前任务必要的数据。 |
| 版本与依据 | 固定资料、作答、题库或推荐结果依据，同时标识提示词与任务配置版本；实体引用结构遵循文档 02。模型说明不得悄悄换用最新数据。 |
| 成功结果 | 返回经核验的解释、证据引用、不确定性及允许的后续建议。不同任务的结构分别校验；测评错误假设结构不能强套到推荐说明或题目草稿。 |
| 可降级结果 | 无可用证据、额度不足、超时、限流、响应不完整、结构错误或引用核验失败时，返回固定解析/规则说明及可识别的降级原因；不返回未经检查的半成品。 |
| 持久化 | 业务模块决定保存获准的解释或草稿，模型模块不更新业务事实。缓存只是可清除的派生结果，不是评分、排序或题库的事实来源。 |

获准启用模型时，仅实现已确认任务需要的 DeepSeek Adapter，并以固定模拟响应验证失败路径。尚无第二家业务供应商时，不建设动态插件注册、通用多模型编排或任意工具执行框架；未来确有差异时按文档 08 评审扩展。

## 3. 任务路由与输出核验

| 任务 | 默认处理 | 输入与结果限制 |
| --- | --- | --- |
| 按科目、范围、知识点和难度组卷 | 测评模块规则，不调用模型 | 题库不足按文档 06 返回覆盖不足，不生成题目补齐。 |
| 客观题判分、未答统计 | 服务端审核答案及判分规则，不调用模型 | 模型不能改变题目答案或最终评分；数学表达式判等若需支持，另行设计规则。 |
| 已提交错题讲解、测评总结、推荐理由改写、报告整理 | Flash，默认关闭思考模式 | 使用任务必需的审核依据和授权作答；短输出，不传整个题库或完整画像；保持固定评分、排序和事实。 |
| 多步解题过程分析、复杂数学草稿辅助审核 | Flash；仅在验证与预算允许时启用思考模式 | 使用 Adapter 当时已验证支持的模式参数；先比较独立验证集效果与成本。输出是错误假设或审核线索，不能自动改答案。 |
| 批量题目草拟与标签建议 | 后续获准的后台离线批次，限量使用 Flash | 进入草稿区，经答案唯一性、公式、解析、干扰项和适用范围审核后才可发布。 |
| Flash 无法可靠完成的任务 | 固定解释、人工复核或证据不足 | 不因失败重试自动切换高价模型。更高价模型须先评审质量收益、任务范围和预算。 |

测评解释必须引用该用户已提交尝试中的题目和作答；错误原因只能作为假设，缺少过程时说明无法区分的原因。服务端核验引用归属、允许标签和与审核答案的一致性；不能稳定核验则展示固定解析。未提交题的答案、解析或其他用户作答不能通过辅助任务泄露。

推荐与报告改写仅依据已固定的推荐结果、事实和来源，不增添新的学校事实、就业数据、风险结论或录取概率。题目草拟即使结构完整，也不等于通过学科审核。所有外部材料与用户文本作为任务数据，不能改变系统指令、任务类型或发布权限。

首版不需要模型主动查询数据库。模型可提出允许的补测标签，后续查询由测评模块执行。只有具体任务评审证明有必要时才增加受限工具，逐项定义可查询范围和返回内容；不得开放任意 SQL、网络 URL 或直接发布能力。

## 4. 成本、缓存与失败控制

Flash 的性价比由人工审核一致性、诊断证据一致性、时延和每任务费用共同衡量，不能凭名称认定适合所有数学任务。初始建议为普通解释约 5,000 输入 token 内、最多 800 输出 token、30 秒总超时；复杂草稿任务使用独立预算。上述数值待评审和压测，不把供应商最大上下文或最大输出当默认额度。

每用户与全站分别限制日额度和并发；任务开始前检查额度，完成后记录实际用量并处理并发预留，避免同时通过检查造成超额。记录任务类型、模型标识、配置/提示词版本、token 数、时延、状态和费用估算；原始输入输出的保存与删除遵循文档 05 及文档 08 的决定。

相同用户、任务、作答或推荐依据、提示词与模型配置下的重复请求，可复用已经核验的结果。缓存必须按用户及完整依据版本隔离；答案、诊断、资料、提示词或模型配置变化后不能继续命中旧结果。供应商别名发生已知变更时重新验证并更新配置版本，不宣称可以固定无法获知的内部模型版本。私人解释缓存的清理属于文档 05 的删除范围。

只对明确可重试的限流或服务错误进行有次数和总时间上限的退避；输入错误、鉴权失败、内容核验失败不作盲目重试。超时不等于未计费，取消浏览器请求也不代表取消了供应商计算；计量状态不明时单独记录，不无限重试。额度不足、模型不可用或核验失败时返回固定解析与规则结论，测评提交、判分、资料查询和基础推荐继续可用。

## 5. 模型专属密钥与配置

- 正式密钥由服务端从部署平台密钥管理或受保护环境读取，配置名建议为 `DEEPSEEK_API_KEY`。账户 ID 不作为模型 ID，也不写入任务正文。
- 真实密钥和账户信息不写进文档、代码、夹具、版本记录或报告；禁止通过 `VITE_` 变量、浏览器存储、URL、客户端请求体或模型提示词传递密钥。
- 本地调试使用系统密钥管理或无回显输入。后续实施须忽略 `.env` 和 `.env.*`，示例文件仅含占位符；本轮不修改忽略配置。开发、测试、正式环境使用独立凭据，忽略规则不能清除已提交的秘密。
- Adapter 仅连接已允许的官方 HTTPS 主机；不接受前端给定地址，不把认证头转发给重定向目标。不在错误页、测试输出或日志中输出密钥片段、认证头、环境变量清单或原始上游错误。
- 先前密钥曾出现在聊天中，建议由用户在控制台轮换。仓库扫描无法证明聊天或平台保留记录已经消失；本轮不自动撤销凭据或操作账号。新密钥应通过受保护配置提供。

会话鉴权、资源归属、日志脱敏、保存期限及删除流程不在本文重复定义，统一遵循文档 05。模型专属检查只验证上述限制及 Adapter 不向错误主机发送认证内容。

## 7. 专项验证与启用门槛

| 验证范围 | 必须验证的内容 |
| --- | --- |
| Interface 与 Adapter | 业务模块只通过获准任务调用；未知任务/模式拒绝；响应完整结束、结构可解析、引用与允许标签正确；供应商错误转为固定类型。 |
| 解释质量 | 覆盖答对、答错、未答、猜测、步骤与选项冲突、信息不足；允许输入审核答案来验证讲解忠实度，但不得改变规则评分或断言“粗心”。 |
| 独立能力与诊断效度 | 使用隔离的验证题和作答轨迹，由人工保存标准答案与预期结论；检验独立求解或诊断能力时，不将待验证答案和预期结论放进生成提示词。与提供答案的解释质量测试分别报告。 |
| 题目与事实安全 | 未提交题无泄题通道；草稿不能发布；已提交解释使用当次版本；推荐与报告不能新增无依据事实；诱导文本不能改变任务权限。 |
| 费用与失败 | 错误密钥、额度不足、限流、超时、重定向、不完整输出及引用失败均可降级；不会自动升级高价模型；重复请求复用规则、并发额度与计量不明状态可验证。 |
| 通用保护 | 按文档 05 验证数据隔离、删除与缓存清除、错误脱敏、构建产物与日志不含秘密；不重复另立一套标准。 |

供应商优先级已经明确，具体任务启用、日预算、复杂任务模式、传输范围和保留期仍需依文档 08 完成决定。通过任务质量、费用、失败路径及受保护配置的环境验收后，才能把相应能力标记为已接入；历史连通成功不能替代这些门槛。
