# DeepSeek 接入、模型路由与密钥管理

> 实施状态（2026-10-03）：本版同步完整画像驱动的两阶段校专业研究与独立年度证据状态。实际实现、历史连通记录及质量验收边界见[实施说明](../实施说明.md)；内容建设与运行门槛不因代码完成而自动通过。

版本：V0.7 · 日期：2026-10-11 · 状态：文档修订，保留历史独立连通检查记录

本版新增院校资料三层架构与收集可靠性方案（2026-10-11）。阶段0只修订文档与测试；新增模块、读取策略和覆盖契约须在后续阶段实现并验收，现行预算保持不变。

## 1. 职责与实施边界

本文是模型任务 Interface、DeepSeek Adapter、输出核验、费用限制及模型专属密钥管理的主文档。实体、ID 和版本以[02-数据模型与可信数据](02-数据模型与可信数据.md)为准；学生端与管理端 HTTP 契约以[04-接口与前端交互](04-接口与前端交互.md)为准；通用鉴权、个人资料删除、日志、备份与运维引用[05-安全运维与验证](05-安全运维与验证.md)。供应商决定及待定预算等事项集中在[08-变更与扩展约定](08-变更与扩展约定.md)，不在本文另建决策表。

按用户要求，DeepSeek 为首选。普通对话与解释使用 Flash；独立联网研究报告默认显式选择 Pro 的 high 思考模式，按本次画像、测评与真实检索资料进行分析。题库、已审核答案、组卷、客观判分、资格筛选、正式排序与阈值判断由业务模块执行；报告中的模型建议不会改写这些结果或替用户确认专业。基础查询、测评与规则专业结论不依赖模型可用性。

代码已包含服务端模型、安全网页检索与独立研究任务，启用依赖部署配置。第6节区分真实连通、保留证据再分析与自动化回归；普通自动测试使用模拟响应，不能代表持续可用或模型业务质量通过。

## 2. 模型模块的 Interface 与依赖方向

业务模块调用一个受控任务 Interface；对外暴露的是任务语义、获准证据、预算与结果状态，不要求调用方理解供应商请求参数。测评模块负责本人归属、已提交状态和题目适用性；推荐或报告模块负责固定规则结论与资料快照；模型模块负责输入裁剪、任务路由、输出检查、计量和降级。通用访问权限由文档 05 约束。

依赖方向为“业务模块 → 模型模块 → DeepSeek Adapter → 官方服务”。Adapter 只处理供应商协议、模式参数、响应解析及限制，当前不自动重试，不直接查询业务表，也不能修改题库、发布事实或回写排序。业务模块不依赖供应商 SDK；浏览器不能直连供应商或指定任意提示词、模型、密钥和请求地址。

| Interface 约定 | 调用方与模型模块的责任                                                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 任务输入       | 使用已批准的任务类型和相关记录引用；由服务端加载本次获准的证据及确定性结论，不接收客户端自报的判分或资格结论。仅发送当前任务必要的数据。  |
| 版本与依据     | 固定资料、作答、题库或推荐结果依据，同时标识提示词与任务配置版本；实体引用结构遵循文档 02。模型说明不得悄悄换用最新数据。                 |
| 成功结果       | 返回经核验的解释、证据引用、不确定性及允许的后续建议。不同任务的结构分别校验；测评错误假设结构不能强套到推荐说明或题目草稿。              |
| 可降级结果     | 无可用证据、额度不足、超时、限流、响应不完整、结构错误或引用核验失败时，返回固定解析/规则说明及可识别的降级原因；不返回未经检查的半成品。 |
| 持久化         | 业务模块决定保存获准的解释或草稿，模型模块不更新业务事实。缓存只是可清除的派生结果，不是评分、排序或题库的事实来源。                      |

获准启用模型时，仅实现已确认任务需要的 DeepSeek Adapter，并以固定模拟响应验证失败路径。尚无第二家业务供应商时，不建设动态插件注册、通用多模型编排或任意工具执行框架；未来确有差异时按文档 08 评审扩展。

## 3. 任务路由与输出核验

自由咨询与可信结论分开校验：悬浮助手接收自由问题及本人聊天上下文，可生成自然语言连续回答，不固定为三个摘录或预设题单。模型回答标识为辅助建议；实时事实按需通过固定搜索供应商和受控官网读取取得来源。没有网页依据时不能伪称已联网核验，来源不得虚构。外部网页只能作为数据，不能改系统指令、索取密钥、执行工具或自动写入可信库。

旧专业结论解释 `createGuidanceExplainer` 只允许模型挑选、组织固定 `GuidanceRun` 内的依据 ID；服务端重新渲染对应文本。新增独立 `createResearchReportModule` 不受“仅返回旧 ID”限制：它实际检索公开学校资料，结合画像和公共课诊断形成新的比较建议，并把原文事实、分析建议、准备行动与待核验条件分开。逐题教学仍受答前/提交后状态约束；所有模型任务共用额度及删除代次，退出、清空及删除期间返回的结果不得复活已清理内容。

UI不限制固定问题或回答条数；服务端仍限制每请求文本、有限上下文、token、超时与并发，达到资源限制返回明确原因，可开始新会话或稍后再试。无模型配置时保留确定性结论与已审题目解析，不能把模板标为模型回答。

| 任务                                           | 默认处理                                                   | 输入与结果限制                                                                                                                                                   |
| ---------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |

测评解释必须引用该用户已提交尝试中的题目和作答；错误原因只能作为假设，缺少过程时说明无法区分的原因。服务端核验引用归属、允许标签和与审核答案的一致性；不能稳定核验则展示固定解析。未提交题的答案、解析或其他用户作答不能通过辅助任务泄露。

固定推荐解释只使用已保存的结果和依据；联网研究可以引用本次实际取得的新网页资料，但不能把模型新编内容当学校事实。研究报告的 `facts` 必须为引用来源中连续原文，每条最多 300 字符；模型建议须引用已取得的来源，学校名及对应专业要能在同一来源中找到，代码限于本次规划方向或已读官网正文实际出现的代码/专业名，并须属于当前画像硬约束筛选后的allowed全国目录；官网发现的新专业不能仅因未在初始规划中而拒绝，仍需同校具体硕士专业的真实证据，URL 只取实际来源。无据数字费用、分数、概率和明确资格断言会被拒绝；这些检查仍不能证明所有自然语言推论正确。题目草拟即使结构完整，也不等于通过学科审核。所有外部材料与用户文本作为任务数据，不能改变系统指令、任务类型或发布权限。

适合度建议与目标年度资格核验独立。历史、年度不明或混合年度官网若明确支持学校与具体专业关联，可保留条件性建议，并由服务端标记 `admissionStatus:needs_verification`；不得把旧资格、学费、名额或分数当成本年事实。`current_evidence` 必须有目标年度学校正文及招生语境，搜索标题、读取时间和版权年份不能替代，且该状态不等于 eligible。明确示例/测试资料、停招或没有校专业关联依据的建议仍拒绝。学校名称含“示例”不单独触发示例资料判断；专业否定语境保守处理，不承诺全面语义识别。否定性的“无法预测录取概率”“不保证录取”可通过，肯定保录与具体概率仍拒绝。

校专业关联须支持具体硕士专业及对应目录代码，不能拿本科专业介绍或博士招生内容证明硕士项目。目标年度官方背景限制与用户明确冲突时剔除该项；历史条件只作风险提示。无费用证据不得判定超预算，改为待核验事项。核心学校身份、具体硕士专业、引用及综合理由必须通过；匹配理由、准备行动、取舍和待核验条目按项校验，局部无据条目移除后，仍须至少两个有效且不同的真实画像维度和至少一项有效取舍，否则整项建议剔除。不合格卡片或总述不清空其他合格建议，报告标为partial并说明删减。院系名只能由该卡引用的学校官网支持，具体三位考试代码须有该卡目标年度官方依据；未取得资料不等于学校尚未发布。结构通过仍不替代人工语义核验。

研究先用完整184条全国基础目录及画像进行方向规划，不从本科专业或旧高亮类别预先锁定范围。画像覆盖兴趣、职业目标、城市、预算、跨专业意愿、学位偏好、七项优先级、可投入时间、课程和备考基础、补充说明及适用诊断。未知不臆测，明确拒绝保留。规划、检索、报告与有界修复共用同一runtime和搜索预算。应用默认博查，`YANTU_SEARCH_PROVIDER=bocha` 只读 `BOCHA_API_KEY`，显式brave才读 `BRAVE_SEARCH_API_KEY`，不自动换供应商或转发密钥；配置见[本地指南](../本地模型与联网测试.md)。

完整画像及原始补充只送模型，不原样进入公开搜索词；本科院校只作自述教育背景，不推断学校层次、歧视风险或录取概率，也不作为公开查询中的个人信息。搜索词仅使用目标年度、规划后的公开专业方向、用户城市偏好及可选目标学校，不发送姓名、本科院校或原始notes。网页只读取服务端精确允许的主机，默认也允许真实搜索结果中的 `.edu.cn` 高校域名；`allowAcademicHosts:false` 可关闭，客户端不能扩展。普通咨询与用户自填网址仍只用 HTTPS、不跟随跳转；研究流程显式设置 `maxRedirects:3`、`allowHttp:true`，只对 `.edu.cn` 放行明文HTTP。同校跳转限同一学校注册域名最多3次，每跳重新做全部DNS公网校验并固定连接IP，HTTPS保留TLS主机校验；跨校跳转拒绝，私网、IP直连、凭据、显式端口、大小与时间上限继续拦截。研究全部读取执行全DNS公网校验、连接IP固定及HTTPS的TLS主机验证；研究HTML/文本下载上限8秒及512000字节，PDF另按下述独立限制；搜索响应上限100000字节，供应商业务失败不会标记成功。其他结果仅保留摘要；所有来源保持 `verified:false`，不自动进入正式资料库。

研究内部可传 `options.search:{includeDomains?:string[],count?:number}`，普通问答默认五条，研究最多十条；域名最多十个，只接受具体根域或子域。博查用原生 `include`，Brave由适配器转换成 `site:`，响应再按域名边界过滤；该参数不来自HTTP请求，也不扩展网页读取权限。官方[请求体文档](https://bocha-ai.feishu.cn/wiki/RXEOw02rFiwzGSkd9mUcqoeAnNK#Jnksd9YtNoMoNjxgK1wchorBncc)确认根/子域的include参数，但未明确承诺site语法或公共后缀edu.cn匹配，不能据此宣称硬过滤有效。接口保持总搜索预算，不做无界重试。

研究内部可显式传 `options.upgradeAcademicHttp:true`，仅在 `sourcesOnly:true` 时保留实际搜索结果中的 `http://*.edu.cn` 原始地址作为读取候选；该历史选项名现在表示允许保留教育网HTTP链接。`WebSource.retrievalNote` 记录待核验线索说明。普通聊天与用户直接提供的URL不启用，客户端不能传此内部选项；凭据、显式端口（包括80）、IP、非教育网域名和歧义URL拒绝。研究会按原始HTTP地址读取，允许同校升级到HTTPS；搜索摘要仍不是官网正文。明文成功读取保存 `transport:"http"`，并展示“明文传输（HTTP）读取，内容可能被网络中间环节篡改，仅作待核验线索”。原始url继续保留，有跳转另存finalUrl；资料库复用与报告导出保留传输方式及提示。

研究最多规划3个方向，每方向提供4–6个不同学校的 `searchSchools`，仅为检索线索。`research-search.ts` 跨方向轮流发现学校、轮换校名与城市，优先“校名＋专业＋硕士”，已有院校资料后扩展第二所学校；从已观察主机提取最多两个具体学校根域，以 `includeDomains` 补查，不能编域名。整个报告最多24次搜索及24次正文读取：先用最多18次搜索与16次读取建立项目证据，保留40条搜索候选及最多12条同校PDF附件候选；生成核验后，按实际推荐学校补查最多6次搜索、8次读取，新增最多8项官网费用正文。初期每学校根域最多4次读取，费用阶段累计不超过6次；所有读取共享总预算。若有明确意向城市且前16次读取未取得其硕士项目与所在地线索，可从费用保留槽位借用最多4次读取，初期最多20次；仅补查已观察的优先学校，单校4次上限不变，费用阶段只使用剩余额度，总计仍最多24次正文读取。相同查询/域名组合不重复；成功搜索结果和公开学校正文在15分钟内复用，失败不缓存，不做无界重试。公开缓存不含个人画像、模型规划或个性化报告；来源保留原检索时间，不把缓存命中伪装为新抓取。只有实际学校官网原文进入最终模型，最多24项，压缩后整个输入不超过24000字符；摘要可用于发现与展示缺口，不能升级为正文。

当前v7以5–10所不同学校为资料库加检索的覆盖目标，每校一个主推荐专业。服务端 `demand-match-v1` 固定规则分层，模型只提供解释，不能改变层级；模型的 `suitabilityTier/suitabilityReason` 不参与排序。方向关联、培养路线及已核验城市决定优先比较，有城市偏好时城市未知不满足优先比较条件。费用只是一个因素，同费用学校可以不同层；预算/城市通过constraintChecks逐项展示，与综合分层独立，未知不能默认合格。

历史v6以5–10所不同学校为目标，每校保留一个主推荐专业。按完整画像综合分为 `preferred`（第一级·优先推荐）、`alternative`（第二级·适合备选）和 `exploratory`（第三级·探索选择）。模型给出 `suitabilityTier` 与 `suitabilityReason`，综合职业目标、兴趣、基础、跨专业准备成本、时间、城市及预算，服务端核验理由后保存 `tier/tierReasons`；无可靠分层理由暂列探索，不默认优先。费用只是一个因素，同费用学校可以不同层，较贵但其他方面高度契合也可优先，须明确费用缺口；未知费用或城市不自动升降层。预算/城市分别通过 `constraintChecks` 标明 `match/mismatch/unknown`，与综合分层独立，未知不能当成满足；优先推荐不等于录取率、录取保证或报考合格。明确不跨专业、已排除方向、停招及目标年度资格硬冲突不能通过备选层放宽。不足5所时保留真实卡片并返回partial，`coverage` 展示已覆盖学校数、分层数量及具体缺口，不宣称全国无校、不按同校多专业凑数量。

意向城市单独验收：单个城市按方向循环使用，不因方向序号丢失；学校域名须来自实际学校主体标识，不能把其他学校页面中提及的导师母校当域名归属。同校不同专业保留检索机会，读页优先补齐本地项目。模型省略location时，仅从引用官网的唯一同校地址或明确同校同项目培养地址恢复，不用摘要、合作单位地址、多校区冲突或学校名称猜测城市。正向城市声明必须与核验结果一致，不能把上海说成符合杭州偏好，也不能擅自认定用户接受长三角通勤。同一综合推荐层级内，已核验符合意向城市的学校优先；不降低资格、专业关联或证据门槛凑本地学校。

`coverage` 可增加 `preferredCities`、`preferredCitySchoolCount`、`unknownCitySchoolCount`；城市未知不计入匹配。已有5校但城市匹配为0，仍为partial并显示意向城市缺口；无其他校验失败时使用 `PREFERRED_CITY_COVERAGE_INCOMPLETE`，其他失败码保留且同时展示城市缺口。有实际本地硕士项目与地址线索时，可与原数量补充共用最多一次覆盖分析，不增加模型请求上限；保留已有建议，但同校可换成有据本地项目，10校已满时可用首个有据本地候选替换末位外地项，摘要同步更新。未取得城市证据时不会为凑数量虚构校区，也不宣称杭州没有适合的学校。历史报告保留原内容，需重新生成才使用本轮规则。

学费只通过 `tuition` 结构化证据表达：amount、CNY、period（academic_year/program/semester/credit）、year、studyMode（full_time/part_time/unspecified）、连续原文quote和sourceId。必须来自该校所引官网，绑定具体项目、明确年度、学习形式、计费单位及唯一费用金额；学校一般收费、别的专业或非全日制费用不能套用。历史费用可保留参考，历史、全程/学期/学分费用或未知学习形式均不能直接与用户年度预算比较，不按学制擅自年化。城市需所引官网的实际培养校区地址原文 `location`，不凭学校名称猜所在地。条件检查由 `research-constraints.ts` 负责，模型不能以自报结果代替constraintChecks；综合分层理由另经报告模块校验，不由单一费用或城市检查决定。

`YANTU_DNS_MODE` 默认 `system`；代理以虚拟IP替代公网DNS答案时可显式使用 `public-doh`。`server/explanation/dns.ts` 只访问固定阿里云 HTTPS DNS 端点，查询A与AAAA，校验问题主机/类型及有限CNAME链，限制5秒与每响应32768字节，不接受客户端配置端点、重定向或静默回退。解析结果继续逐项做公网校验，再固定连接地址；DNS请求只含目标主机名，不携带搜索词、画像或供应商凭据。公网教育网IPv6不能因`2001`前缀被一律误判：按[IANA特殊用途登记](https://www.iana.org/assignments/iana-ipv6-special-registry)拒绝保留/隧道/文档地址，允许普通全球单播地址；混合答案含任意非公网地址仍整次拒绝。

`research-evidence.ts` 将停招与本科限制绑定到具体专业的代码/句段，不能因目录中相邻专业停招或限招而排除当前专业；归属不清时保持待核验，明确学校整体停招仍拒绝。压缩长正文时保留实际学校标识、具体专业代码和邻近原文，不能用搜索标题补造校名。专业关联仍须通过官网正文核对，历史条件与目标年度条件分别处理。

招生PDF仅由研究显式设置 `WebReader.allowPdf:true` 与 `maxPdfBytes:5000000`，普通问答默认false，前端不能自选。受控下载遵守上述研究HTTP及同校有限跳转边界，公网校验与HTTPS的TLS规则不变：仅PDF下载及解析输入上限5000000字节；HTML、JSON和普通文本仍为研究512000字节、reader全局1000000字节硬上限。研究下载8秒、reader全局10秒，响应必须同时匹配 `application/pdf` 与 `%PDF` 文件头。`pdf-text.ts` / `pdf-text-worker.ts` 使用 `pdf-parse@2.4.5` 在独立隐藏Node子进程提取纯文本，最多5秒、80页、120000字符；任何超限整项拒绝，不截取后声称完整。扫描件不做OCR，可能返回无文本。

解析子进程固定启动参数，旧生代128MB、新生代16MB，环境仅保留必要SystemRoot，不继承密钥、`.env` 或 `NODE_OPTIONS`；只接收已下载字节与限制。关闭PDF内JS求值、外联fetch、XFA及渲染，字体/CMap取自安装依赖本地文件，超时终止进程。这是解析隔离与资源限制，不代表完整操作系统沙箱。`WEB_PDF_INVALID`、`WEB_PDF_TIMEOUT`、`WEB_PDF_TOO_MANY_PAGES`、`WEB_PDF_TEXT_TOO_LARGE`、`WEB_PDF_EMPTY` 均保留原搜索摘要并记录读取失败，不把摘要升级为正文；证据不足返回partial。下载与解析各自计时，不能将8秒下载上限宣传为含解析的端到端时间保证。

`generate({subjectId,run,selectedProgram?,onProgress?})` 返回结构化 `ResearchReport`；`getReadiness()` 仅检查本地配置，不调用付费服务。新报告为 `reportVersion:profile-research-v7`，保留研究方向及补问，兼容旧版 `profile-research-v6` 及v3–v5；`failureStage` 可选值为 `preparing/researching/analyzing/writing`，表示失败发生的真实阶段；阶段失败、模型输出校验失败和用户信息不足分别解释。已保存画像充分但模型格式错误时，不提示用户必须先选学校或重新填写画像；只有实际画像不足或有效规划中的明确追问才请求补充。新建议包含具体 `programName`、目录派生 `degreeType`、至少两个不同真实画像字段的 `fitReasons`、`tradeoffs` 与服务端计算的 `admissionStatus`，契约见02。无配置、无规划方向或无真实来源为 `blocked`；只有摘要、缺少校专业官网依据、额度不足、超时或输出校验失败为 `partial`。`completed` 表示本次适合建议流程完成，可以同时含年度待核验建议，不代表全国覆盖或资格通过。未通过校验的内容不展示，已有来源可保留。

现行v7及兼容v6的规划与最终报告均以字段引用生成匹配理由：模型输出 `profileField` 与 `reason`，服务端从本次已保存画像快照补入 `profileValue`。提供给模型的 `profileEvidence` 只列当前可用字段，排除空值、不确定项、已清空notes和默认中性优先级50；多个优先级仍只算一个维度。旧格式显式提供 `profileValue` 时继续严格核验当前原值，数值优先级与城市数组只按实际字段类型规范化，不能借规范化改写偏好、增加城市或恢复旧备注。单条可选理由不合格时隔离该条；仍有至少两个不同真实画像维度且不只包含本科背景时保留方向或建议，不足时汇总字段问题供一次有界修复。字段绑定不意味着自由文本理由的所有推断都已获事实证明。

任务路由在 `POST /guidance/:id/research` 创建作业，使用 `GET /research-jobs/:id` 及 `GET /guidance/:id/research/latest` 查询、恢复状态。模型模块按实际工作等待 `preparing → researching → analyzing → writing` 回调，不做假计时增长或伪造流式 token 百分比；没有网页依据时在进入分析阶段前结束。每次回调可检查会话、画像、专业选择和资料版本，检查失败直接取消结果交付，不吞成模型降级。路由还负责排队、失败、取消、重启后的中断标记及报告持久化。

首版不需要模型主动查询数据库。模型可提出允许的补测标签，后续查询由测评模块执行。只有具体任务评审证明有必要时才增加受限工具，逐项定义可查询范围和返回内容；不得开放任意 SQL、网络 URL 或直接发布能力。

模型与网页读取共用服务端 `YANTU_DNS_MODE` 配置。`system` 保留原生fetch；`public-doh` 时 `deepseek-transport.ts` 只向固定 `api.deepseek.com` 的允许路径POST，复用固定阿里HTTPS DoH和 `public-address.ts` 全公网校验，优先已验证IPv4并以lookup固定IP；保持SNI、`rejectUnauthorized:true`、禁止重定向和原AbortSignal，不回退、不重试、不转发凭据给DNS。响应以受取消保护的按需流桥接交给同一JSON/SSE解析器。模型请求体最多98304字节，以容纳合法24000字符中文输入，不提高模型字符上限。DoH服务自身仍可能受系统解析或外部网络影响，未硬编码未经证实的bootstrapIP，不保证持续连通。

### 3.1. 研究读取策略（V0.7）

以下是用户已确认、在阶段1实施的研究专用策略（D-15、T-26）。阶段1已实现研究HTTP及同校有限跳转；本阶段不改变18次搜索、16次读取、24次总搜索/读取和40条搜索候选等预算。

- 同校跳转只允许同一学校注册域名内最多3次，每跳重新做全DNS公网校验并固定连接IP；跨校跳转、私网、IP直连、凭据与不允许端口继续拒绝，HTTPS跳转继续校验TLS主机。
- `.edu.cn` 明文 HTTP仅限研究流程，来源保存实际 `WebSource.transport:'http'` 并展示“明文传输”；普通咨询与用户自填网址仍只用 HTTPS、不跟随跳转。
- 编码识别结合响应声明、页面声明与受控回退，支持UTF-8、GBK/GB18030；非法或无法可靠解码时保留失败原因，不把乱码当专业事实。
- gzip/deflate/br只作受限解压，压缩输入与解压输出均有大小上限，下载/解压均受时间和取消限制；超限整项拒绝，不截取后声称完整，PDF及工作簿解析限制仍保留。
- 细分读取失败码至少区分DNS、连接、超时、HTTP状态、跳转越界、编码、压缩和大小超限；保存固定安全错误码及尝试时间，不保存原始错误详情、响应中的秘密或个人信息。

三层资料流程为正式目录（人工审核发布）→独立公共院校资料库（原文与ProgramFact，始终 `verified:false`）→实时检索补缺。研究先查公共院校资料库，再按具体专业字段补查；从全国种子取得已核验网址线索，以学校注册域名设置 `includeDomains`，结果仍做域名边界过滤，不能通过查询参数扩展读取权限。

研招网 `yz.chsi.com.cn` 作为明确允许的官方平台证据参与读取和引用，须核验招生单位、具体专业、年度与原文归属，不能当成某学校的域名或任意跨校跳转授权。公共资料库、预抓取和平台证据见T-29；并发读取、新预算、结构化事实作为模型输入及额度核算在阶段5实现并通过T-30。

阶段2将无据单句校验改为只删除该句，不能因“符合城市偏好”无依据就整条作废有官网支持的推荐。初试科目/学费/校区由确定性规则按完整专业身份绑定，归属不清展示原文待确认；下属学院归一到招生单位，validationIssues、被拒原因与读取尝试落盘。核心校专业身份、引用及必要画像维度门槛不放宽；T-27。

## 4. 成本、缓存与失败控制

模型任务质量由人工审核一致性、诊断证据一致性、时延和每任务费用共同衡量，不能凭 Flash 或 Pro 名称保证效果。普通解释最多800输出token，搜索判断400，自由聊天及逐题追问2000，非思考请求最多30秒。研究方向规划采用同一所选模型非思考4096输出token/30秒，最终报告默认16384输出token（含思考）/120秒，两阶段及各自最多一次校验修复共享同一日预算。服务端输出参数范围1–16384；JSON输入字符上限为非思考16000、思考24000，非流式响应字节上限65536，思考流式响应另设分层上限，不使用供应商最大上下文作为默认额度。

研究思考请求使用 `stream:true` 与 `stream_options.include_usage:true`，非思考请求保持非流式JSON。`deepseek.ts` 在服务端增量解析SSE，只累计最终 `delta.content`，不累计、展示或记录 `reasoning_content`；支持字节/中文分片、多行data、CR/LF及独立或随stop返回的用量。必须取得 `[DONE]`、`finish_reason:stop`、匹配模型和完整usage，拒绝工具调用、截断、未知用量及异常结构；完整completion_tokens包含思考。总超时仍最多120秒、全部SSE响应（含思考和协议帧）最多8388608字节（8MiB），单事件或未结束行最多65536字节（64KiB），最终content累计最多131072字节（128KiB），心跳不延长截止时间，DONE后取消剩余连接。失败仍保留预留额度，不因网络结局不明自动重试。依据[DeepSeek流式接口](https://api-docs.deepseek.com/api/create-chat-completion/)与[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。流式传输可减少长时间静默等待，不保证解决DNS或连接故障。

应用默认每账号每日100000、全站300000模型token，并发分别1和4；直接创建 `ModelRuntime` 而不注入应用配置时仍有每账号20000、全站100000的保守默认值。调用前按输入字符和最大输出预留，实际输入及总输出（含思考）结算。研究、解释、咨询和修复共用账本，不能绕过额度；搜索另由共享 `createSearchBudget` 计量，应用默认每账号每日60次、全站300次，发送前计数且失败不退还。环境变量为 `YANTU_MODEL_USER_DAILY_TOKENS`、`YANTU_MODEL_DAILY_TOKENS`、`YANTU_SEARCH_USER_DAILY_REQUESTS`、`YANTU_SEARCH_DAILY_REQUESTS`；搜索次数不等于报告份数。这些数值是应用本地token上限，不是供应商账户余额或充值。账本是单进程内存、重启重置，不构成长久或跨实例账单硬上限。

研究参数由 `YANTU_RESEARCH_MODEL`、`YANTU_RESEARCH_EFFORT`、`YANTU_RESEARCH_TIMEOUT_MS`、`YANTU_RESEARCH_MAX_OUTPUT_TOKENS` 提供，默认分别为 `deepseek-v4-pro`、`high`、`120000`、`16384`。最终报告采用Pro/high，含思考输出最多16384token/120秒；方向规划使用同模型非思考4096token/30秒，保留184目录、仅裁剪长notes/courses以控制15000字符。模型只允许Flash/Pro，强度只允许low/high/max；不会因失败自动调用另一模型。

相同用户、任务、作答或推荐依据、提示词与模型配置下的重复请求，可复用已经核验的结果。缓存必须按用户及完整依据版本隔离；答案、诊断、资料、提示词或模型配置变化后不能继续命中旧结果。供应商别名发生已知变更时重新验证并更新配置版本，不宣称可以固定无法获知的内部模型版本。私人解释缓存的清理属于文档 05 的删除范围。

`research-generation.ts` 通过同一 `ModelRuntime` 运行规划与最终报告。每阶段结构、引用或画像校验失败且取得模型正文时最多修复一次；确认收到HTTP 500/502/503/504时，该阶段原始与修复调用共用最多一次临时重试，退避250毫秒后通过 `beforeRetry` 再查会话、画像版本和取消状态，并以新retry键重新预留同一额度。规划与初次报告每阶段最多3次模型请求；少于5校且已有至少5个学校官网根域和5个校名线索时，最多再用一次同账本分析补充遗漏候选，不修复、不重试，不超过10校且保留已有建议。整份报告最多7次模型请求，预算不足保留已有建议并说明原因；不是保证会调用到上限。适配器自身不重试，不切换模型或供应商。网络错误、超时、认证、余额不足、限流、输出截断和取消不自动重试。校验修复只携带原始画像、目录、证据与最多六条内部字段问题；近上限时去掉无效旧回答，不裁掉原始证据。未知上游用量保留预留额度，超时不等于免费。

错误原因按安全状态分类：400/422为 `PROVIDER_INVALID_REQUEST`，401/403为 `PROVIDER_AUTH_FAILED`，402为 `PROVIDER_BALANCE_INSUFFICIENT`，429为 `RATE_LIMITED`，500/502/503/504为 `PROVIDER_TEMPORARY_UNAVAILABLE`，连接失败/中断为 `PROVIDER_NETWORK_ERROR`，本地超时为 `MODEL_TIMEOUT`，成功HTTP但非法JSON/SSE为 `INVALID_RESPONSE`；响应超限为 `RESPONSE_TOO_LARGE`、非正常结束为 `INCOMPLETE_RESPONSE`、用量缺失或非法为 `UNKNOWN_USAGE`，均明确解释模型输出故障，无需修改画像。未归类HTTP保留 `PROVIDER_UNAVAILABLE`。页面解释基础设施原因，不要求用户重填画像；不读取或展示上游错误正文、认证头和密钥。分类依据见[DeepSeek错误码](https://api-docs.deepseek.com/quick_start/error_codes/)，502/504按临时网关错误处理。

预算、预留及最长24小时的私人模型缓存位于单进程内存。个人数据删除清除私有缓存并使在途结果失效；公开学校正文缓存与个人报告分别管理，不能用公开资料缓存恢复已删除个人结果。
