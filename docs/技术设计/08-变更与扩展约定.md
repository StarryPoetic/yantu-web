## 1. 本文职责

本文集中管理待决事项、扩展位置、兼容要求和变更流程。其他文档引用本表的决定，不再各自维护一份待定清单。文档评审、题库制作、程序开发和正式发布是不同阶段；本轮同时更新设计、实现与回归验证。新需求先更新设计和验收依据，再按用户明确的实施指令进入开发。

## 3. 允许扩展的位置

Module 表示负责一组完整行为的模块；Interface 包括输入、输出、状态约束、错误和性能限制；Seam 是替换行为的位置，Adapter 是满足该 Interface 的具体实现。只在确实存在变化的位置保留 Seam，不能为未知需求预造通用插件体系。

| 编号 | 变化需求 | 扩展位置与稳定约定 | 必须同步验证 |
| --- | --- | --- | --- |
| X-01 | 新增专业、学校、地区或招生年度 | 目录 Module 的资料导入/发布 Interface；新资料先变规范化草稿，保持完整项目身份与来源语义。 | 唯一键、历史映射、科目范围、资格规则、城市覆盖；不复制一套推荐流程。 |
| X-02 | 新增题目、题型、专业课或补测 | 测评 Module 的组卷/提交 Interface；配置区分范围与难度，新增题型必须提供对应评分与结果契约。 | 固定题集、五题初测基线、主观题评分依据、答案保护、旧版本兼容；后续补测独立尝试。 |
| X-03 | 更换模型或增加解释模式 | 使用 07 定义的受控任务 Interface 和供应商 Adapter；固定模板是既有降级实现，供应商字段只留在模块内部。 | 依据一致性、授权、隐私、费用、限额、缓存及失败降级；业务端不能直接拼供应商请求。 |
| X-04 | 增加账号、多设备同步 | 身份与画像 Module 的授权主体 Interface；业务记录统一归属 subjectId，账号绑定不改项目或题目 ID。 | 绑定证明、冲突合并、会话失效、越权隔离与删除范围；不能按相同姓名自动合并。 |
| X-05 | 新增推荐维度或排序方法 | 推荐 Module 的规则包与计算 Interface；保留资格筛选、证据状态、确定性回放及理由因子。 | D-04、权重/缺失策略、同分规则、版本差异解释；不得让模型改资格或标准答案。 |
| X-06 | 新增报告格式、部署规模或数据导入渠道 | 报告渲染与基础设施适配位置；领域模块仍读同一版本契约。仅出现具体需求后添加新 Adapter。 | 任务幂等、权限下载、跨版本读取、恢复与回滚；先证明瓶颈再拆独立进程/模块。 |

## 4. 兼容与版本约定

版本字段的唯一含义见[02](02-数据模型与可信数据.md)。新增可选响应字段可保持同一 schemaVersion；字段改义、删字段、状态或枚举变化、身份规则变化，必须评估旧调用方并制定兼容过渡或升级 schemaVersion。未知枚举必须进入明确的“不支持/待核验”状态，不能默认当成功或满足资格。

数据批次、题库和规则各自发布，不要求每次共同升级。发布清单记录新版本支持的结构版本和必要依赖；推荐记录固定所用目录、规则、画像、选择版本与 assessmentRefs[]。新目录生效后旧运行记录不可就地重算，只能标记依据更新并创建新的 recommendationRunId。隐私删除优先于个人快照保留，公共来源版本可以独立保留。

V0.4 新增兼容点：兴趣选择仍保存画像字符串，旧自由兴趣不因下拉限制而丢失；结构化 `stem` 与原题干文本保持语义对应，解释素材仅在交卷后下发；已提交测评颜色与单题导航只改呈现，不重判旧答案。独立目标接口写入既有 SelectionSnapshot，旧计划不再充当当前目标恢复来源。联网研究使用独立 ResearchJob/ResearchReport，不改写既有推荐报告；刷新只读持久任务，进程中断标失败且不自动重试付费请求。

回滚前检查旧程序是否能读取仍在使用的数据结构，以及被回滚的规则/目录是否已被撤回。不能回滚到已知失实或失效资料；无法满足兼容性时暂停受影响能力，保留安全查询与错误说明。不得通过删除审计记录掩盖回退。modelConfigVersion 固定供应商、模型别名、模式、参数及已知核验信息；请求 ID 属于逐次调用记录。别名不能被视为不可变模型权重。

## 5. 新内容的纳入流程

1. **归类与编号**：判断是既有需求澄清、参数调整、新能力还是外部事实更新。已有 R/U 编号不重排；新增编号及依据写入00。
2. **找主文档**：按00的责任表只在主文档定义规则，其他文档更新引用。新增文档必须有独立主题和已有文档容纳不了的理由。
3. **写影响说明**：列输入/输出、状态变化、受影响实体/版本、谁读写、权限与删除、错误/降级、费用和验收编号；无影响项写明理由，不留含糊“以后扩展”。
4. **检查依赖**：是否新增循环调用、跨模块直写、把数据库或供应商字段泄漏到前端；有则优先收回到所属 Module 的 Interface。
5. **兼容与迁移**：明确既有画像、作答、收藏、报告和缓存怎样处理，能否回滚，是否需要重新确认资料适用性。
6. **评审与验证**：给出正常/缺失/冲突/越权/降级/旧版本样例，更新05验收矩阵和文档校验。业务规则须人工审阅，格式测试不证明事实正确或诊断有效。
7. **记录变更**：版本说明、决定状态及对应 Git commit 一起保存。未通过影响评审的内容留在“拟议”，不得混入当前首版承诺。

变更记录模板：需求编号与依据；主文档；决定状态/责任角色；当前行为与拟改行为；输入输出/数据版本；错误和降级；权限、删除与成本；迁移回滚；验收编号；实施范围。填写模板不等于授权实施。
