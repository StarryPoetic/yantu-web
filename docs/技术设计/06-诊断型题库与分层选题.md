# 诊断型题库建设与分层选题要求

> 实施状态（2026-09-27）：本版同步兴趣选择、题干与交卷回顾、独立目标保存及联网研究报告需求。实际已实现能力、配置及上线验收边界见[实施说明](../实施说明.md)；未完成的内容建设与运营门槛不视为已交付。

版本：V0.4 · 日期：2026-09-27 · 状态：实施同步，正式题库持续建设

## 1. 职责与范围

本文是题目审校、分层组卷、测评状态及诊断限制的主文档。实体、ID 和版本字段以[02-数据模型与可信数据](02-数据模型与可信数据.md)为准；HTTP 契约与交互以[04-接口与前端交互](04-接口与前端交互.md)为准；权限、个人资料删除与运行验证引用[05-安全运维与验证](05-安全运维与验证.md)。待定事项及后续需求按[08-变更与扩展约定](08-变更与扩展约定.md)评审，不在本文另建决策清单。

当前正式入口使用服务端题库、固定尝试、确定性判分与逐题讲解；开发环境的二十道示例题仅用于验证链路，真实审校题库持续建设。产品 V0.7 的公共课初测基线保持不变：至少选择一科，每科五题，默认数学、英语、政治三科共十五题，数学可取消；学生也可跳过整个测评直接查看联合推荐。扩容后台题库不改变单次初测题数，自愿补测与大规模正式题库仍按批准范围建设。

题库扩容与分层策略按后续批准的范围实施；自愿补测、专业课测评是可选增强，不作为首版上线门槛。专业课若启用，必须先确认报考专业，每次五题，本科专业资料不等于已确认报考专业。五题初测只能提供有限筛查线索，未覆盖知识点显示待评估，不推算考研得分、能力上限或录取概率。

## 2. 题量与覆盖建议

下列数量只是估算建设工作的建议，须结合首批知识点、合法题源及学科审校资源确认；既不是已完成数量，也不单独构成上线门槛。

| 范围 | 建议首批目标 | 覆盖重点 |
| --- | --- | --- |
| 数学 | 120 题 | 极限与连续、导数与微分、积分、线性代数、概率等；逐题标明适用考试范围。 |
| 英语 | 60 题 | 词义与语境、句子结构、指代、逻辑关系、阅读推断；区分词汇障碍与理解障碍的线索。 |
| 政治 | 60 题 | 概念辨析、材料理解、论据与结论匹配；注明教材或考纲依据及适用年份。 |
| 专业课 | 另预留 40 题 | 按实际批准的专业方向建库，只在确认专业后按需使用。 |

公共题库建议合计 240 题，专业题另计。不能靠同一道题反复替换数字凑数。每个重点知识点应有概念题、常规应用题及可验证错误假设的对照题，并按实际需要分布在基础、中等、较难三档。先形成经审核、足以满足组卷约束的小范围题池，再扩展知识点和题量。

## 3. 题目的诊断特点

题干、选项、公式与讲解素材采用可审校的结构化内容。行列式和矩阵使用专业排版，明确行列位置与边界；公式可用MathML或受限KaTeX（trust=false、有限展开、无任意HTML）。不能由模型直接注入HTML/SVG。图解必须与当前题目版本绑定，有替代文字、使用权限和审核记录；适合结构图的题目通过已知图形类型生成，不为了凑图片产生误导插画。

每题有明确讲解入口。答前仅暴露审过的知识点提示，不发送正确选项或完整解析给前端/模型；若无法保证不泄题，仅展示固定概念提示。提交后按questionId校验本人尝试，显示标准答案、步骤和图示，并允许连续追问。辅助模型不能改变判分；撤回题目拒绝新增讲解，历史诊断保持生成时版本。

题干使用 `stem` 文本与数学片段按顺序拼接，行列式、矩阵、分式和幂次在原句对应位置渲染；不在题干下重复同一公式。`prompt` 是兼容文本，不与结构题干重复展示。为作答必需的数学表达属于题干，帮助推导的 `presentation` 公式或图属于解释材料：服务端在未提交响应中剔除，答前提示也不接收这些材料，不能只用 CSS 隐藏。提交后才展示审核过的解释图和替代文字。题目资源只接受受控的数学/图形结构或允许的本地图片路径，拒绝任意 HTML、事件属性和远程图片地址。



| 设计方式 | 用途 | 解释限制 |
| --- | --- | --- |
| 成组对照 | 保持知识点相同，只改变一个关键条件，例如链式法则的内层函数、积分区间或概率条件。 | 多题对照帮助提出假设，不能单凭一组题断言掌握程度。 |
| 有依据的干扰项 | 错误选项对应可解释的步骤错误、条件遗漏或概念混淆。 | 选到该项只是线索，也可能来自猜测、误读或其他原因。 |
| 概念与计算分开 | 同一知识点分别检查概念识别和计算应用，避免只统计最终对错。 | 证据足够才区分原因，不能把计算错误直接称为“粗心”。 |
| 情境与变式 | 用不同材料或轻微变式观察方法迁移。 | 不靠故意歧义、超纲条件或语言陷阱制造难度。 |
| 简要过程与补问 | 鼓励填写关键一步，必要时追问所用条件或公式。 | 过程为可选输入，没有过程就明确证据不足。 |
| 自信度与用时辅助 | 可选“确定/不确定”，结合多题记录安排复查。 | 不独立形成能力结论，不因一次用时长推断能力差或不认真。 |

数学重点区分极限替换条件、链式法则遗漏、定积分符号与面积、矩阵概念、独立与互斥、条件概率等错误假设。英语重点区分词义、句法、指代和逻辑证据。政治测评只评价所测知识与材料理解，不推断个人政治认同、价值观，也不作为专业适配的硬性排除条件。

数一/数二等是考试范围，不能当作难度档位。目标专业或项目未确定时优先使用共同基础题；确定后按具体项目科目核对适用范围，不由学硕/专硕类型推导。难度初始标注为人工初分；取得足量且有代表性的作答数据后才能校准，不宣称初始标签已具有测量效度。

## 4. 分层组卷与版本使用

组卷由测评模块执行，读取已发布且适用的题目，不调用模型临时选题或生成题目补齐。题目结构、资源引用、来源、错误假设标签与校准状态在文档 02 统一定义。

1. **确定范围**：根据用户勾选的模块、已确认项目的考试范围及题库审核状态选取候选题；尚未确认项目不因此阻断公共课初测。
2. **选择起始策略**：数学基础自评只用于选择初始难度配比。基础薄弱者以基础题为主，基础较好者可增加综合题，两者均保留共同基础检查；自报水平不是已经证实的能力。
3. **校验五题约束**：每个所选模块必须同时满足五题、题目不重复、考试范围适用及已评审的知识点覆盖。不能满足时说明缺口，不创建不完整的初测；可由用户调整模块或跳过测评继续推荐。不得自动缩短初测、静默降低审核要求、重复凑题或生成未经审核的题目。
4. **固定尝试**：创建时固定题目及顺序、所用题目版本和组卷结果。随机策略保存种子及实际选题依据；只存种子不足以替代题集快照。刷新、返回修改、基础自评变化或慢响应均不替换已经开始的题集。
5. **分别固定版本**：`questionBankVersion` 确定题目和审核答案，`assemblyRuleVersion` 确定组卷策略，`scoringVersion` 确定判分规则；`diagnosisVersion` 标识基于该次提交形成的诊断。版本引用结构以文档 02 为准，不压缩为一个含义不明的测评版本。

已发布题目与答案不可原地修改。答案修正产生新题库版本并列出受影响尝试；受影响的旧诊断不再用于推荐。纠正输出生成新的 `diagnosisVersion`，显式引用原尝试、旧诊断、更正后的题目修订及本次纠正采用的 `scoringVersion`，并解释变更原因。原尝试固定的题库、题目、组卷和评分版本以及用户作答均不改变，原评分与原依据保留。错误题尚未提交时，将受影响尝试转为 `invalidated`，不能在学生答题中替换题集；继续测评须创建新尝试。

## 5. 测评状态与提交规则

选择模块、填写基础自评、查看题号和提交前检查属于界面状态；服务端尝试只使用以下状态。具体请求、版本冲突与幂等响应由文档 04 定义。

| 状态 | 允许的行为 | 后续变化 |
| --- | --- | --- |
| `in_progress` | 适用性为 `applicable` 时，在同一固定题集内保存答案、简要思路、用时与进度，允许返回修改；其他适用状态只读草稿。 | 适用性通过且用户主动提交后到 `submitted`；明确放弃到 `abandoned`；题目撤回等原因使其不能继续时到 `invalidated`。 |
| `submitted` | 读取已提交作答、规则评分、固定解析及获准的辅助解释。 | 原提交不可修改；若要改答案或重测，创建新尝试并通过 `derivedFrom` 关联原尝试。 |
| `abandoned` | 查看放弃说明，保留必要历史。 | 不恢复成原尝试继续答题；重新开始时创建新尝试。 |
| `invalidated` | 查看不能继续的原因，例如题目被撤回。 | 不提交、不静默换题；确认后新建尝试。 |

选答案后先给予短暂反馈，再自动切到下一题；末题停留等待主动提交。题号、上一题、下一题和方向键只改变当前位置。未答题需要先确认，服务端分别记录答对、答错、未答；末题自动切题、返回检查、刷新均不能替代主动提交。

提交应固化学生确认的最新草稿，并在一次受控操作中保存提交及客观评分；重复提交返回同一次结果。不能把尚未完成的草稿保存请求当成已提交答案。客观评分只使用该次固定答案与判分规则，不接受客户端或模型给出的最终分数。

交卷结果以三色题号方格导航，每格保留题号与正确/错误/未答文字或可访问名称，读屏与非色觉线索同样完整。单题回顾只展开当前题的本人作答、标准答案、审核步骤、解释图与辅助追问，可用题号和前后题切换；切换不再保存或修改作答。实际模块顺序、未答、末题和刷新后的历史结果均来自同一固定尝试，不能用页面颜色或模型回答重新判分。

专业变更时按文档 02 重判专业课尝试和结果的 `applicability`，判定绑定当前专业、项目修订或公共考试范围，以及 `ruleVersion` 和 `evaluatedAt`；不改写已提交状态，不删除历史答案。只有 `applicable` 的已提交结果可作为新推荐依据。进行中尝试若为 `not_applicable` 或 `pending`，保留 `in_progress` 及原草稿，但阻止保存和提交，显示不适用或待判定原因；切回原目标或兼容目标后，经重新判定为 `applicable` 才可继续。用户也可主动放弃并新建尝试；已为 `abandoned` 或 `invalidated` 的尝试不可因此恢复。公共课结果同样按范围和版本核对适用性。

初测、重新测评、专业课和未来补测均独立保存。旧六题缓存不得恢复为新版答案或已完成结果。推荐通过文档 02 定义的 `assessmentRefs[]` 引用本次实际采用且适用的尝试/诊断；没有可用测评时使用空集合并显示待评估，不能默认读取“最近一次”结果。

## 6. 诊断、补测与模型协作

诊断输出依次说明所依据的题目与作答、已经观察到的表现、可能原因、尚不能区分的原因，以及建议补测或复习内容。题集按缩小后的覆盖范围设计时必须先经过组卷规则评审，不能在创建失败后临时减题。没有测到的知识点不作结论，不把所有知识点压成一个看似精确的能力分。

自愿补测仅在后续评审启用后提供：针对少量待验证假设创建独立轮次，事先显示题数、范围、目的及与原尝试的关系；不覆盖初测、不强制补测、不阻断择校。补测题量和策略变更按文档 08 管理，不能反向改变默认每科五题初测。专业课同样是确认报考专业后的可选路径。

DeepSeek 只辅助讲解和提出错误原因假设。服务端可向模型提供用户已提交题目的审核答案、解析和获准发送的作答过程，模型输出须引用对应证据。合法补测标签由测评模块解释并查询题库，模型不直接读写题库、不执行任意查询、不改判分。具体模型 Interface、输出核验及固定解析降级见[07-DeepSeek接入与密钥管理](07-DeepSeek接入与密钥管理.md)。

## 7. 审校与专项验证

建设流程为“草拟或授权导入 → 答案与解析复核 → 干扰项和范围检查 → 小规模试用 → 标注校准状态 → 发布”。模型草拟题与人工题适用同一审核要求；原创或授权来源、图片和公式资源引用遵循文档 02 的统一模型。

| 检查对象 | 必须验证的内容 |
| --- | --- |
| 单题发布 | 客观题答案唯一；条件完整；选项无重复或逻辑歧义；公式、单位、答案、解析和错误选项依据一致。单题审核不要求“题库总共五题”。 |
| 对照题与诊断 | 只改变计划中的关键条件；正确、错误、未答、猜测、步骤与选项冲突、范围不适用和未覆盖均有审校样例。 |
| 组卷 | 每科五题、不重复、范围与覆盖约束；题池不足明确失败；随机回放、刷新和慢响应保持同一题集。 |
| 状态与版本 | 末题主动提交、提交幂等、最新草稿固化；已提交改答开新尝试；纠正生成新诊断并保留原尝试和更正依据，旧诊断退出推荐；错误题未提交尝试失效；初测与补测分开。 |
| 适用性 | 专业切换只改变适用判断并保留历史；不适用或待判定时不能保存/提交，切回后重新判定才可继续，已放弃或失效尝试不能恢复；推荐只采用明确引用的适用结果；政治基础不触发专业硬排除。 |
| 诊断边界 | 五题结果不转为科目分、总分或录取概率；证据不足时给出限制与下一步，模型失败仍显示固定解析。 |
| 题干与解释素材 | 文本和数学顺序正确且无重复，行列式边界清晰；交卷前响应无推导图和解释公式，交卷后图示可读有替代文字，手机端不发生整页溢出。 |
| 单题结果回顾 | 三色方格同时提供状态名称，键盘/触摸可切题，正确/错误/未答及模块边界保持；新题追问不能显示上一题的迟到回答。 |

模型解释质量验证可按真实业务输入提供审核答案，检查解释是否遵守答案、引用作答且不过度推断。独立求解能力或诊断效度验证则使用隔离的题目、作答轨迹与人工标准结论，不能把待验证答案或预期诊断结论放入同一生成任务后据此宣称模型有效。两类验证目的、输入和结论分别记录，模型专项要求见文档 07，通用测试门槛见文档 05。

正式题库的知识点、题量、题源、审校人员、难度校准方法，以及补测是否启用，均须依文档 08 留下评审结论后再发布。当前示例与接口回归不能替代学科审校；本轮题干呈现和回顾交互对应 T-18、T-19，通用测评边界继续对应 T-03、T-14。
