# V0.5 技术设计文档清单与需求映射

版本：V0.5 · 日期：2026-09-23 · 状态：设计文档索引

## 1. 依据与边界

- 需求基线：[产品设计文档 V0.5](../产品设计文档.md)。本清单按该文档的第 2～7 节拆分设计与验收责任。
- 现状基线：[README](../../README.md)。现有系统是离线纯前端交互 Demo；模拟项目、分数、考试科目和推荐说明不能当作真实报考依据。技术设计应分别写明 Demo 已验证的交互，以及首版投入使用前需要建设和验证的能力。
- 城市目录基线：[城市数据说明](../city-data.md)。当前 391 项静态快照用于交互演示；生产城市标准库、更新流程和自定义城市审核需要单独设计。
- 本轮只交付技术设计文档，不在索引中把待定方案表述为已实现能力。首版业务范围以产品文档第 6 节为准；专业课测评是专业确认后的可选增强功能，不阻断专业与院校联合推荐。

## 3. V0.5 模块到技术文档的映射

编号供设计评审和后续测试追踪；需求原文与验收口径以[产品设计文档 V0.5](../产品设计文档.md)为准。表中的文档编号对应上表。

| 需求编号 | 需求模块或约束 | 首版定位 | 主责文档 | 协作文档与设计验收重点 |
| --- | --- | --- | --- | --- |
| R-01 | 学生画像、草稿、资料修改与删除 | 必备 | 02 | 04、05：未确定值、保存恢复、最小化采集和删除范围。 |
| R-02 | 意向城市选择与城市标准库 | 必备 | 04 | 02、05：中文/拼音/首字母搜索，多选、自定义和“不确定”互斥；静态目录的来源与过期处理。 |
| R-03 | 用户偏好、学校/专业屏蔽与恢复 | 必备 | 03 | 02、04：偏好如何作用于排序，以及结果变化的可解释性。 |
| R-04 | 公共课测评与诊断 | 必备 | 03 | 02、04、05：数学/英语/政治各 5 题、模块可选，政治不作为专业硬排除；少量题不推断考研分数。 |
| R-05 | 专业推荐与选择 | 核心 MVP | 03 | 01、02、04：未确认专业也能推荐，展示兴趣、课程、跨专业成本、职业目标和对应院校的依据。 |
| R-06 | 学硕/专硕建议与说明 | 必备 | 03 | 02、04：建议依据与项目差异，两个入口使用相同说明；考试科目由实际项目决定。 |
| R-07 | 专业课测评 | 可选增强 | 03 | 02、04：仅确认报考专业后可做，每次 5 题；变更专业后重新判定旧结果适用性，不阻断推荐。 |
| R-08 | 院校及招生项目推荐与选择 | 核心 MVP | 03 | 01、02、04：按完整项目组合筛资格，最多十个、不足不补齐；专业和院校双向调整。 |
| R-09 | 分数规划与阶段任务 | 必备 | 03 | 02、04、05：历年门槛、备考目标、当前能力分开；检查总分、单科和复试条件，标明年份及可比性；任务随目标变化保留历史并可勾选。 |
| R-10 | 院校评价与证据分级 | 必备的风险提示 | 02 | 03、04、05：按学院/专业/年份记录证据，去重、脱敏、复核及失效撤销；匿名传闻不直接影响排序。 |
| R-11 | 对比、收藏/排除与报告 | 必备 | 04 | 02、03、05：完整项目组合比较，修改条件后重新计算，报告保留依据、数据版本和缺失提示。 |
| R-12 | 管理后台与人工复核 | 必备的维护能力 | 02 | 01、04、05：招生资料、题库、就业/政策依据和评价证据的录入、审核、纠错及权限。 |
| R-13 | 正文字号、375px 布局与响应式 | 必备的验收约束 | 04 | 05：正文 16px、辅助至少 12px、表单及操作至少 14px；页面无横向溢出。 |
| R-14 | 测评导航、提交和版本隔离 | 必备的验收约束 | 04 | 02、03、05：选中反馈后自动切题、末题主动提交、返回修改不丢答案；旧版 6 题缓存不混入新版。 |
| R-15 | 说明弹窗与城市浮层键盘交互 | 必备的验收约束 | 04 | 05：弹窗固定关闭入口及焦点恢复；浮层随空间翻转、列表独立滚动、方向键与按钮可用。 |
| R-16 | 数据来源、缺失、过期和政策/就业依据 | 必备的横向约束 | 02 | 03、05：项目级来源与年份可追溯，缺失不等于事实结论，模型不得补造事实。 |
| R-17 | 规则、模型 API 与人工分工 | 必备的横向约束 | 01 | 03、05：资格与客观判分由规则处理，模型只基于已提供证据解释；模型失效时基础查询可用。 |

首版主链路是 R-01/R-03/R-04 → R-05 与 R-08 联合推荐 → R-06/R-09/R-10 解释 → R-11 比较与确定目标；R-02、R-12～R-17 为贯穿流程的输入、维护和验收条件。R-07 可在主链路完成后按专业方向补充，不得变成进入联合推荐的前置门槛。

## 4. 开发前待确认事项

以下问题会直接影响数据模型、算法边界或交付范围。确认结论应写入对应设计文档，并保留决策日期、责任人和变更原因。

| 编号 | 需确认的决定 | 影响文档 |
| --- | --- | --- |
| D-01 | 首版覆盖哪些理工科专业方向、院校、学院、招生年份及全日制项目；如何向未覆盖用户显示覆盖边界。 | 01、02、03 |
| D-02 | 各类官方招生、考试科目、复试、历年分数、就业及政策数据的可用来源、采集许可、更新频率和人工核验责任；支持哪些目标招生年份，以及缺失或未来年份目录未发布时的历史预览边界。 | 02、03、05 |
| D-03 | 是否需要账户与多设备同步；画像、测评、收藏、报告保存到何处，保存多久；“删除资料”是否同时删除收藏、目标、报告和后台审计关联。当前 Demo 删除画像与测评但保留收藏和目标，产品要求需确认正式语义。 | 01、02、04、05 |
| D-04 | 专业与院校联合排序的维度、权重及可调范围，冲刺/匹配/相对稳妥分组的定性规则，证据不足和资格不明时的展示策略；谁负责复核排序变化。 | 03、05 |
| D-05 | 学硕/专硕建议与职业、科研目标的映射口径；专业课测评是否进入首版排期，以及覆盖哪些已确认方向。 | 03、04 |
| D-06 | 历史分数采用的统考人群和项目口径、考试科目或培养方案变化后的可比性规则；目标分数如何设定，哪些数据缺失时只展示待评估。 | 02、03、05 |
| D-07 | 院校评价的证据收集方式、独立来源判定、复核和申诉流程，以及严重风险降权或移出前十的责任人与时效。 | 02、03、05 |
| D-08 | 大模型服务的供应方式、预算与响应要求，以及可以发送的个人资料范围；无模型或超时时采用哪些固定解释模板。 | 01、03、05 |
| D-09 | 生产城市标准库的权威来源、港澳台及自定义城市的编码与审核方式；旧静态快照与用户历史城市值如何迁移。 | 02、04、05 |
| D-10 | 首版的可用性、性能、备份恢复和人工复核时限目标，以及验收环境与责任分工。 | 01、05 |

## 5. 文档评审完成判据

进入实现前，五份 P0 设计文档应做到：每项核心需求有明确数据来源或缺失处理、规则输入与输出、用户可见解释、失败与降级行为和对应验收方法；跨文档的项目标识、年份、考试科目、测评版本与证据状态保持一致；D-01～D-10 中影响首版可开发性的决定已有结论或明确的阻塞标记。README 已同步标注产品文档 V0.5，并明确当前仍是交互 Demo，不能把设计草案当成已实现能力。
