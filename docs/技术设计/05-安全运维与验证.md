# 安全、运维与验证方案

状态：设计草案｜依据：[产品设计文档 V0.5](../产品设计文档.md)

## 1. 个人资料与权限

画像、偏好、测评答案、专业选择、收藏、目标及报告均与用户相关。首版应按完成推荐所必需的范围采集，允许“不确定”和跳过测评；敏感的简要解题过程、评价原始材料与管理员记录分别存储和授权。游客通过受保护会话访问自己的数据，后台通过独立身份及角色访问审核对象。服务端逐项校验资源归属，不能靠前端隐藏按钮实现授权。

画像删除应覆盖服务端画像、测评草稿、测评结果、个人推荐记录以及浏览器中的相关缓存。已生成报告、收藏和目标是否随画像一并删除，需在开发前形成用户可读的删除说明并与接口行为一致；当前 Demo 只清除画像和测评、保留收藏与目标，不能将此行为默认为正式产品策略。用于审计的最小操作记录与已脱敏公共资料需定义独立保留规则。数据保留期限、备份清除周期与跨设备账号能力由产品和合规负责人确定后写入正式配置。

传输使用 HTTPS；会话凭据设置安全、同源及仅 HTTP 可读属性，写操作防跨站请求伪造。数据库和对象存储按环境隔离，凭据放在服务端密钥管理中，不进入前端构建产物或日志。个人输入、模型请求/响应、纠错材料和评价证据要做日志脱敏；下载报告设置授权与有效期，避免长期可猜测链接。

## 2. 可信数据与模型边界

外部文件、院校页面、评价投稿和用户输入一律作为数据处理，不能执行其中的指令。采集时记录来源、发布时间、适用招生年份、采集时间和内容校验值，先入草稿库，经过格式校验与人工复核才发布。官方资料与非官方反馈分开展示，缺失、过期和相互矛盾的资料均明确标记。严重评价要留证据链、独立性判定和复核人，支持后续整改及撤回。

模型调用由服务端网关控制，输入仅包含完成当前解释所需的脱敏画像、已审核项目资料和可公开的来源摘要；输出为建议性文字，必须通过事实字段对照与引用检查后展示。若启用“分析解题过程”，需单独告知用户并由其主动触发，只发送该题的必要答案与简要思路，不带姓名等无关资料；是否保存模型输入/输出及保留期限按 D-08 确定。在此决定前，首版可使用经审核的固定解析完成基础诊断。模型不得决定报考资格、题库标准答案、风险标签、分数口径或排序结果。模型不可用、超时或生成未获证据支持的事实时，返回确定性规则解释，基础查询、筛选、测评与推荐继续可用。模型调用配额与超时须限制成本和滥用。

## 3. 运行与发布

建议将前端、API/后台任务、数据库和证据文件存储分开部署；开发、测试、正式环境使用独立数据与密钥。数据库迁移先在测试环境演练，重要结构变化采取可回退的分步迁移。项目与规则采用“草稿审核 → 一次性发布快照 → 服务读取新版本”的流程，发布后旧推荐与报告仍可追溯到其使用的版本。发现错误资料时撤回受影响快照或项目，重新计算当前推荐并在用户再次查看时提示版本变化。

备份覆盖数据库、已发布资料和证据文件；至少演练一次从备份恢复并核对版本与来源关联。运行监控聚焦 API 错误率、请求耗时、推荐空结果/待核验比例、数据采集失败、资料临期、模型降级、审核积压和删除请求失败。日志使用请求 ID 关联，不在日志中保留完整画像或作答。故障时先保证公开项目查询及确定性推荐，随后恢复模型解释与后台采集。

## 4. 验证矩阵

| 层级 | 核心验证 | 通过条件 |
| --- | --- | --- |
| 文档与契约 | 产品 V0.5 需求有对应设计；接口请求/响应、错误码、版本字段及项目组合键一致。 | 文档链接与需求映射有效，关键待决事项显式列出；契约审查无相互矛盾字段。 |
| 数据导入 | 同校不同学院/方向/学位/年份、科目变化、缺失来源、重复评价及撤回。 | 组合不误合并；来源与适用年份可追溯；未审核资料不发布，重复转载不重复计数。 |
| 规则单元 | 资格符合/不符/未知、排序稳定、七项偏好变化、风险分级、缺失维度。 | 未知资格不进入已核验前十；相同输入和版本输出一致；可解释变化原因。 |
| 测评状态 | 1–3 个公共课模块、每科五题、末题停留、主动提交、返回修改及题库版本；若启用可选专业课测评，再验专业切换。 | 题量、题号、模块进度和结果随实际选择变化；草稿不丢失；旧六题缓存不成为新版完成记录。专业课测试属于启用该增强功能时的验收，不作为首版上线门槛。 |
| 分数口径 | 统考/推免/专项、单科/总分、考试科目更换、历史数据不足。 | 不可比数据不连成同一趋势；目标分项合计正确；少量示例题不换算总分。 |
| API 集成 | 会话归属、乐观锁冲突、提交幂等、审核发布、删除与缓存清除、模型不可用。 | 越权访问被拒绝；重复提交只生成一个结果；降级后查询与规则推荐可用。 |
| 端到端 | 未定专业或学校完成联合探索；专业和院校双向调整；学校/专业/项目屏蔽与恢复；收藏/比较/报告、阶段任务；城市搜索及说明弹窗。 | 关键流程无需专业课测评；来源、年份、缺失和风险均能查看；任务完成状态持久化，目标变化后的旧任务标记正确；刷新后状态正确。 |
| 可访问性与响应式 | 375px 手机、键盘城市网格实际行列移动、浮层翻转、弹窗视口内缩放/滚动与焦点恢复、文字字号。 | 页面无横向溢出与裁字，底部操作可见；Esc 和键盘移动正常；正文/辅助/操作字号满足产品文档。 |
| 安全与隐私 | 输入校验、鉴权、上传文件、注入文本、日志脱敏、数据删除及备份恢复。 | 无越权读写；外部文本不能改变规则/发布状态；删除范围与声明一致，恢复演练完成。 |

每个产品验收方向在测试用例中标记需求编号、所用数据版本和证据截图/日志。测试不得只断言固定模拟分数或复制实现计算公式；应覆盖条件变化、未知状态和错误路径。

## 5. 阶段性验收门槛

1. **设计评审**：产品确认首批覆盖、支持的目标招生年份及尚未发布目录时的预览边界、身份和删除策略；数据负责人确认来源与复核流程；技术负责人确认接口、项目唯一键和故障降级。
2. **内测准备**：真实资料覆盖清单中的每个上线项目均有目标年份官方依据；题库与评分标准经审核；规则回放、隐私删除、备份恢复和 375px 交互测试通过。
3. **上线前**：所有自动化检查与人工高风险样例通过；不存在把模拟项目、未经核验资格或模型编造事实展示为真实报考建议的路径；异常数据和模型故障有可操作的降级页面。

本文件定义验证方法与门槛，不表示当前离线 Demo 已具备上述正式服务能力。
