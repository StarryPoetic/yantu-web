## 1. 命名、身份与时间

本文件是实体、字段名称和版本含义的唯一维护位置；以下为逻辑模型，当前由 SQLite 资源快照与领域模块实现，独立关系表按实际扩展需要演进。API 使用 camelCase，数据库列名可映射，但不得出现多个含义相同的公开字段。内部 ID 不随显示名称改变，也不能复用 Demo 短名称作为正式键。

目标招生年度用 `targetAdmissionYear`，初试实际举行日期另存。一个 `AdmissionProject` 对应一个完整年度招生项目，对外标识统一为 `programId`。业务唯一键至少为学校、学院、专业代码及体系、方向或明确的无单列方向、学位类型、学习方式、目标招生年度；官方另分校区、招生单元或考试组时加入区分字段。同键不同内容进入冲突处理，不覆盖旧值。跨年项目通过经复核的关联映射追踪，不复用年度项目 ID。

## 2. 标识与版本字典

| 字段 | 含义及生成规则 | 使用边界 |
| --- | --- | --- |
| `schemaVersion` | API 或持久快照结构契约版本 | 不替代业务数据版本；破坏性变化按 08 迁移。 |
| `subjectId` | 服务端身份层产生的稳定个人数据主体 ID | 从会话解析，不由客户端传入归属；已注册账号使用稳定 accountId 关联，游客只能在显式注册迁移时认领原主体。 |
| `profileVersion` | 同一主体每次保存画像产生的递增版本 | 固定画像和城市偏好；允许空画像的已定义初始版本。 |
| `selectionVersion` | 确认专业、目标和排除等选择记录的递增版本 | 收藏也属于选择记录；推荐只使用相关字段，收藏本身不改变排序。 |
| `programId` / `programRevisionId` | 年度项目身份 / 同一身份的不可变资料修订 | 收藏引用身份，计算和报告固定修订。 |
| `catalogVersion` | `CatalogRelease` 的不可变发布标识 | 固定项目修订、来源、城市与证据版本；一轮计算使用一个快照。 |
| `ruleVersion` | 已审核推荐与规划规则包版本 | 含维度映射、权重、缺失策略、风险规则及兼容依赖。 |
| `questionBankVersion` | 已审核题目修订集合的发布标识 | 不与招生目录绑定发布；记录适用范围和版本清单。 |
| `assemblyRuleVersion` / `scoringVersion` | 组卷策略 / 确定性判分标准版本 | 创建尝试固定，不能随后台配置漂移。 |
| `assessmentAttemptId` / `attemptVersion` | 一次测评尝试 ID / 草稿递增版本 | 提交后作答固定；重新答题产生新尝试。 |
| `diagnosisVersion` | 一次尝试的不可变诊断结果版本 | 绑定题目、评分、诊断规则和证据；纠正时显式引用原尝试、旧诊断、更正题目修订及评分版本，原尝试固定版本不变。 |
| `assessmentRefs[]` | 多个 `{assessmentAttemptId, diagnosisVersion}` 引用 | 可为空；分别表示公共课、专业课和补测，不能压成单个测评版本。 |
| `recommendationRunId` | 一次推荐计算及其输入快照的 ID | 保存版本、结果和依据；重复幂等请求复用同一运行。 |
| `guidanceRunId` | 一次全国专业探索结论及固定依据的 ID | 联网研究报告引用本人仍适用的结论；不替代年度招生项目推荐运行。 |
| `planId` / `planVersion` | 计划身份 / 计划快照版本 | 固定目标、科目、分数建议和生成依据；任务进度独立保存。 |
| `reportId` / `taskId` / `jobId` | 报告 / 学习任务 / 后台作业身份 | 学习任务与后台作业是不同实体。 |
| `promptVersion` / `modelConfigVersion` | 提示模板版本 / 供应商、模型别名、模式及参数的配置版本 | 仅影响辅助文字与计量，不影响业务判分和排序。 |
| `deletionGeneration` | 个人数据删除开始时递增的隔离代次 | 作业读写、缓存和旧请求均检查；流程见 05。 |
| `deletionScopeVersion` | 已批准删除策略的版本 | 删除预览返回必删、可保留项和期限；提交必须匹配该版本，不由客户端自行缩小范围。 |

## 3. 核心实体与关联

账号持久字段包括 accountId、规范用户名、显示用户名、带随机盐的 scrypt 密码哈希、student/admin 角色、独立管理权限与创建时间。Cookie 只包含随机会话凭据，数据库保存哈希；用户响应不暴露密码哈希。管理身份由受保护初始化配置创建，不允许注册字段提升权限。

画像新增 `profileSavedAt` 和 `profileCompleted`；第一次保存即使值与空画像一致也记录保存状态与版本，同版本重复完整保存不重复增长。学科确认初始为 null，本科专业不自动赋给 confirmedMajorId。

兴趣字段 `targetMajor` 保存去重后的多项名称或自由原文，不以建议列表限制用户内容，也不自动写入 `confirmedMajorId`。下拉分组是目录名称的展示索引，不改变全国目录代码或类别。

全国 `DisciplineCatalog` 存门类、四位代码、一级学科/专业学位类别、学位类型、硕士限定脚注、官方来源、原件哈希与覆盖统计。当前2022基础目录为14/117/67，184条；二级、自设、交叉与六位年度招生专业通过招生项目扩建，不能声称同等全量覆盖。更新必须保留旧快照，不用名称充当ID。

`GuidanceRun` 固定画像、选择、全国目录、规则及诊断引用，保存结论、逐方向理由、准备要求、待核验资格、补问和有限性说明；目录/画像/选择/诊断变化标记需刷新，不重写历史。聊天作为独立本人资源，清空时同时阻断旧缓存、幂等回放和未完成请求回填。

`SelectionSnapshot.targetProgramId` 是当前目标的唯一读取来源，独立于计划是否已经保存。选择项目时绑定其真实 `majorCode` 前四位与 `degreeType` 对应的有效全国目录类别；无有效全国代码时只保留明确匹配的历史方向，不任意选择方向。目标变更、取消或画像变化使受影响计划新增 `needs_review`、`valid=false` 版本及历史，并标记未完成任务需重新确认；读取历史计划不能反写目标。同一完整目标重复 PUT 不增加选择或计划版本。

| `AssessmentAttempt` / `Answer` | 主体、阶段、模块、范围、固定题目修订、组卷与评分版本、草稿版本、简要思路和用时、提交时间；`derivedFrom` 关联重新作答或补测来源，状态由 06 定义。 |
| `Diagnosis` / `AssessmentApplicability` | 诊断证据、未覆盖知识点及限制；适用性记录当前目标、范围、规则与判定结果，可重新评估但不改原作答和诊断。 |
| `RecommendationRun` | 主体、画像和选择快照、目标年度、明确筛选、目录及规则版本、适用测评引用、未采用诊断及原因、逐步排除理由、排序结果、生成时间。 |
| `Plan` / `PlanTask` | 项目及修订、科目、历史参考、分数目标与待核验项、来源推荐运行；目标与新确认专业不兼容时计划标记 `needs_review`，不得当作当前有效计划；任务带来源、所属计划、完成状态和需重新确认标志。 |
| `ReportSnapshot` | 主体、固定推荐运行、计划版本、内容/文件引用、来源、生成时间和缺失提示；新版本生成新报告。 |
| `ResearchJob` | 本人 `guidanceRunId`、任务状态、阶段、进度、事件时间、固定目标项目修订/目录版本及可选研究报告；持久保存，刷新只读取或轮询。 |
| `ResearchReport` | 固定专业结论版本、研究方向、事实及引用、具体学校/专业建议、结构化画像理由、取舍、年度证据状态、补问与来源；不写入正式招生目录或改写基础结论。 |
| `ResearchEvidenceLibrary` | 可跨账户复用的公开官网正文、实际附件链接、合法来源归属、原始抓取时间、内容版本及有限读取诊断；不包含个人画像、账号、检索问题或模型建议。 |
| `ResearchProgramCoverage` | 学校、学院、专业代码、学位和学习形式形成的稳定项目身份；逐项保存专业条目、初试、培养地点、学费、报考条件、培养内容的原文依据与缺项。 |
| `ResearchEvidenceGap` | 一项具体专业、字段及待查年度的稳定补查任务，保留已有来源、原文、原因、下一步和读取诊断；缺项不等同于不符合偏好或不适合。 |
| `EmploymentEvidence` / `PolicyEvidence` / `RiskCase` | 分别记录就业统计、政策条款、审核后的风险结论，不能共用一个不明来源的综合字段；规则见第 6 节。 |
| `Correction` / `AuditEvent` / `Job` | 纠错目标和处理进展；只追加的操作审计；含幂等键、重试及完成状态的后台作业。不得在日志副本中保存完整个人记录。 |

`AssessmentApplicability.applicability` 只允许 `applicable/not_applicable/pending`，记录判定目标（专业/项目修订或公共范围）、`ruleVersion` 和 `evaluatedAt`。它是相对于目标的判断，不是测评生命周期状态。不适用或待核验的进行中尝试禁止保存和提交，但仍保留草稿；切回兼容目标并重判适用后可继续，已经放弃或失效的尝试不可恢复。已提交历史保留，答案更正使旧诊断退出后续推荐，新诊断通过显式引用才可使用；具体流程见 06。

题目可用 `stem` 将文本与受限数学表达按顺序组成题干；`prompt` 保留文本语义兼容。`presentation` 是审核后的讲解素材，未提交的公开响应不包含其推导图或解释公式。数学与图形结构按允许清单校验，不能存任意可执行 HTML；边界详见 06。

研究任务使用 `queued/running/completed/partial/blocked/failed/cancelled`，与普通报告作业的状态分开。`stage` 为 queued、preparing、researching、analyzing、writing 或 done，`events[]` 记录真实阶段进入时间。`progress` 是阶段刻度，不按计时器增长。任务存于本人 `research-job`，`research-latest` 按结论引用定位最近任务；固定报告字节不被后续画像或目录更新改写，读取时附 `needsRefresh/refreshReasons`。服务重启把遗留 queued/running 标为 failed，不自动重新执行上游付费请求。

新研究报告保持 `schemaVersion:1`，当前新增报告为可选 `reportVersion:'profile-research-v7'`（继续兼容旧 `profile-research-v3`、`profile-research-v4`、`profile-research-v5` 与 `profile-research-v6`）、`researchDirections[]`（disciplineCode、name、rationale）及 `followUpQuestions[]`。新建议增加 `programName`、由全国目录派生的 `degreeType`（academic 或 professional）、`fitReasons[]`（profileField、profileValue、reason）、`tradeoffs[]` 和 `admissionStatus`。每项新建议至少包含两个不同真实画像字段的理由；字段值必须对应固定画像，不由模型杜撰。`admissionStatus` 由服务端证据检查计算，`current_evidence` 仅代表取得目标年度相关资料，`needs_verification` 表示该年度仍需核验，二者均不等于确定性资格结果 eligible。`failureStage` 可选值为 `preparing/researching/analyzing/writing`，表示失败发生的真实阶段；阶段失败、模型输出校验失败和用户信息不足分别解释。已保存画像充分但模型格式错误时，不提示用户必须先选学校或重新填写画像；只有实际画像不足或有效规划中的明确追问才请求补充。模型元数据描述最终报告模型；规划阶段另采用固定非思考配置。旧报告缺少这些字段时按历史内容展示，不补造理由或默认为资格已通过。

历史v6契约新增可选 `tier`（preferred/alternative/exploratory）、`tierReasons[]`、`constraintChecks[]`（field为budget/cities，status为match/mismatch/unknown，含reason/sourceIds）、`tuition` 与 `location`。学费记录amount、currency:CNY、period:academic_year/program/semester/credit、year、studyMode:full_time/part_time/unspecified、quote、sourceId；城市记录city、quote、sourceId。历史v6由模型输出suitabilityTier与suitabilityReason，再核验综合理由；旧快照保持当时内容。当前v7使用 `demand-match-v1` 从保存需求及官网证据生成tier及tierReasons，模型等级不参与排序。方向关联、培养路线和已核验城市形成逐项match/mismatch/unknown比较，有城市偏好时，城市未知不满足优先比较条件。测评只用于准备观察与任务，不用于推断录取概率或隐藏地降低层级。费用/城市事实仍按当前具体项目、年度、学习形式和计费单位核验，历史费用和全程费用不直接对比年度预算，未知保持unknown；preferred不代表报考资格通过。

v7报告增加 `referencePolicy`（strategy:history-first-v1、targetYear、referenceYears、summary），每个具体专业可带 `referenceBasis`（year、sourceIds、reason）、`exams.historicalReference`、最多三个独立年度的 `exams.history` 与 `historicalChanges`。目标年度为2027时优先比较2026、2025、2024，取实际取得的最近历史年度；未取得不补造，发布时间、版权年和本科生源年份不替代招生政策年。已知2027科目独立保留在exams当前状态中，历史参考不能覆盖它；同一年不同考试组保留ambiguous，不把跨年科目变化混成同年冲突。

`candidateAudit[].coverage.programs[]` 枚举本次已读取的所有相关专业，包括未成为学校主卡的同校专业。完整项目身份区分学院、专业代码和学习形式，不从主卡继承另一专业的费用、校区或科目。六个fields分别使用supported_current、supported_reference、missing、ambiguous、not_applicable或excluded状态，附可逐字核对的quote、sourceId和明确年度。`evidenceCoverage` 汇总schoolCount、programCount、supportedProgramCount、pendingProgramCount、gaps、reusedSourceCount、supplementedSourceCount、lookupKeys与attempts；supportedProgramCount仅表示取得适用且有年份的专业条目，不表示所有字段齐全。资料缺失与需求不匹配分别展示，不能把未查到资料写成不适合或没有该学校。

`coverage` 记录targetMin:4、targetMax:5、schoolCount、preferredCount、alternativeCount、exploratoryCount、shortfallReasons；明确城市偏好时还记录preferredCities、preferredCitySchoolCount、unknownCitySchoolCount。按不同学校计数，每校一个主专业；不足4所或意向城市覆盖为0均为partial并保留真实卡片，未知城市不计为匹配。旧v5报告保持原内容可读并提示重新生成，不回填新费用、分层或coverage字段。

v6规划与最终报告均以字段引用生成匹配理由：模型输出 `profileField` 与 `reason`，服务端从本次已保存画像快照补入 `profileValue`。提供给模型的 `profileEvidence` 只列当前可用字段，排除空值、不确定项、已清空notes和默认中性优先级50；多个优先级仍只算一个维度。旧格式显式提供 `profileValue` 时继续严格核验当前原值，数值优先级与城市数组只按实际字段类型规范化，不能借规范化改写偏好、增加城市或恢复旧备注。单条可选理由不合格时隔离该条；仍有至少两个不同真实画像维度且不只包含本科背景时保留方向或建议，不足时汇总字段问题供一次有界修复。字段绑定不意味着自由文本理由的所有推断都已获事实证明。

规划失败可附带 `validationIssues:[{path,code}]`，仅记录服务器校验器产生的固定字段路径和错误码，最多六条；不保存画像值、原始模型回复或内部思考。它随本人报告受同一权限和清除规则保护，用于定位失败而非替代推荐内容。

推荐、报告和测评固定快照是业务追溯要求，不是无限保留个人信息的理由。个人保留期限、删除与缓存失效统一由 [05](05-安全运维与验证.md)定义；账户等待定范围见 [08 的 D-03](08-变更与扩展约定.md)。

## 4. 来源、事实状态与发布

`SourceRecord` 记录发布机构、标题、原始 URL 或文件出处、受控原件引用、内容哈希、发布日期、采集与核验时间、来源类型及使用限制。`FactClaim` 记录所指实体与字段、原文定位、规范值和单位、招生年度、人群/学院/专业/地区、有效期、来源、录入及复核人员、替代关系。

以下三组状态独立存储，不能互相代替：

| 状态维度 | 允许含义 | 处理规则 |
| --- | --- | --- |
| 审核状态 `reviewStatus` | `draft`、`pending_review`、`approved`、`rejected` | 草稿提交审核；批准或拒绝均留理由；修改已批准内容须新修订并重审。 |
| 发布状态 `publicationStatus` | `unpublished`、`published`、`withdrawn` | 批准不等于发布；只有已发布修订可供业务读取，撤回必须保留原因。 |
| 事实可用性 `availability` | `verified_current`、`verified_historical`、`missing`、`unverified`、`conflicting`、`expired`、`not_applicable` | 结合目标年度、有效期、范围及复核决定；冲突与过期事实不能因已批准而被继续当作有效依据。 |

资格 `eligible/ineligible/unknown` 是 03 对事实和用户条件的计算结果，不是资料审核状态。目标年度文件未发布时，记录原因 `target_year_unpublished`；往年材料不能推断当年资格，但真实学校官网中明确的校专业关联可支持独立研究中的条件性适合建议，须保留年份及待核验状态。旧学费、名额和条件不得转成当年事实。不同官方文件冲突需保留断言并人工裁决，不静默选值。来源链接失效不自动删除已有出处，但须重核验并展示状态。

发布流程：覆盖与来源登记 → 草稿标准化 → 身份/年份/口径/来源校验 → 人工审核 → 候选快照回归 → 原子切换发布指针。`CatalogRelease` 固定修订清单、覆盖、变更摘要、复核记录及依赖清单；题库使用独立发布集合。一次推荐固定一个目录版本，不能混读发布前后值。

紧急更正先撤回错误修订的有效服务资格、失效相关缓存，再发布修正版；旧快照保留历史并显示撤回警告，不能继续用于新推荐。回滚按 08 检查兼容和撤回清单，不恢复已确认错误。公开资料更新只使个人旧结果需要刷新，不重写其历史。

公开官网证据复用由 `research-library.ts` 使用同一Store的专用SQLite表实现：research_public_sources保存按URL更新的正文与内容版本，research_public_disciplines和research_public_schools只索引正文或合法附件归属，research_public_read_attempts保存有限读取诊断。只接收HTTPS教育域或明确配置的官方host，拒绝账号、token及检索问题等私密URL参数；search_snippet、空响应和错误页不能进入正文库。verified始终为false，复用原文不意味着已经进入人工审核发布的正式招生目录。

同一URL的新有效正文替换当前版本；较旧响应、失败或空响应不覆盖最后有效原文。相同正文的真实成功复核可以更新retrievedAt，单纯再次保存缓存不更新抓取时间。来源ID与合法附件parentSourceId按公开URL稳定生成，归属证据与附件逐字正文分别保留，标题不能单独提供学校身份或政策年度。库不保存subjectId、个人画像、查询文本、账号、模型建议或原始错误详情；清除个人数据不会清除其他账户可复用的公开事实。

复用时保留原始retrievedAt，增加 `library:{status,storedAt,expiresAt,version}` 与复核说明。默认目标年度资料1天、历史资料30天、年份不明资料7天后标stale，过期可保留用于历史参考及定位补查，但不能冒充本次新抓取；研究模块优先重新核验过期来源。召回只取请求相关学科、明确学校及目标年度/此前三年的有限来源，默认24条、最多40条，并保留已取得的目标年度变更；不能把全国全部正文注入模型。读取诊断每URL最多20条、全库最多10000条，每次返回最多200条，只保留固定安全错误码。Store统一负责关闭数据库，事务仅包含短时本地写入。

## 5. 历史分数与可比性

成绩最小口径：年度、完整项目或经复核的历史映射、学习方式、录取类别、人群、考试科目组、初试/复试阶段、总分及单科满分、指标类型、数值、样本数、统计口径与来源。普通统考、推免、专项和调剂不得混为总体；复试线、最低录取分、均值、中位数分别记录。未公开样本数保持缺失，推导值单独标记待复核。

可比性结论记录比较对象、可比/有限可比/不可比/待核验、原因、日期和复核人。科目、满分、方向、学院、培养方式、人群或复试权重变化时重新评估；不可比序列断开。原始统计、建议目标和当前能力独立保存，五题测评不能写入考研分数。计算约束由 [03](03-联合推荐测评与分数规划.md)维护。

## 6. 就业、政策与评价证据

就业证据保留学校/学院/项目能达到的最细粒度、毕业年度、培养类型、统计人群、分母、统计日和来源，就业/升学/待就业分开。全校本科或全校研究生数据不能替代目标硕士项目。岗位资料保留城市、招聘期、岗位与学历/技能条件、样本局限，岗位数量不直接等于个人机会。发展前景属于推断，标明依据和时间范围。

政策保存机关、文号或出处、条款、施行/失效日、地区、人群、学历专业条件和申请环节；结合预计毕业时间判断，不把当前政策当作将来福利保证。就业、发展前景、政策支持独立展示，缺失不填默认正面值。

评价先作为线索记录事件年度、学院/专业/项目、环节、材料类别及原始出处；原件与联系方式隔离，公开摘要先脱敏。按原始 URL、哈希、相似内容及最初来源聚类，再人工判断独立性；多个转载或账号不自动算多份独立证据。风险案例固定证据簇、相互印证、适用范围、严重度、整改与有效期，至少两人复核。

匿名传闻不影响排序；多个独立且已复核材料可按规则提醒或有限降权；严重可靠确认且仍适用于目标年度项目的风险才默认移出前十。撤销、整改或范围不符及时更新，保留理由与申诉/纠错入口。普通本科录取少、复试占比大不能单独推定歧视，未发现负面反馈也不等于公平结论。

## 7. 城市与覆盖边界

当前 391 项静态目录的版本、授权和地区覆盖统一见[城市数据说明](../city-data.md)，不重复抄录依赖版本。生产城市来源与港澳台层级口径由 D-09 决定，须保存代码体系、有效期及旧码映射。中文、拼音、首字母搜索使用同一发布索引，A–Z 只展示实际分组。

自定义城市仅保存原文和待匹配状态，不自动成为官方城市；同名地名须消歧，无法唯一映射时保留原文。城市标准库不等于招生项目覆盖，城市筛选只读取已核验项目所在地。目录响应必须提供覆盖年度、专业/项目范围和缺失摘要，避免用户将未覆盖误解为不存在。

## 10. 阶段4 ProgramFact持久化契约

`research_program_facts` 按项目身份＋字段＋来源存储，项目身份包括学校、学院、专业代码、专业名称、学位类型、学习方式、年度。字段为 `catalog/exams/tuition/campus`，值来自阶段2确定性绑定；全校统一学费保留 `school_wide` / `school_wide_mode`，城市级校区核验只确认城市，不能补造具体校区。

每条保留 `quote/sourceUrl/sourceId/retrievedAt/extractedAt/extractor/status/verified:false`；当前extractor 为 `phase2-program-binding@3`，status 为 `bound/pending`。quote必须为来源中连续原文，模型输出不能入库，公开库不保存个人画像、查询文本或推荐结论。

不同来源或年度的冲突同时保留；同一来源成功读取新版本后，只替换其旧事实。失败不删除旧事实。目标年度、历史和未标年度分别沿用1天、30天、7天复核期限，queryFacts 按学校名／注册域名、城市种子映射、学科代码与完整项目身份查询，返回 fresh/stale 和 targetYearApplicable；过期及未标年度事实仍可展示，不能当目标年度事实。

`coverageStats()` 的 `librarySchoolCount/libraryProgramCount` 统计全库去重学校与专业，专业数按完整身份去掉年度和来源，避免多年或多来源重复计数。WebSource.redirectChain 保存逐跳URL，`transport/finalUrl`保留；HTTP/HTTPS按最终地址去重，原文复用仍标明明文传输。SQLite事务同时更新原文、索引和事实，原获取时间不因复用而刷新。

阶段4质量审查修正：规则版本为 phase2-program-binding@2，旧规则事实确定性重提取且不刷新retrievedAt。目录身份与推荐共用programEntries，只收目录型页面中的相邻代码名称行，名称至少2个汉字且通过停用词校验；catalog quote≤300字。初试bound/pending均须具体科目，同身份同年度规范化去重，指引句不作证据。新增school_degree_type标识按学位类型和学习方式的学校学费，保留年度、计费单位、原文；目录方式未知不选档。学院规则的全部备选校区同城只能确认城市，跨城或未知学院仍pending；registrySchoolCity另查同校正文的跨城命名校区。以上均保持verified:false。

阶段7人工审计后升级为phase2-program-binding@3：自设和交叉学科字母代码也终止上一条科目范围；代码后的括号学位标签可识别；联系前缀及纯研究生院/招生办公室地址不能供城市级核验。旧@2事实打开资料库时离线重提取，原获取时间与旧报告不改写，真实原报告及离线修复结果分别见[阶段7记录](../阶段7真实验证记录.md)。

## 11. 补查快照、结果差异与私有断点（已实现）

`ResearchSupplementScope` 固定已展示项目的学校、学科代码、六位专业代码、专业名称及已有的学院、学位、学习方式；包含 `programAlternatives` 中已展示的同校对照，不包含 `candidateAudit` 内未展示候选。缺少身份维度不能当作通配条件去匹配其他学院或学习方式。旧报告没有可冻结身份或 `evidenceCoverage` 时返回 `scope_unverified`，保留旧报告并提示重新调研。

`ResearchSupplementPlan` 保存 `version:1`、`baseGeneratedAt`、`scope`、`scopeVerified`、稳定任务ID及 `limitations`。任务按项目身份、字段、请求年份与查询去重，只取原报告已记录缺项；已有专项资料调查才继续对应专项任务。范围快照不读取种子扩校、不调用模型。

`ResearchSupplementState` 在账号私有 `ResearchCheckpoint` 中保留 plan、baseReport、completedTaskIds、failedTaskIds、workingSources、merged。成功搜索但没有可用结果可以记为任务已执行，不等于证据确认不存在；搜索/读取失败不能冒充成功空结果。IO完成但来源尚未合并时 `merged` 仍未完成，继续时必须完成合并；取消、失败或超时不把半成品覆盖对外旧报告。已完成查询及已读取来源可复用，失败任务可在显式继续时重试，进程重启不自动发起收费请求。

对外 `ResearchReport.supplement` 使用 `ResearchSupplementResult`：`outcome` 为 updated/no_change/no_pending_work/scope_unverified，保留冻结 scope、baseGeneratedAt；`changes` 包含 programKey、beforeRank/afterRank、beforeTier/afterTier、changedFields。名次从1开始，移除后 afterRank 为 null；变化只说明本次依据发生什么，不声明人工审核通过。`reusedSourceCount/newSourceCount/newSearchCount/newReadCount/remainingTaskCount` 分开统计复用来源、本次新增或更新原文、实际调用和剩余任务；任务数量不能充当已确认事实数。

补查断点和个人差异随本人权限、版本及删除代次保护，不写入公共事实表；公开来源仍保持 `verified:false`。免费预览的临时数据库丢失时这些状态也不能保证保留，不宣称跨实例恢复。
