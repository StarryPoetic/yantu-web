# 数据模型与可信数据设计

状态：设计草案｜依据：[产品设计文档 V0.5](../产品设计文档.md)｜适用范围：首版全日制理工科 MVP

## 1. 设计边界与数据契约

首版的数据单位是目标招生年度的**完整招生项目**，而不是学校名称。学生画像、公共课诊断、专业方向、项目条件、历年分数、就业与政策证据、院校评价共同形成推荐依据；每一项用户可见的关键事实都应能追溯到发布的数据版本和原始来源。缺失、未核实、过期、冲突、明确不适用是不同状态，不用空字符串或 `0` 混写。

当前 `src/data.ts` 的六个项目只有学校名称可用于界面展示；项目组合、考试科目、名额、分数、匹配值、梯度和说明都是模拟数据。`src/assessmentQuestions.ts` 是本地示例题，不能推断考研成绩。`src/cities.ts` 是用于搜索交互的 391 项静态城市快照。当前无服务端、账户、官方招生 API 或真实推荐算法；生产数据须走下述采集、核验和发布流程，不能将 Demo 中的值直接标记为“已核实”。

设计约定：实体使用不随展示名称改变的内部 ID；年度、适用范围、来源、审核状态和发布版本独立建字段。用户所见“报考年份”在生产数据中须与招生目录标注的**目标招生年度**对应；初试实际举行日期另记，避免跨自然年混淆。学科/专业代码、机构代码和行政区划代码只有在来源可靠且编码体系明确时才存为外部标识；不得将 Demo 的 `njust` 一类短 ID 当作正式项目键。

## 2. 核心实体与关系

| 实体 | 最小字段与约束 | 主要关系与用途 |
| --- | --- | --- |
| `StudentProfile` | `profile_id`、`user_id`、`revision`、目标招生年度、本科院校/专业、毕业年份、课程基础、英语经历、备考进度、每周可投入时间、预算、跨专业意愿、科研/职业目标、七项偏好权重、已确认目标专业、`created_at/updated_at`。每个可选字段区分“未填写”“不确定”和具体值。 | 关联城市选择、屏蔽项、测评尝试、收藏和报告；版本变化可解释推荐差异。姓名不作为推荐必要字段。 |
| `ProfileCityPreference` | `profile_id`、排序、`city_id?`、用户原文、`kind=standard/custom/uncertain`、标准化状态。`uncertain` 与具体城市互斥；多选去重。 | 生产城市标准库可能没有自定义值，自定义值只能作为偏好文本，待审核匹配后再绑定标准 ID。 |
| `Institution` / `College` | 稳定内部 ID、正式名称及别名、已核验外部代码、学校与学院隶属关系、有效期。 | 名称变更保留历史映射；学院不能仅按名字跨校合并。 |
| `MajorDirection` | 内部方向 ID、专业代码及代码体系、方向名称/别名、学科门类、培养和职业说明的证据版本。 | 可与多个招生项目关联；名称相同但培养内容不同的方向允许分开建模。 |
| `AdmissionProject` | 见第 3 节；一个项目一个招生年度，含学位类型、学习方式、学院、专业/方向、考试科目、报考资格、复试规则、费用和招生计划等经过核验的版本化事实。 | 与专业方向多对一或多对多映射；收藏、对比、目标、评价和历史分数均按完整项目或明确的适用范围关联。 |
| `ExamSubjectRequirement` | `project_revision_id`、科目顺序/代码/名称、考试方式与版本、适用人群、来源事实 ID；科目组支持经官方明确给出的可选条件。 | 数一/数二、英一/英二取项目当年资料，不由学硕/专硕类型推导。 |
| `AdmissionScoreRecord` | `project_id` 或可核对的历史项目映射、招生年度、人群口径、初试/复试阶段、总分或单科指标、统计量、样本数、来源、可比性标记。 | 用于近三至五年历史门槛；原始记录与可比性结论分开保存，详见第 5 节。 |
| `QuestionBankRelease` / `Question` | 独立公共课/专业课题库版本；题目 ID、科目、知识点、专业适用范围、题型、题干、选项、正确答案、解析、评分标准、审核状态和来源。发布后不可原地改答案。 | 题目与答案按版本固定到测评尝试；答案在提交前不向客户端暴露。 |
| `AssessmentAttempt` / `Answer` | 学生 ID、阶段、模块、题库版本、专业方向及适用性、状态、题目快照 ID、作答/简要思路/用时、提交时刻、评分结果版本。 | 公共课与专业课独立；专业变更触发专业课结果适用性重判，不能将旧版 6 题记录当作新版结果。 |
| `EmploymentEvidence` / `PolicyEvidence` | 指标或政策条款、对象与地区、统计人群或适用条件、年度/有效期、来源、可核实程度、缺失与冲突状态。 | 职业方向、就业前景和政策支持分开呈现；第 6 节定义禁止推断。 |
| `EvaluationEvidence` / `RiskCase` | 学院/专业/项目、事件年度、材料类别、证据原件安全引用、脱敏摘要、独立来源簇、核验状态、适用范围、整改/失效时刻、复核记录。 | 一条评价线索不是一条可直接参与排序的风险结论；第 7 节定义审核与去重。 |
| `SavedProject` / `ExcludedItem` / `PlanTask` / `ReportSnapshot` | 收藏按完整项目 ID；屏蔽项含学校/专业方向/项目作用域及恢复状态；阶段任务含目标项目、来源、生成版本、完成状态与失效标记；报告记录输入摘要、事实发布版本、规则版本、生成时刻和缺失提示。 | 收藏、屏蔽、目标、任务及报告随项目修订可显示“资料已更新”；旧报告不得被悄然改写成新事实，任务完成状态不因重算丢失。 |
| `SourceRecord` / `FactClaim` / `DataRelease` | 来源原件、可核验断言、审核与冲突状态、发布批次；字段见第 4 节。 | 所有可能影响资格、排序、风险、历史门槛或报告的事实均关联来源和发布批次。 |

学生画像与测评原始答题属于个人数据，与供全体用户读取的招生事实分开存储和授权。`SavedProject` 使用正式项目 ID；项目撤销或更正时保留历史引用与提示，避免收藏自动跳到另一年度或学院。

## 3. 完整项目唯一键、年度与修订

正式项目的业务身份至少包含：`institution_id + college_id + major_code/code_system + direction_id（或明确的“无单列方向”值）+ degree_type + study_mode + target_admission_year`。若同学院同专业同方向仍分不同校区、招生单位或考试科目组招生，增加官方招生单元/校区/项目批次等区分字段。不能用学校名加专业名或 Demo 的 `School.id` 充当唯一键。每个项目另有不可复用的 `project_id`；对同一业务身份建立唯一约束，导入时出现同键不同内容进入冲突队列，不静默覆盖。

`project_revision_id` 标识同一项目在同一招生年度的每次资料修订，`valid_from/valid_to` 表示事实适用期，`published_at/superseded_at` 表示平台发布期。招生简章、专业目录、学院补充通知、复试细则和更正公告可以在不同时间更新不同字段；原件、修订前值和差异保留。目标年度正式文件未发布时，仅可引用前一年项目作“历史参考”，必须单独标为 `target_year_unpublished`，不能显示为已核实的目标年度报考资格，也不能进入已确认可报考前十。

专业方向与招生项目拆开：同一方向可能在多校、多学院、学硕/专硕和不同学习方式下有不同条件；同校同专业的学硕与专硕仍是不同项目。项目事实应以字段级断言保存，至少覆盖报考资格、科目、招生计划的人群拆分、学制与学费、复试比例/规则及公开结果。方向说明、院校简介或学校整体就业信息不自动继承为具体项目事实。

## 4. 来源、断言与发布快照

`SourceRecord` 至少记录 `source_id`、发布机构、标题、原始 URL 或文件出处、原件安全存储引用、内容哈希、文件发布日期、采集时间、最近核验时间、来源类型（官方文件/官方统计/可核实第三方/用户反馈）、权限或使用限制。URL 失效不删除已核验的出处和校验信息；有条件时保留受控原件快照。

`FactClaim` 记录 `claim_id`、所指实体及字段、原文摘录或定位、规范化值、单位、目标年度、适用人群/学院/专业/地区、有效区间、来源 ID、录入人与复核人、状态、失效或替代关系。建议状态：`collected → normalized → pending_review → approved → published`；旁路状态为 `conflict`、`rejected`、`expired`、`withdrawn`。`approved` 不代表已上线，只有进入 `DataRelease` 的事实可被正式推荐读取。若两个官方材料冲突，保留两条断言、来源与时间，待人工按更正公告和适用范围裁决；裁决前将受影响字段标为冲突，不选一个数值掩盖问题。

`DataRelease` 使用不可变的 `release_id`、生成时间、审核签名、各实体版本、覆盖范围与变更摘要。一轮推荐固定读取一个已发布快照，并同时记录画像版本、规则版本及适用的测评版本；报告注明这些版本和生成时间。模型生成文字只能引用该快照传入的事实及来源，缺数据时输出“未核实/暂无数据”，不能补造学校事实、就业率、政策福利或录取概率。

可用性标记至少分为：`verified_current`、`verified_historical`、`missing`、`unverified`、`conflicting`、`expired`、`not_applicable`。状态须由年份、有效期、材料类型和人工复核共同决定；“未发现负面反馈”只表示资料缺失或没有相关已审核案例，不等于公平结论。重要事实的页面展示包含名称/值、目标年度、适用范围、来源入口、核验时间与当前状态。

## 5. 历年成绩与分数口径

成绩记录保留原始统计定义和计算后的展示值，不把统考、推免、专项计划或调剂混入同一总体。最小维度为：招生年度、完整项目或可核实的历史项目映射、学习方式、录取类别、人群（普通统考/专项等）、初试或复试环节、考试科目组、分数满分与单科满分、指标（复试线、最低录取分、均分、中位数等）、数值、样本数、统计口径、来源。缺少样本数或仅有名单时，如实记录“未公开”或“推导待复核”，不能伪造精度。

跨年可比性另存 `comparability_decision`：比较对象、结论（可比/有限可比/不可比/待核验）、理由、复核者、日期。考试科目、专业方向、学院、培养方式、满分、人群口径、复试权重或招生方式变化时，要先复核再绘趋势；不同口径在图表中断开或分组。历史最低录取分只标为观察值，不作为安全线。建议备考目标与当前能力是独立实体或计算输出，不回写历史成绩表；当前五题示例测评只提供知识点诊断，不能换算科目分、总分或录取概率。目标规划必须同时核对总分、单科与复试门槛，并保存所用项目及规则版本。

## 6. 就业与政策证据

就业证据按“学校 → 学院 → 专业/项目 → 毕业年度 → 培养方式/学位类型 → 统计人群 → 去向类别”记录可达到的最细粒度，附分母、统计日期、数据来源和缺失项。就业、升学、待就业分别统计；全校本科或全校研究生数据不能替代目标硕士项目表现。岗位数据另记城市、招聘期、岗位名称、学历与技能条件、来源及样本局限，不能从岗位数量直接推出个人就业机会或录用率。

政策证据保存发布机关、文号或官方出处、条款、发布日期、施行和失效日期、适用地区、人群、学历/专业条件、申请环节及变更记录。展示时结合用户目标城市和预计毕业时间检查是否仍可能适用；仅凭“政策支持”字样不能给出可领取福利或就业保证。发展前景属于推断，须说明所依据的岗位、产业和时间范围，并与政策事实分开展示。未公开、已失效或仅覆盖其他人群的资料标明原因，不填默认正面值。

## 7. 院校评价证据、去重与风险发布

评价材料先作为线索接收，记录事件发生年份、学院/专业/项目、复试或培养环节、材料类型（官方事实、可核实亲历、匿名线索、转载）、收集时间与原始出处。原件与联系信息隔离保存；展示前移除姓名、准考证号、电话、聊天身份等可识别信息，摘要由人工复核。涉及第三方的原件不直接公开。允许被评价方与学生提交纠错或补充材料，并保留处理进展。

去重分两层：先用原始 URL、文件哈希、内容指纹、时间与表述相似度识别复制/转载；再核对最初发布者、亲历人、材料来源和事件细节，形成 `evidence_cluster_id` 与独立性判断。多个链接引用同一匿名帖子仍是一份线索；多个账号也不自动等于独立证人。聚类不删除原件，人工可拆分或合并并留审计记录。

风险案例由审核人员汇总证据簇、相互印证关系、适用范围、严重程度、整改状态和有效期，记录至少两人的复核结论与发布日期。单条匿名传闻只可显示为待核实线索，不参与排序。多份独立且已复核材料可形成提醒或有限降权；严重问题有可靠确认、仍适用于目标项目和招生年度时，才可按版本化规则默认移出推荐前十，同时在详情展示依据与申诉入口。事实不成立、范围不符、已整改或过期时及时撤销风险标记，旧版发布记录和处理原因仍可追溯。普通本科录取人数少、复试占比大等单一统计现象不能直接标为歧视。

## 8. 城市标准库与自定义城市

现有离线目录来自 `china-division@2.7.0` 的 `pc-code.json` 和 `HK-MO-TW.json`，拼音由 `pinyin-pro@3.29.4` 预生成；大陆源数据标注为 2023 年统计用区划代码、截至 2023-06-30。目录共有 391 项，港澳台部分不能套用大陆的统计截止日期；范围和许可证见[城市数据说明](../city-data.md)。它是 Demo 交互快照，不等于 2026 年实时、穷尽的行政区划，也不代表这些城市有演示院校。

生产 `City` 建议保存内部 `city_id`、编码体系与代码、正式名称、上级行政区、层级/类型、别名、拼音与首字母、适用日期、源版本、审核状态及旧码映射。编码须带体系和有效期，不能只靠代码字符串跨版本关联。来源、港澳台层级及名称口径、更新周期和责任人需在 D-09 确认；变更采用新版本并保留旧名称映射，不能改写历史画像原文。中文、拼音、首字母搜索使用同一已发布索引，A–Z 仅显示实际有候选的字母。

用户输入未匹配的城市存 `kind=custom`、原文和待匹配状态；审核确认后可补别名或映射，不自动创建官方城市。`kind=uncertain` 与其他城市互斥。迁移 Demo 中的“杭州”等字符串时，先用名称加省份/地区消歧；无法唯一匹配则保留原文并请求用户确认，不能猜测编码。城市筛选只作用于已核验项目所在地，城市目录不代表项目覆盖。

## 9. 个人数据生命周期与删除

画像按需采集，提供草稿与正式保存、修订记录和用户修改入口。测评草稿、答案、诊断结果、收藏/排除项、目标、报告及纠错申请应按用户 ID 分别建表或隔离存储，访问只授予本人和必要的审核角色；推荐计算日志记录版本与最少输入摘要，避免复制完整画像。报告可下载，但服务端报告副本及其依据引用要有明确留存和删除策略。

“删除个人资料”在生产端建议作为一次可审计操作：撤销会话访问、删除画像与城市偏好、测评答案/草稿/结果，以及由个人输入生成的报告副本和可识别的计算缓存；清理异步索引与备份中的可识别关联应有完成状态。已发布的公共招生事实和匿名化统计不因单个用户删除而删除。收藏、目标、纠错申请及必要的操作审计是否一并删除，需要在 D-03 明确并在界面列出确切范围；在决定前不能宣称“已删除全部资料”。对因纠错处理需要保留的材料，需事先定义最小留存、隔离和到期清理规则。

当前 Demo 仅用浏览器 `localStorage` 保存状态：`yantu-demo-v1`、`yantu-demo-assessment-attempt-v2`、`yantu-demo-admin-records` 等。现有“删除资料”会清空画像与测评结果/草稿，**保留收藏和目标**；浏览器本地行为既不等于服务器删除，也不能作为生产删除语义。正式产品若引入账户、多设备同步，必须重新设计身份、留存期限、导出与删除确认；这些仍是 D-03 待决项。

## 10. 采集、复核、发布与回退流程

1. **确定覆盖清单**：先确认首版专业方向、学校/学院、招生年度和全日制项目范围（D-01）；范围外查询显示未覆盖，不补虚构项目。
2. **登记来源**：为招生、成绩、题库、就业、政策、评价和城市数据分别登记来源、授权/使用限制、更新频率与责任人；抓取或人工录入后保存原件引用、时间和哈希。
3. **标准化与质量检查**：校验完整项目业务键、代码体系、目标年度、招生人群、分数满分、科目数量和取值；发现同键冲突、空白关键字段、异常年份或跨源差异时挂起。
4. **人工复核**：招生资格、考试科目、分数口径、题目答案与解析、政策适用范围、评价风险由有权限人员复核；争议项双人复核，所有改动记录前后值与理由。
5. **候选版验证**：在未发布快照上执行样本检查：同校学硕/专硕独立、目标年度文件缺失不进入已核验前十、历史口径变化断开、转载评价不重复计数、城市旧值可迁移；生成覆盖率和缺失清单。
6. **原子发布**：审核通过后生成不可变 `release_id`，服务端一次切换正式读取指针；查询和推荐只用同一批次快照。公告关键变更，并保留上一批次供回退。
7. **监测与纠错**：接收用户纠错与官方更正，按影响范围重新核验；紧急撤回错误事实或风险标签时发布修订批次，旧报告提示已过期。回退只回切数据版本，不抹去审计与错误处理记录。

生产发布门槛与责任人尚需确认（D-02、D-07、D-10）。可先设计验证样例和数据契约，不能因为 Demo 页面已有管理表格就视作上述后台、权限或审核流程已经实现。
