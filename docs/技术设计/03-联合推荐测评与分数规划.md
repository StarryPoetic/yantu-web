# 联合推荐、测评与分数规划设计

状态：设计草案｜依据：[产品设计文档 V0.5](../产品设计文档.md)｜适用范围：首版全日制理工科 MVP

## 1. 设计目标与边界

首版以“专业方向 × 招生项目”为推荐单位。用户可以先给出专业兴趣，也可以先选择学校；两种操作都重新计算同一组候选组合。招生项目指“学校＋学院＋专业/方向＋学位类型＋学习方式＋招生年份”，不得把同校不同学院、学位类型或年份合并。

推荐依赖已审核的招生资料与确定性规则；大模型只辅助理解补问、撰写有出处的解释与报告。模型输出不决定报考资格、题目对错、历史统计、排序分数或录取概率。当前 Demo 的 `match`、`tier`、`score` 和项目资料均为模拟展示，不能迁移成真实结论。

## 2. 联合推荐流水线

输入为画像版本、可选公共课诊断版本、目标招生年份、用户显式筛选/排除项、偏好权重和已确认的专业/学校约束。输出为最多十个可比较组合、未入选原因、每个维度的解释和完整计算版本。

1. **标准化输入**：保留“不确定”和缺失状态；城市自定义值先尝试匹配城市标准库，未匹配时只作为文本偏好，不作为报考资格条件。学硕/专硕偏好参与培养路径建议，不推导考试科目。
2. **取数据快照**：固定已发布的目标年份项目版本、来源版本、规则版本、题库/诊断版本与画像版本。一次计算只读同一快照，避免结果中途变化。
3. **资格筛选**：由项目官方条件逐项判定 `eligible`、`ineligible`、`unknown`，并记录条件、证据和判定依据。明确不符合者不推荐；缺少目标年份正式资料或关键条件无法验证者进入“待核验候选”，不宣称满足报考要求，也不占推荐前十。不能仅因本科院校层次、普通本科录取少或复试权重大推定不符合资格。对尚未发布目录的未来年份，是否开放预览及支持哪些年份须先按 D-02 确定；没有已核验项目时清楚显示空结果和历史参考。
4. **构建组合**：将可报考项目关联到其专业方向，形成候选对；若用户已确认专业或学校，则只在对应约束内计算，并提供解除约束的入口。学生屏蔽学校、专业方向或完整项目时，在该层级剔除所有受影响组合，记录排除原因并提供逐项恢复。专业课测评不是此步骤的门槛。
5. **分别计算专业适配与项目适配**：专业侧考虑兴趣、课程背景、职业目标、跨专业准备成本和培养取向；项目侧考虑城市、培养资源、实际考试科目、预算、招生透明度与已复核风险。就业机会依据目标城市、预计毕业年份、应届硕士岗位条件和可核验项目去向分别判断；发展前景用有时间范围的岗位与行业证据表述；政策支持按地区、人群和生效期判断，不能推导就业保证。三者各有来源和缺失状态，不能共用一个笼统分值或把全校数据当成项目数据。任何维度缺证据时标记 `unknown`，不把缺失当成零分或有利事实。
6. **形成组合排序**：使用经评审且版本化的权重配置，将有证据的专业与项目维度合成排序值。用户七项重要性先归一化，客观限制仍由资格筛选处理，不能被高偏好权重抵消。证据覆盖率作为单独信息展示；覆盖不足时不给伪精确的“匹配百分比”。同分按预先公布的稳定项目 ID 排序，保证相同输入和版本结果一致。
7. **风险处理**：单条匿名传闻不能降权。相互独立且经复核的多份反馈可产生提醒或有限降权；严重问题经可靠确认且仍相关时默认移出前十，保留可查看的排除理由与申诉/纠错入口。风险规则和人工审核记录必须可追溯。
8. **输出与解释**：最多十个，数量不足不补齐；对每项返回专业理由、项目理由、实际考试科目、准备成本、主要风险、数据缺失、来源与版本。用户修改条件后返回“增加、移出、名次变化及触发因素”。

“冲刺、匹配、相对稳妥”仅是基于可比历史门槛、准备成本和风险的比较标签，须显示其依据与不确定性；不代表录取概率或保证。首版在可靠数据不足时可只显示排序与风险，不强行分组。

### 学硕/专硕建议

对每个专业方向分别汇总科研或职业目标、希望的课程与实践方式、可投入时间、预算和已发布项目的培养事实，形成“更倾向学硕/专硕/目前证据不足”的建议及逐项理由。建议只影响培养路径解释和可调整的排序偏好，不排除另一学位类型；学生可覆写并并排比较，覆写后结果变化应解释为偏好变化。具体学制、学费、培养资源和考试要求以项目资料为准，缺失时明确待核验。两个页面的说明按钮共用同一内容和弹窗，不以学硕固定等同数一英一、专硕固定等同数二英二。

## 3. 规则配置与解释记录

| 项目 | 设计要求 |
| --- | --- |
| 规则版本 | 规则配置作为可发布版本保存，包括资格条件解释、维度计算方法、权重边界、缺失策略、风险处理与分组阈值。发布须经过双人复核。 |
| 计算记录 | 保存输入摘要、画像/项目/规则/诊断版本、候选数量、每步排除数、每项维度贡献与排序结果；对个人信息作最小化记录。 |
| 差异解释 | 比较同一用户最近两次计算的输入和版本，区分“用户改了偏好”“目标年份资料更新”“规则更新”，禁止把数据更新误称用户能力变化。 |
| 反馈纠错 | 用户可对项目资料和解释提出纠错；纠错进入审核流程，不直接修改已发布项目或既有计算记录。 |
| 人工验证 | 在有限覆盖的 MVP 样本中准备有资格/无资格/资料缺失、同校不同专业、学硕考数学二或专硕考数学一等案例，审核排序与理由。 |

## 4. 测评状态机

公共课测评从数学、英语、政治三个模块中至少选择一个；默认三个均选，每科固定五道示例题。数学可取消，政治只用于了解备考基础，不能成为专业适配的硬性排除理由。专业课测评是预留的可选增强设计，不作为首版上线门槛；若启用，仅在目标专业确认后开放，每次五题，可跳过；本科专业资料不等于已确认报考专业。目标专业变更后，原专业课结果只有在新方向的题库适用范围明确兼容时才可复用，否则标记失效并提示重测。

状态为 `selecting → in_progress → review → submitted`，另有 `abandoned`、`invalidated`。创建尝试时服务端固定题库版本、模块和题目 ID；答案、简要思路和单题用时可保存草稿。选答案后客户端给短暂反馈并自动切到下一题；末题不自动提交。上一题、下一题、题号与方向键导航只改变当前题号，不清空答案。未答题提交时需先显示确认；只有主动点击提交才写入 `submitted` 并生成结果。

客观题在服务端按题库版本判分，返回逐题答案与已审核解析。简要思路可供用户自行回顾，若引入模型分析，必须标为辅助解释并允许“证据不足”；不得仅凭错误选项推断“粗心”。五题诊断只输出知识点表现、建议补测和准备任务，不换算考研科目得分、总分或录取概率。跳过测评时，推荐保留，能力维度标记“待评估”。

题库采用不可变发布版本。公共课与专业课使用独立题库/尝试版本；旧版六题缓存只可废弃或展示迁移说明，不得恢复为新版答案或已完成结果。重新测评创建新尝试，原结果保留为历史但不自动作为当前依据；删除个人资料同时删除测评草稿与结果。

## 5. 分数规划与可比性

分数页面明确分开三种量：

| 量 | 获取与展示 |
| --- | --- |
| 历史门槛 | 取近三至五年可获得的官方或已复核数据，显示年份、统考/推免/专项人群、总分与单科口径、初试/复试环节、样本数量和出处。缺年就留空，不补插值。 |
| 建议备考目标 | 在用户选定项目和科目后，基于同口径历史数据、项目要求及用户可投入时间给可调整的目标区间和理由。若目标年份条件或历史口径不足，只展示“待制定/待核验”，不生成精确分数。 |
| 当前能力 | 来自足量且适用的测评或用户明确录入的模考成绩，并注明来源与日期。首版五题示例测评仅提供薄弱点，不作为量化分数依据。 |

规划计算先核对项目当年的总分、单科、复试门槛与考试科目，再校验用户输入的各科目标是否与总目标相加一致，且满足同一项目、年份、人群适用的已核验硬性门槛；不可比的历史最低录取分不作为校验线。仅当当前能力来自与项目科目、满分和日期口径相符的可靠模考或正式测量时，才逐科计算“目标 − 当前表现”并注明依据；否则差距显示“待评估”，五题示例测评只提示薄弱知识点。数一/数二、英一/英二以具体项目为准；项目变化时重算科目与分数规划。考试科目、专业方向、培养方式、人群口径或复试计分规则不同的历史数据不可直接画成同一连续趋势；页面应注明断点。最低录取分不能称“安全线”，不输出未经验证的精确录取概率。

## 6. 阶段任务

首版任务从已确认组合的考试科目、资料缺失、测评薄弱点和分数规划生成“核验资料、补测/复习、比较项目、确定目标”等阶段性建议，保留来源与生成版本。用户可勾选完成或自行调整；完成状态独立于推荐计算，不因重新排序被重置。若目标项目或考试科目改变，旧任务保留为历史，受影响的未完成任务标记“需重新确认”，再生成新项目任务，不把旧专业科目任务直接沿用。跳过测评时使用一般性核验和备考任务，不伪造个性化能力差距。

## 7. 验收样例

- 不填目标专业、跳过测评：仍能获得合格的专业与院校组合；能力依据显示不足。
- 同一学校存在学硕和专硕，且科目配置与常见印象相反：项目展示以招生资料为准，两个组合独立排序。
- 用户从专业 A 改选专业 B：候选院校同步改变，旧专业课结果不串用，公共课结果在版本适用时保留。
- 用户提高城市权重或屏蔽学校：结果可复算，差异解释指向具体变更；屏蔽可恢复。
- 项目缺失目标年份报考条件：只出现在待核验候选，不进入前十；事实陈述带来源和年份。
- 同一匿名评价被转载多次：按同一证据簇处理，不产生多次降权。
- 五题测评全对：只给所测知识点诊断，不推断具体考研得分。
- 同一项目有已核验分数门槛但无可靠模考：展示历史门槛和备考目标，当前能力差距为待评估；改换科目后重算并提示任务需确认。

正式测试矩阵、责任人与上线门槛见[安全运维与验证](05-安全运维与验证.md)。
