# 报告补查的范围与状态

2026-11-12 用户确认：补查只覆盖当前报告已展示的学校与项目（含已展示的同校对照）；新证据可以在这个集合内更新顺序，并展示变化。其他候选、扩校通过“重新调研并生成报告”单独发起。

## 三个入口

| 入口               | 范围与复用                                                                                               |
| ------------------ | -------------------------------------------------------------------------------------------------------- |
| 继续补查缺少的资料 | 冻结原报告项目身份与已记录缺项，复用来源和已完成任务；只执行仍未完成的定向补查。                         |
| 失败后的继续/重试  | 沿用原任务的类型、冻结范围和私有断点；补查失败不会变成全量调研。已取得资料但尚未合并的断点仍须完成合并。 |
| 重新调研并生成报告 | 重新建立候选与调查范围，可调查其他学校。用户显式点击才启动。                                             |

补查独立于全量候选筛选、扩校和报告模型路径。使用可追溯抽取、核验和排序规则处理新增资料；无可执行任务时零检索、零读取、零模型调用。没有改变事实的新资料时保留原建议；受新事实影响的旧理由需要更新或标为重新评估。明确停招/资格冲突应失效，不能用别校补位。

## 如何读结果

- 本次任务的最新处理记录单独显示，明细按新到旧排列；原报告可在补查期间继续查看。
- 正常自动同步时没有手动刷新进度按钮。断连时保留最近状态和成功同步时间，提供“重新连接”；该操作只读取当前任务，不会创建调研任务。
- 补查结果列出复用来源数、本次实际检索/读取次数、新增或更新原文数、未执行完的任务数，以及项目顺序、层级和资料变化。
- “任务已执行”不代表缺项已补齐。没有找到原文、读取失败、无法绑定年份/项目的资料仍待核验，不据此估算，也不认定不存在。
- 旧报告无法明确项目身份时不盲目补查，提示重新调研。取消、失败和超时不覆盖对外的旧报告；尚未合并的来源仅保留在私有断点中。

所有本地验证使用 fixture/mock 或隔离数据库，不执行真实收费检索/模型调用。覆盖率数值不作为这批交互与补查修复的完成条件。
